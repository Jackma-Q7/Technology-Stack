## weak_ptr与shared_ptr
在多线程程序中通过裸指针来管理共享对象是一个很让人头疼的场景，最大的困难之处就是保证共享对象的有效性和共享对象的有效性的检测。一不小心就会造成共享对象被某个线程释放，而造成线程访问无效内存导致程序崩溃的问题。**<font style="color:#DF2A3F;">那么在C++11 中通过weak_ptr与shared_ptr的结合可以很方便的在多线程环境下检测，管理共享对象的有效性</font>**。

避免shared_ptr的循环引用

```cpp
    delete pInt;
    pInt = nullptr;
}

void t2()

    /*std::weak_ptr<int> wInt(gInt);*/
    int *wInt = gInt;
    //std::this_thread::sleep_for(std::chrono::seconds(3));
    if (wInt)
    {
        std::this_thread::sleep_for(std::chrono::seconds(3));

}

int main()
{
    std::thread th1(t2);
    std::this_thread::sleep_for(std::chrono::seconds(1));
    std::thread th2(t1);

    gInt.reset();

    th1.join();
    th2.join();
}
```

0s：t2 启动，拿到 gInt（有效）  
1s：t1 delete 掉内存 ❗  
3s：t2 还在用这个指针 ❗（炸了）

注解版本：

0s：  
 t2 启动 → weak_ptr 绑定 gInt（此时对象存在）  
 👉 weak_ptr 不增加引用计数  
1s：  
 t1 启动 → 拿到 shared_ptr（引用计数 +1）  
 👉 此时至少有 2 个 shared_ptr（gInt + t1里的）  
 main 线程如果 reset gInt：  
 👉 引用计数 -1（但对象不会释放，因为 t1 还在用）  
3s：  
 t2 执行 lock()：  
 ✅ 如果 t1 还没结束 → lock 成功（对象还活着）  
 ❌ 如果 t1 已结束 → lock 失败（对象已释放）  
 👉 不会崩溃！最多只是拿不到对象

**delete pInt;删的是pInt，但是用的是gInt为啥有问题呢？**

delete 不是删“指针变量”，而是删“指针指向的那块内存”  

**是不是一个对象被三个指针引用，我delete其中一个指针，这个对象就会释放？**

裸指针：deletep2;

智能指针：sp2.reset(); // 或 sp2 出作用域           引用计数为0释放
