## **weak_ptr**
weak_ptr用来表示临时所有权(弱引用，不会增加引用计数)，它需要配合shared_ptr使用，追踪shared_ptr所管理的对象是否有效，当需要<font style="color:#DF2A3F;">临时所有权时</font>**，则将其转换为shared_ptr，这样对象的引用计数会加1，来保证正在访问的对象有效性，它有三个关键方法:**<font style="color:#DF2A3F;">use_count()，expired()，lock()</font>

weak_ptr具有复制语义，**<font style="color:#DF2A3F;">可以通过一个weak_ptr对象构造另一个weak_ptr对象，通过一个shared_ptr构造一个weak_ptr对象</font>**

**🔴 一、先看为什么需要 weak_ptr（核心动机）**

❌ 经典问题：循环引用（内存泄漏）

```cpp
#include <memory>
#include <iostream>

class B; // 前向声明

class A {
public:
std::shared_ptr<B> b_ptr;
~A() { std::cout << "A 析构\n"; }
};

class B {
public:
std::shared_ptr<A> a_ptr;
~B() { std::cout << "B 析构\n"; }
};

int main()
{
    std::shared_ptr<A> a = std::make_shared<A>();
    std::shared_ptr<B> b = std::make_shared<B>();

    a->b_ptr = b;
    b->a_ptr = a;

    return 0;
}
```

🧠 你觉得会发生什么？

正常应该：

```cpp
A 析构
B 析构
```

❌ 实际结果：

👉 什么都不打印！  
👉 **内存泄漏！**

🔍 为什么？

我们一步一步看引用计数：

初始：

```plain
a → A   count = 1
b → B   count = 1
```

建立互相引用：

```plain
A 里有 shared_ptr<B> → B count = 2
B 里有 shared_ptr<A> → A count = 2
```

main 结束：

```plain
a 销毁 → A count = 1
b 销毁 → B count = 1
```

👉 注意：

+  A 还被 B 持有 
+  B 还被 A 持有 

👉 **永远不会变成 0 → 永远不会析构**

**✅ 二、用 weak_ptr 解决**

👉 把“其中一条关系”改成弱引用

```cpp
class B {
public:
std::weak_ptr<A> a_ptr;  // 🔥改这里
~B() { std::cout << "B 析构\n"; }
};
```

🔁 再执行一遍流程

初始：

```plain
A count = 1
B count = 1
```

建立关系：

```plain
A → B（shared_ptr） → B count = 2
B → A（weak_ptr）   → A count = 1（不增加）
```

main 结束：

```plain
a 销毁 → A count = 0 → A 析构 ✔
b 销毁 → B count = 0 → B 析构 ✔
```

🎯 结论

👉 **weak_ptr 不参与引用计数，所以不会造成循环引用**

## **weak_ptr三个核心API**
weak_ptr **不能直接访问对象**

❌ 错误：

```plain
wp->xxx   // ❌不允许
```

✅ 正确方式：用 lock()

```cpp
std::shared_ptr<A> sp = wp.lock();
```

📌 示例

```cpp
std::shared_ptr<int> sp1 = std::make_shared<int>(10);
std::weak_ptr<int> wp = sp1;
```

1️⃣ 查看引用计数

```cpp
std::cout << wp.use_count() << std::endl;
```

👉 输出：1  
（只算 shared_ptr，不算 weak_ptr）

2️⃣ 判断是否失效

```cpp
if (wp.expired())
{
    std::cout << "对象没了\n";
}
```

3️⃣ 获取临时所有权（核心）

```cpp
if (auto sp2 = wp.lock())
{
    std::cout << *sp2 << std::endl;
}
```

👉 发生了什么：

+  lock() 成功 → 返回 shared_ptr 
+  引用计数 +1（临时保护对象） 

🔁 如果对象已经被释放：

```cpp
sp1.reset();
```

再：

```cpp
auto sp2 = wp.lock();
```

👉 sp2 = nullptr

**🔥 三个关键函数总结**

1️⃣ use_count()

```cpp
wp.use_count()
```

👉 当前有多少个 shared_ptr

2️⃣ expired()

```cpp
wp.expired()
```

👉 对象是否已经被释放

等价于：

```cpp
wp.use_count() == 0
```

3️⃣ lock()（最重要）

```cpp
auto sp = wp.lock();
```

👉 如果对象还在：

+  返回 shared_ptr 
+  引用计数 +1 

👉 如果对象没了：

+  返回 nullptr 

**你那段话我帮你“优化成最标准版本”**

你原话：

weak_ptr用来表示临时所有权...

👉 更准确版本：

👉 **weak_ptr 是一种“弱引用”，不参与引用计数，用来观察 shared_ptr 管理的对象是否还存在**  
👉 **当需要访问对象时，通过 lock() 临时获得 shared_ptr，从而安全访问对象**

**🟡 再给你一个非常实用的场景（工程里常见）**

场景：观察者模式

比如：

+  UI组件 
+  回调 
+  任务系统 

```cpp
class Task {
public:
void run() { std::cout << "task run\n"; }
};

std::weak_ptr<Task> g_task;
```

使用时：

```cpp
if (auto t = g_task.lock())
{
    t->run();  // 安全
}
else
{
    std::cout << "任务已经被销毁\n";
}
```

🧩 一句话总结（一定记住）

👉 **shared_ptr：拥有对象（会影响生命周期）**  
👉 **weak_ptr：观察对象（不影响生命周期）**

## **weak_ptr的大小**
```cpp
#include <iostream>
#include <memory>

int main()
{
    std::cout << "sizeof(int*): " << sizeof(int*) << std::endl;

    std::cout << "sizeof(std::shared_ptr<int>): "
              << sizeof(std::shared_ptr<int>) << std::endl;

    std::cout << "sizeof(std::weak_ptr<int>): "
              << sizeof(std::weak_ptr<int>) << std::endl;

    return 0;
}
```

大多数编译器（gcc / clang / MSVC）结果类似：

```plain
sizeof(int*): 8
sizeof(std::shared_ptr<int>): 16
sizeof(std::weak_ptr<int>): 16
```

你可以把它们想象成这样：（**<font style="color:#DF2A3F;">在栈上</font>**）

```plain
shared_ptr:
    [对象指针] + [控制块指针]

weak_ptr:
    [对象指针] + [控制块指针]
```

👉 每个指针 8 字节（64位）

```plain
8 + 8 = 16 字节
```

控制块里才是真正核心：

```plain
控制块（control block）：
    - strong count（shared_ptr计数）
    - weak count（weak_ptr计数）
    - 删除器
    - 分配器
```

weak_ptr 为什么也要控制块指针？

因为它要做三件事：

1️⃣ 判断对象是否还活着

```plain
wp.expired()
```

👉 需要去控制块看：

```plain
strong_count == 0 ?
```

2️⃣ lock() 转换

```plain
auto sp = wp.lock();
```

👉 要做：

+  检查 strong_count 
+  如果 >0 → ++strong_count 

👉 所以必须访问控制块

3️⃣ 跟踪对象生命周期

weak_ptr 虽然不“拥有”对象，但要“观察”它

👉 观察就必须有控制块地址
