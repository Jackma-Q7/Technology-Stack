## 删除器
&emsp;&emsp;对智能指针不只是管理动态内存，还可以其它类型的资源(只要业务认为是资源且对外暴露为指针，比如文件，数据库连接等)，shared_ptr和unique_ptr都可以胜任这样的工作，通过它们获取资源很容易，只要用资源的指针去构造它们即可。那么释放资源时就要注意了，需要通过自定义删除器去告知智能指针如何去释放资源

**shared_ptr的删除器**

1. shared_ptr是个模板类

template< class T > class shared_ptr

2. shared_ptr带删除器的构造函数

template< class Y, class Deleter >

shared_ptr( Y* ptr, Deleter d );

删除器是shared_ptr构造函数的一个参数

**unique_ptr的删除器**

1. unique_ptr是个模板类

template<class T,class Deleter = std::default_delete<T> > class unique_ptr

删除器是unique_ptr的模板参数，是类型的一部分

**默认删除器**

&emsp;&emsp;默认删除器是std::default delete，其行为就是delete,所以对于动态分配的**数组或其它类型**的资源显然就不适用，这时就需要使用自定义删除器

```cpp
#include <iostream>
#include <memory>
#include <fstream>
class CFileDeleter
{
public:
    CFileDeleter(const std::string& strFile) :m_strFileName(strFile)
    {

    }

    void operator()(std::ofstream* fp)
    {
        fp->close();
        std::remove(m_strFileName.c_str());
    }

private:
    std::string m_strFileName;
};
int main()
{
    std::shared_ptr<int> p1(new int[10]);
    std::shared_ptr<int> p2(new int[10], [](int* p) {
        std::cout << "delete p" << std::endl;
        delete[] p;
    });

    p2.get()[0];

    std::unique_ptr<int[]> p3(new int[10]);

    p3[0];
    //std::shared_ptr<std::ofstream> fp(new std::ofstream("test.txt"), CFileDeleter("test.txt"));

    //std::unique_ptr<std::ofstream, CFileDeleter> ffp(new std::ofstream("test.txt"), CFileDeleter("test.txt"));



    std::system("pause");
}
```

1️⃣**删除器 = 告诉智能指针“资源该怎么释放”**

默认情况：

+ `new` → `delete`
+  但现实中还有： 
    - `new[]` → `delete[]`
    -  文件 → `close()`
    -  socket → `close()`
    -  数据库 → `disconnect()`

2️⃣ shared_ptr 的删除器（重点：运行时传入）

```cpp
template< class Y, class Deleter >
shared_ptr( Y* ptr, Deleter d );
```

+ 删除器是**构造函数参数**
+  类型**不影响 shared_ptr 类型**

```cpp
std::shared_ptr<int> p(new int[10], [](int* p){
    delete[] p;
});
```

shared_ptr<int> 类型没变

删除器是“附带信息”（存在控制块里）

 3️⃣ unique_ptr 的删除器（重点：编译期决定）  

```cpp
template<class T, class Deleter = std::default_delete<T>>
class unique_ptr;
```

+  删除器是**模板参数**
+  属于类型的一部分

```cpp
std::unique_ptr<int[], void(*)(int*)> p(
    new int[10],
    [](int* p){ delete[] p; }
);
```

👉 这里类型已经变了：

```cpp
unique_ptr<int[], void(*)(int*)>
```

+ `shared_ptr`：删除器是“对象的一部分”（运行时） 
+ `unique_ptr`：删除器是“类型的一部分”（编译期）

4️⃣ 默认删除器的问题

```plain
std::default_delete<T>
```

👉 实际行为：

```plain
delete ptr;
```

❌ 问题：

```plain
new int[10]  ❌ 不能用 delete
```

👉 正确：

```plain
delete[] ptr;
```

## 问题1 ：构造函数参数和模板参数
+ **模板参数**：编译期决定，影响“类型” 
+ **构造函数参数**：运行时传入，不影响类型 

1️⃣ 看起来像，但本质完全不同

✅ 模板参数（类型的一部分）

```cpp
std::unique_ptr<int, MyDeleter> p;
```

👉 这里：

+ `MyDeleter` 是**类型的一部分**
+  编译器会认为这是一个**全新类型**

---

✅ 构造函数参数（只是初始化数据）

```cpp
std::shared_ptr<int> p(new int, MyDeleter());
```

👉 这里：

+ `MyDeleter()` 只是**传进去的一个参数**
+ `shared_ptr<int>` 类型**没有变化**

2️⃣ 最关键区别（你必须抓住这个）

🧩 类型是否改变？

```cpp
std::unique_ptr<int, D1> p1;
std::unique_ptr<int, D2> p2;
```

👉 ❗这是**两个完全不同类型**  
👉 不能互相赋值

---

```cpp
std::shared_ptr<int> p1(new int, D1());
std::shared_ptr<int> p2(new int, D2());
```

👉 ✅ 这是**同一种类型**  
👉 可以互相赋值

## 问题2：两种不同的参数传入的是存放在哪里怎么进行使用的？
1.你可以把 `shared_ptr` 想成这样：

```plain
p（栈上）
 │
 ├── 指向对象（堆） → int
 │
 └── 指向控制块（堆）
         │
         ├── 引用计数
         ├── 删除器（MyDeleter）
         └── 其他信息
```

👉 **删除器就藏在“控制块”里**

删除器什么时候用？

👉 当引用计数变成 0：

```plain
~shared_ptr()
```

内部会做：

```plain
deleter(ptr);
```

👉 也就是：

```plain
MyDeleter()(ptr);
```

2.`unique_ptr` 没有控制块！结构非常简单：

```plain
p（栈上）
 │
 ├── 指向对象（堆） → int
 │
 └── 删除器（Deleter） ← 直接存在对象里
```

删除器什么时候调用？

👉 当 `unique_ptr` 销毁：

```plain
~unique_ptr()
```

内部逻辑类似：

```plain
deleter(ptr);
```

👉 也就是：

```plain
MyDeleter()(ptr);
```
