`class CTest : public std::enable_shared_from_this<CTest>`

 定义一个类  ： 表示 **公有继承   父类enable_shared_from_this<当前类>**  
这句的意思是：让 `CTest` 对象内部可以安全地拿到“指向自己”的 `shared_ptr`。  

 就是在成员函数里可以写：  

shared_from_this()

 它返回一个 `std::shared_ptr<CTest>`，指向当前对象 `this`。  
注意，它不是新建对象，而是**返回一个和外部 **`shared_ptr`** 共用引用计数的智能指针**。  

```cpp
sp3 ----> CTest对象
    |
    v
    vecCTest[0] ----> 同一个CTest对象
```

于是引用计数会这样变化：

+ `sp3` 创建后，计数是 **1**
+ `shared_from_this()` 放进 `vecCTest` 后，计数变成 **2**

当代码块结束时：

```cpp
{
    CTest* p1 = new CTest();
    std::shared_ptr<CTest> sp3(p1);
    sp3->Process();
}
```

`sp3` 析构了，计数从 2 变成 1。  
但对象内部的 `vecCTest` 里还存着一个指向自己的 `shared_ptr`，所以计数不会变成 0。

结果就是：

+  析构函数 **不会调用**
+ `~CTest`**不会打印**
+  对象泄漏了

`enable_shared_from_this`**为什么存在。**

假如你在成员函数里直接这样写：

```cpp
std::shared_ptr<CTest> sp(this);
```

这是危险的，因为它会创建一个**新的控制块**。  
外面本来已经有一个 `shared_ptr` 在管这个对象了，你又拿 `this` 单独生成一个新的 `shared_ptr`，就会导致两个独立的智能指针系统都以为自己拥有这个对象，最后可能重复释放。

`enable_shared_from_this` 就是为了解决这个问题：  
它让 `shared_from_this()` 返回和原来那个 `shared_ptr`**同一套引用计数** 的智能指针。

---

不过它有一个使用前提：  
对象必须已经被 `shared_ptr` 管理了，才能调用 `shared_from_this()`。

比如这个是对的：

```cpp
std::shared_ptr<CTest> sp3(new CTest());
sp3->Process();
```

但这个不行：

```cpp
CTest t;
t.Process();
```

因为 `t` 不是被 `shared_ptr` 管的，这时调用 `shared_from_this()` 会出错。
