## 41、C++中有几种类型的new
在C++中，new有三种典型的使用方法：plain new，nothrow new和placement new

（1）**plain new**

言下之意就是普通的new，就是我们常用的new，在C++中定义如下：

```cpp
void* operator new(std::size_t) throw(std::bad_alloc);
void operator delete(void *) throw();
```

```cpp
int* p = new int;
```

大致可以理解为：

```cpp
void* mem = operator new(sizeof(int)); // 先申请内存
int* p = static_cast<int*>(mem);       // 再构造 int 对象
```

因此**plain new**在空间分配失败的情况下，抛出异常**std::bad_alloc**而不是返回NULL，因此通过判断返回值是否为NULL是徒劳的，举个例子：

```cpp
#include <iostream>
#include <new>
using namespace std;

int main()
{
    try
    {
        char* p = new char[10e11]; // 申请非常大的内存

        delete[] p; // 注意：new[] 对应 delete[]
    }
    catch (const std::bad_alloc& ex)
    {
        cout << ex.what() << endl;
    }

    return 0;
}
//执行结果：bad allocation
```

（2）**nothrow new**

nothrow new在空间分配失败的情况下是不抛出异常，而是返回NULL，定义如下：

```cpp
void * operator new(std::size_t,const std::nothrow_t&) throw();
void operator delete(void*) throw();
```

```cpp
char* p = new (nothrow) char[1000000000000];
```

展开

```cpp
char* p = static_cast<char*>(
    operator new[](1000000000000 * sizeof(char), nothrow)
);
```

举个例子：

```cpp
#include  #include  
using namespace std;

int main()
{
    char *p = new(nothrow) char[10e11];
    if (p == NULL) 
    {
        cout << "alloc failed" << endl;
    }
    delete p;
    return 0;
}
//运行结果：alloc failed
```

（3）**placement new**

这种new允许在一块已经分配成功的内存上重新构造对象或对象数组。placement new不用担心内存分配失败，因为它根本不分配内存，它做的唯一一件事情就是调用对象的构造函数。定义如下：

```cpp
void* operator new(size_t,void*);
void operator delete(void*,void*);
```

```cpp
char* p = new (nothrow) char[sizeof(ADT) + 1];

ADT* q = new (p) ADT;
```

展开

```cpp
// 1. 申请一块原始内存，大小是 sizeof(ADT) + 1 字节
void* mem = operator new[](
    sizeof(ADT) + 1,
    nothrow
);

// 2. 转成 char*，交给 p 保存
char* p = static_cast<char*>(mem);

// 3. 在 p 指向的这块内存上，直接构造 ADT 对象
ADT* q = new (p) ADT;
```

其中第 3 步还可以继续理解为：

```cpp
// placement new：不再重新申请内存
// 只是把 ADT 对象“放到”p 指向的地址上
ADT* q = reinterpret_cast<ADT*>(p);

// 在 q 指向的位置调用构造函数
q->ADT::ADT(); // 只是帮助理解，构造函数不能这样直接调用
```

使用placement new需要注意两点：

+  palcement new的主要用途就是反复使用一块较大的动态分配的内存来构造不同类型的对象或者他们的数组
+  placement new构造起来的对象数组，要显式的调用他们的析构函数来销毁（析构函数并不释放对象的内存），千万不要使用delete，这是因为placement new构造起来的对象或数组大小并不一定等于原来分配的内存大小，使用delete会造成内存泄漏或者之后释放内存时出现运行时错误。

举个例子：

```cpp
#include <iostream>
#include <new>
using namespace std;

class ADT
{
private:
    int i;
    int j;

public:
    ADT()
    {
        i = 10;
        j = 100;
        cout << "ADT construct i = " << i << ", j = " << j << endl;
    }

    ~ADT()
    {
        cout << "ADT destruct" << endl;
    }
};

int main()
{
    // 1. 只申请原始内存，不调用构造函数
    char* p = new (nothrow) char[sizeof(ADT) + 1];

    if (p == nullptr)
    {
        cout << "alloc failed" << endl;
        return -1;
    }

    // 2. placement new：在 p 指向的内存上构造 ADT 对象
    ADT* q = new (p) ADT;

    // 3. 不能 delete q，因为 q 指向的内存不是普通 new ADT 申请的
    // delete q; // 错误

    // 4. 显式调用析构函数
    q->~ADT();

    // 5. 释放原始内存
    delete[] p;

    return 0;
}
//
ADT construct i = 10, j = 100
ADT destruct
```

所以整体意思是：

```plain
p 指向一块原始内存
q 把这块内存当成 ADT 对象来使用
```

图示：

```plain
堆区原始内存：
p ─────► [ sizeof(ADT) + 1 字节 ]

placement new 后：

p ─────► [ ADT对象 ][ 多出来的1字节 ]
q ─────► [ ADT对象 ]
```

** p和q都能管理这个对象吗？  **

不是。

```cpp
char* p = new (nothrow) char[sizeof(ADT) + 1];
ADT* q = new (p) ADT;
```

它们职责不同：

```plain
p：管理原始内存
q：管理/访问构造出来的 ADT 对象
```

更准确地说：

```plain
p 指向整块内存的起始地址
q 也指向同一块内存的起始地址
```

但是类型不同：

```plain
p 是 char*，只能按字节看这块内存
q 是 ADT*，可以把这块内存当 ADT 对象使用
```

所以释放时要这样：

```cpp
q->~ADT();   // q 负责调用析构函数，销毁对象
delete[] p;  // p 负责释放原始内存
```

不能这样：

```cpp
delete q; // 错误
```

因为这块内存不是通过：`new ADT`申请的，而是通过：`new char[]`申请的。

## 42、C++的异常处理的方法
在程序执行过程中，由于程序员的疏忽或是系统资源紧张等因素都有可能导致异常，任何程序都无法保证绝对的稳定，常见的异常有：

+ 数组下标越界
+ 除法计算时除数为0
+ 动态分配空间时空间不足
+ ...

如果不及时对这些异常进行处理，程序多数情况下都会崩溃。

**（1）try、throw和catch关键字**

C++中的异常处理机制主要使用**try**、**throw**和**catch**三个关键字，其在程序中的用法如下：

```cpp
#include <iostream>
using namespace std;

int main()
{
    double m = 1;
    double n = 0;

    try
    {
        cout << "before dividing." << endl;

        if (n == 0)
        {
            throw -1;      // 抛出 int 类型异常
        }
        else if (m == 0)
        {
            throw -1.0;    // 抛出 double 类型异常
        }
        else
        {
            cout << m / n << endl;
        }

        cout << "after dividing." << endl;
    }
    catch (double d)
    {
        cout << "catch (double): " << d << endl;
    }
    catch (...)
    {
        cout << "catch (...)" << endl;
    }

    cout << "finished" << endl;

    return 0;
}
//结果：
before dividing.
catch (...)
finished
```

代码中，对两个数进行除法计算，其中除数为0。可以看到以上三个关键字，程序的执行流程是先执行try包裹的语句块，如果执行过程中没有异常发生，则不会进入任何catch包裹的语句块，如果发生异常，则使用throw进行异常抛出，再由catch进行捕获，throw可以抛出各种数据类型的信息，代码中使用的是数字，也可以自定义异常class。**catch根据throw抛出的数据类型进行精确捕获（不会出现类型转换），如果匹配不到就直接报错，可以使用catch(...)的方式捕获任何异常（不推荐）。**当然，如果catch了异常，当前函数如果不进行处理，或者已经处理了想通知上一层的调用者，可以在catch里面再throw异常。

**（2）函数的异常声明列表**

有时候，程序员在定义函数的时候知道函数可能发生的异常，可以在函数声明和定义时，指出所能抛出异常的列表，写法如下：

```cpp
 int fun() throw(int,double,A,B,C){...};
```

这种写法表名函数可能会抛出int,double型或者A、B、C三种类型的异常，如果throw中为空，表明不会抛出任何异常，如果没有throw则可能抛出任何异常

```cpp
#include <iostream>
using namespace std;

class A {};
class B {};
class C {};

// 表示 fun 可能抛出 int、double、A、B、C 类型异常
int fun(int type) throw(int, double, A, B, C)
{
    if (type == 1)
        throw 1;        // int 异常
    else if (type == 2)
        throw 1.1;      // double 异常
    else if (type == 3)
        throw A();      // A 类型异常
    else if (type == 4)
        throw B();      // B 类型异常
    else if (type == 5)
        throw C();      // C 类型异常

    return 0;
}

// throw() 表示不抛出任何异常
void test() throw()
{
    cout << "test 不抛异常" << endl;
}

int main()
{
    try
    {
        fun(2);
    }
    catch (int e)
    {
        cout << "catch int: " << e << endl;
    }
    catch (double e)
    {
        cout << "catch double: " << e << endl;
    }
    catch (A)
    {
        cout << "catch A" << endl;
    }
    catch (B)
    {
        cout << "catch B" << endl;
    }
    catch (C)
    {
        cout << "catch C" << endl;
    }

    test();

    return 0;
}
//结果：
catch double: 1.1
test 不抛异常
```

**（3）C++标准异常类  exception**

C++ 标准库中有一些类代表异常，这些类都是从 exception 类派生而来的，如下图所示

```plain
std::exception
├── std::bad_typeid
├── std::bad_cast
├── std::bad_alloc
├── std::ios_base::failure
└── std::logic_error
    └── std::out_of_range
```

+ bad_typeid：使用typeid运算符，如果其操作数是一个多态类的指针（ 多态类的指针，就是指向“含有虚函数的类”的指针。  ），而该指针的值为 NULL，则会拋出此异常，例如：

```cpp
#include  #include  
using namespace std;

class A{
public:
virtual ~A();
};

int main() {
    A* a = NULL;
    try {
        cout << typeid(*a).name() << endl; // Error condition
    }
    catch (bad_typeid){
        cout << "Object is NULL" << endl;
    }
    return 0;
}
//运行结果：bject is NULL
```

+ bad_cast：在用 dynamic_cast 进行从多态基类对象（或引用）到派生类的引用的强制类型转换时，如果转换是不安全的，则会拋出此异常
+ bad_alloc：在用 new 运算符进行动态内存分配时，如果没有足够的内存，则会引发此异常
+ out_of_range:用 vector 或 string的at 成员函数根据下标访问元素时，如果下标越界，则会拋出此异常

### 42、补充1：noexcept
 注意：这种写法是 **C++ 旧标准的动态异常规范**，现在基本不用了。  

```cpp
throw()  // 旧写法
noexcept // 新写法
```

`noexcept` 是 C++11 引入的关键字，用来说明：

```plain
这个函数承诺不会抛出异常
```

或者更准确地说：

```plain
如果这个函数抛出了异常，程序会直接终止
```

1. 最基本写法

```cpp
void func() noexcept
{
    cout << "这个函数承诺不抛异常" << endl;
}
```

```plain
func 函数不会抛出异常
```

如果它真的抛出了异常，比如：

```cpp
void func() noexcept
{
    throw 1;
}
```

那么异常不会被外面的 `catch` 捕获，程序会直接调用 `std::terminate()` 终止。

2. 示例代码

```cpp
#include <iostream>
using namespace std;

void fun1()
{
    throw 1;
}

void fun2() noexcept
{
    throw 1;
}

int main()
{
    try
        {
            fun1();
        }
    catch (int e)
        {
            cout << "catch fun1 exception: " << e << endl;
        }

    try
        {
            fun2();
        }
    catch (int e)
        {
            cout << "catch fun2 exception: " << e << endl;
        }

    cout << "finished" << endl;

    return 0;
}
```

运行结果大致是：

```cpp
catch fun1 exception: 1
terminate called after throwing an instance of 'int'
```

原因是：

```cpp
fun1()
```

没有 `noexcept`，所以抛出的异常可以被 `catch` 捕获。

```cpp
fun2() noexcept
```

承诺不抛异常，结果它真的抛了，所以程序直接终止。

3. noexcept 和 throw() 的关系

以前 C++ 旧写法是：

```cpp
void fun() throw()
{
}
```

意思是：

```plain
这个函数不抛异常
```

现代 C++ 推荐写：

```cpp
void fun() noexcept
{
}
```

所以可以简单理解为：

```cpp
throw()   // 旧写法
noexcept  // 新写法
```

现在写代码时优先用 `noexcept`。

4. noexcept 可以带条件

`noexcept` 后面可以加一个表达式：

```cpp
void fun() noexcept(true)
{
}
```

等价于：

```cpp
void fun() noexcept
{
}
```

表示不抛异常。

也可以写：

```cpp
void fun() noexcept(false)
{
}
```

表示这个函数可能抛异常。

```cpp
#include <iostream>
using namespace std;

void fun1() noexcept(true)
{
    cout << "fun1 不抛异常" << endl;
}

void fun2() noexcept(false)
{
    cout << "fun2 可能抛异常" << endl;
    throw 1;
}

int main()
{
    fun1();

    try
        {
            fun2();
        }
    catch (int e)
        {
            cout << "catch exception: " << e << endl;
        }

    return 0;
}
```

输出：

```cpp
fun1 不抛异常
fun2 可能抛异常
catch exception: 1
```

5. noexcept 也可以用来判断表达式会不会抛异常

注意这里有两种用法：

第一种：修饰函数

```cpp
void fun() noexcept
{
}
```

第二种：作为运算符使用

```cpp
noexcept(表达式)
```

它会返回 `true` 或 `false`。

示例：

```cpp
#include <iostream>
using namespace std;

void fun1() noexcept
{
}

void fun2()
{
}

int main()
{
    cout << boolalpha;

    cout << noexcept(fun1()) << endl;
    cout << noexcept(fun2()) << endl;

    return 0;
}
```

输出：

```cpp
true
false
```

解释：

```cpp
noexcept(fun1())
```

表示判断：

```cpp
fun1() 这个表达式会不会抛异常
```

因为 `fun1` 被声明为 `noexcept`，所以结果是 `true`。

而：

```cpp
fun2()
```

没有声明 `noexcept`，所以编译器认为它可能抛异常，结果是 `false`。

6. noexcept 常用于移动构造函数

这是非常重要的用途。

比如：

```cpp
class Person
{
public:
    Person(Person&& other) noexcept
    {
        cout << "移动构造函数" << endl;
    }
};
```

为什么移动构造函数常常写 `noexcept`？

因为很多 STL 容器，比如 `vector`，在扩容时会搬移元素。

如果移动构造函数是 `noexcept`，`vector` 更愿意使用移动构造。

如果移动构造函数可能抛异常，`vector` 为了安全，可能会使用拷贝构造。

示例：

```cpp
#include <iostream>
#include <vector>
using namespace std;

class Person
{
public:
    Person()
    {
        cout << "默认构造" << endl;
    }

    Person(const Person&)
    {
        cout << "拷贝构造" << endl;
    }

    Person(Person&&) noexcept
    {
        cout << "移动构造" << endl;
    }
};

int main()
{
    vector<Person> v;

    v.push_back(Person());
    v.push_back(Person());

    return 0;
}
```

你会看到扩容时更倾向于调用：

```plain
移动构造
```

如果把：

```cpp
Person(Person&&) noexcept
```

改成：

```cpp
Person(Person&&)
```

有些情况下 `vector` 可能会改用：

```plain
拷贝构造
```

7. 析构函数默认是 noexcept

例如：

```cpp
class A
{
public:
    ~A()
    {
    }
};
```

这个析构函数默认相当于：

```cpp
~A() noexcept
{
}
```

所以析构函数里面最好不要抛异常。

错误示例：

```cpp
class A
{
public:
    ~A()
    {
        throw 1;
    }
};
```

这样很危险，可能导致程序直接终止。

析构函数一般应该写成：

```cpp
~A() noexcept
{
    // 清理资源，不抛异常
}
```

8. 总结

你可以这样记：

```cpp
void fun() noexcept;
```

意思是：

```plain
fun 承诺不抛异常
```

如果违反承诺：

```plain
程序直接终止
```

旧写法：

```cpp
void fun() throw();
```

新写法：

```cpp
void fun() noexcept;
```

常见使用场景：

```plain
析构函数
移动构造函数
移动赋值运算符
swap 函数
释放资源的函数
```

最常见写法：

```cpp
class A
{
public:
    A(A&& other) noexcept
    {
    }

    A& operator=(A&& other) noexcept
    {
        return *this;
    }

    ~A() noexcept
    {
    }
};
```

一句话理解：noexcept 是给编译器和程序员看的承诺：这个函数不会抛异常。

### 42、补充二： typeid  
`typeid` 是 C++ 里的一个运算符，用来获取一个对象或类型的**类型信息**。

需要头文件：

```cpp
#include <typeinfo>
```

最常见用法：

```plain
typeid(变量).name()
typeid(类型).name()
```

1. 基本示例

```cpp
#include <iostream>
#include <typeinfo>
using namespace std;

int main()
{
    int a = 10;
    double b = 3.14;

    cout << typeid(a).name() << endl;
    cout << typeid(b).name() << endl;
    cout << typeid(int).name() << endl;
    cout << typeid(double).name() << endl;

    return 0;
}
```

可能输出：

```cpp
i
d
i
d
```

不同编译器输出可能不一样：

```cpp
GCC 中 int 可能显示 i
GCC 中 double 可能显示 d
MSVC 中可能显示 int、double
```

所以 `typeid(...).name()` 的输出结果和编译器有关。

2. 判断两个变量类型是否相同

```cpp
#include <iostream>
#include <typeinfo>
using namespace std;

int main()
{
    int a = 10;
    int b = 20;
    double c = 3.14;

    if (typeid(a) == typeid(b))
    {
        cout << "a 和 b 类型相同" << endl;
    }

    if (typeid(a) != typeid(c))
    {
        cout << "a 和 c 类型不同" << endl;
    }

    return 0;
}
```

输出：

```plain
a 和 b 类型相同
a 和 c 类型不同
```

3. typeid 用在普通类上

```cpp
#include <iostream>
#include <typeinfo>
using namespace std;

class Base
{
};

class Derived : public Base
{
};

int main()
{
    Derived d;
    Base* p = &d;

    cout << typeid(p).name() << endl;
    cout << typeid(*p).name() << endl;

    return 0;
}
```

这里要注意：

```cpp
typeid(p)
```

看的是 `p` 本身的类型。

所以它是：

```cpp
Base*
```

而：

```cpp
typeid(*p)
```

看的是 `p` 指向的对象类型。

但是这里 `Base` 不是多态类，因为没有虚函数。

所以：

```plain
typeid(*p)
```

得到的是静态类型：

```plain
Base
```

不是 `Derived`。

4. typeid 用在多态类上

如果类里面有虚函数，这个类就是多态类。

```cpp
#include <iostream>
#include <typeinfo>
using namespace std;

class Base
{
public:
    virtual void show()
    {
    }
};

class Derived : public Base
{
public:
    void show() override
    {
    }
};

int main()
{
    Derived d;
    Base* p = &d;

    cout << typeid(p).name() << endl;
    cout << typeid(*p).name() << endl;

    return 0;
}
```

此时：

```cpp
typeid(p)
```

还是看指针变量本身类型：

```plain
Base*
```

但是：

```plain
typeid(*p)
```

会看 `p` 实际指向的对象类型。

因为 `p` 实际指向的是：

```plain
Derived d;
```

所以得到的是：

```plain
Derived
```

5. 关键区别：typeid(p) 和 typeid(*p)

假设：

```cpp
Base* p = new Derived;
```

那么：

```cpp
typeid(p)
```

看的是指针变量 `p` 的类型：

```plain
Base*
```

而：

```cpp
typeid(*p)
```

看的是 `p` 指向的对象类型。

如果 `Base` 是多态类：

```cpp
typeid(*p) 结果是 Derived
```

如果 `Base` 不是多态类：

```cpp
typeid(*p) 结果是 Base
```

## 43、static的用法和作用？
1.先来介绍它的第一条也是最重要的一条：隐藏。（static函数，static变量均可）

当同时编译多个文件时，所有未加static前缀的全局变量和函数都具有全局可见性。



2.static的第二个作用是保持变量内容的持久。（static变量中的记忆功能和全局生存期）存储在静态数据区的变量会在程序刚开始运行时就完成初始化，也是唯一的一次初始化。共有两种变量存储在静态存储区：全局变量和static变量，只不过和全局变量比起来，static可以控制变量的可见范围，说到底static还是用来隐藏的。

```cpp
#include <iostream>
using namespace std;

void func()
{
    static int a = 0;   // static局部变量
    a++;
    cout << a << endl;
}

int main()
{
    func();//1
    func();//2
    func();//3
    return 0;
}
```

3.static的第三个作用是默认初始化为0（static变量）

其实全局变量也具备这一属性，因为全局变量也存储在静态数据区。在静态数据区，内存中所有的字节默认值都是0x00，某些时候这一特点可以减少程序员的工作量。



4.static的第四个作用：C++中的类成员声明static

+ 函数体内static变量的作用范围为该函数体，不同于auto变量，该变量的内存只被分配一次，因此其值在下次调用时仍维持上次的值；
+ 在模块内的static全局变量可以被模块内所有函数访问，但不能被模块外其它函数访问；
+ 在模块内的static函数只可被这一模块内的其它函数调用，这个函数的使用范围被限制在声明它的模块内；
+ 在类中的static成员变量属于整个类所拥有，对类的所有对象只有一份拷贝；
+ 在类中的static成员函数属于整个类所拥有，这个函数不接收this指针，因而只能访问类的static成员变量。

```cpp
#include <iostream>
using namespace std;

class Student
{
public:
    string name;

    // 1. static 成员变量声明
    static int count;

public:
    Student(string n)
    {
        name = n;
        count++;   // 每创建一个对象，学生总数 +1
    }

    void show()
    {
        cout << "学生姓名: " << name << endl;
        cout << "当前学生总数: " << count << endl;
    }

    // 2. static 成员函数
    static void showCount()
    {
        cout << "学生总数是: " << count << endl;

        // cout << name << endl; 
        // 错误！static成员函数不能直接访问普通成员变量
        // 因为它没有 this 指针
    }
};

// 3. static 成员变量必须在类外定义
int Student::count = 0;

int main()
{
    Student s1("张三");
    Student s2("李四");
    Student s3("王五");

    s1.show();
    s2.show();
    s3.show();

    cout << "----------------" << endl;

    // 4. static成员变量属于类，可以通过类名访问
    cout << Student::count << endl;

    // 5. static成员函数也属于类，可以通过类名调用
    Student::showCount();

    return 0;
}

//输出

当前学生总数: 3
学生姓名: 李四
当前学生总数: 3
学生姓名: 王五
当前学生总数: 3
----------------
3
学生总数是: 3
```

类内：

+ static类对象必须要在类外进行初始化，static修饰的变量先于对象存在，所以static修饰的变量要在类外初始化；
+ 由于static修饰的类成员属于类，不属于对象，因此static类成员函数是没有this指针的，this指针是指向本对象的指针。正因为没有this指针，所以static类成员函数不能访问非static的类成员，只能访问 static修饰的类成员；

| 概念 | 类 | 对象 |
| --- | --- | --- |
| 含义 | 模板、图纸、类型 | 具体实例 |
| 是否占内存 | 类本身不代表具体数据对象 | 对象会占内存 |
| 举例 | `Student` | `s1`<br/>、`s2` |
| 类比 | 汽车设计图 | 一辆具体的汽车 |
| 内容 | 定义有哪些属性和方法 | 真正保存属性值 |


+ static成员函数不能被virtual修饰，static成员不属于任何对象或实例，所以加上virtual没有任何实际意义；静态成员函数没有this指针，虚函数的实现是为每一个对象分配一个vptr指针，而vptr是通过this指针调用的，所以不能为virtual；虚函数的调用关系，this->vptr->vtable->virtual function

| 名称 | 作用 |
| --- | --- |
| `this` | 指向当前对象 |
| `vptr` | 虚函数表指针，通常存在对象内部 |
| `vtable` | 虚函数表，里面存放虚函数地址 |
| `virtual function` | 最终要调用的虚函数 |


## 44、指针和const的用法
1. 当const修饰指针时，由于const的位置不同，它的修饰对象会有所不同。
2. int *_const p2中const修饰p2的值,所以理解为p2的值不可以改变，即p2只能指向固定的一个变量地址，但可以通过_p2读写这个变量的值。顶层指针表示指针本身是一个常量
3. int const *_p1或者const int *p1两种情况中const修饰*p1，所以理解为*_p1的值不可以改变，即不可以给*p1赋值改变p1指向变量的值，但可以通过给p赋值不同的地址改变这个指针指向。

底层指针表示指针所指向的变量是一个常量。

## 45、形参与实参的区别？
1. 形参变量只有在被调用时才分配内存单元，在调用结束时， 即刻释放所分配的内存单元。因此，形参只有在函数内部有效。 函数调用结束返回主调函数后则不能再使用该形参变量。
2. 实参可以是常量、变量、表达式、函数等， 无论实参是何种类型的量，在进行函数调用时，它们都必须具有确定的值， 以便把这些值传送给形参。 因此应预先用赋值，输入等办法使实参获得确定值，会产生一个临时变量。
3. 实参和形参在数量上，类型上，顺序上应严格一致， 否则会发生“类型不匹配”的错误。
4. 函数调用中发生的数据传送是单向的。 即只能把实参的值传送给形参，而不能把形参的值反向地传送给实参。 因此在函数调用过程中，形参的值发生改变，而实参中的值不会变化。
5. 当形参和实参不是指针类型时，在该函数运行时，形参和实参是不同的变量，他们在内存中位于不同的位置，形参将实参的内容复制一份，在该函数运行结束的时候形参被释放，而实参内容不会改变。

```cpp
#include <iostream>
using namespace std;

// a 和 b 是形参
void change(int a, int b)
{
    cout << "函数内部修改前：" << endl;
    cout << "a = " << a << ", b = " << b << endl;

    a = 100;
    b = 200;

    cout << "函数内部修改后：" << endl;
    cout << "a = " << a << ", b = " << b << endl;
}

int main()
{
    int x = 10;
    int y = 20;

    cout << "函数调用前：" << endl;
    cout << "x = " << x << ", y = " << y << endl;

    // x 和 y 是实参
    change(x, y);

    cout << "函数调用后：" << endl;
    cout << "x = " << x << ", y = " << y << endl;

    return 0;
}
//
函数调用前：
x = 10, y = 20
函数内部修改前：
a = 10, b = 20
函数内部修改后：
a = 100, b = 200
函数调用后：
x = 10, y = 20
```

## 46、值传递、指针传递、引用传递的区别和效率
1. 值传递：有一个形参向函数所属的栈拷贝数据的过程，如果值传递的对象是类对象或是大的结构体对象，将耗费一定的时间和空间。（传值）
2. 指针传递：同样有一个形参向函数所属的栈拷贝数据的过程，但拷贝的数据是一个固定为4字节的地址。（传值，传递的是地址值）
3. 引用传递：同样有上述的数据拷贝过程，但其是针对地址的，相当于为该数据所在的地址起了一个别名。（传地址）
4. 效率上讲，指针传递和引用传递比值传递效率高。一般主张使用引用传递，代码逻辑上更加紧凑、清晰。

引用传递和指针传递底层通常都是传地址，效率基本一样；引用不是因为效率低才少用，而是根据语义选择：必须有对象用引用，可以为空用指针。  

```cpp
#include <iostream>
using namespace std;

// 1. 值传递：形参是实参的一份拷贝
void valuePass(int x)
{
    x = 100;
    cout << "值传递函数内部 x = " << x << endl;
}

// 2. 指针传递：传的是变量地址
void pointerPass(int* p)
{
    *p = 200;
    cout << "指针传递函数内部 *p = " << *p << endl;
}

// 3. 引用传递：形参是实参的别名
void referencePass(int& r)
{
    r = 300;
    cout << "引用传递函数内部 r = " << r << endl;
}

int main()
{
    int a = 10;
    int b = 10;
    int c = 10;

    cout << "调用前：" << endl;
    cout << "a = " << a << endl;
    cout << "b = " << b << endl;
    cout << "c = " << c << endl;

    cout << "----------------" << endl;

    valuePass(a);
    pointerPass(&b);
    referencePass(c);

    cout << "----------------" << endl;

    cout << "调用后：" << endl;
    cout << "a = " << a << endl;
    cout << "b = " << b << endl;
    cout << "c = " << c << endl;

    return 0;
}
//
调用前：
a = 10
b = 10
c = 10
----------------
值传递函数内部 x = 100
指针传递函数内部 *p = 200
引用传递函数内部 r = 300
----------------
调用后：
a = 10
b = 200
c = 300
```

2. 静态局部变量和全局变量一样，数据都存放在全局区域，所以在主程序之前，编译器已经为其分配好了内存，但在C和C++中静态局部变量的初始化节点又有点不太一样。在C中，初始化发生在代码执行之前，编译阶段分配好内存之后，就会进行初始化，所以我们看到在C语言中无法使用变量对静态局部变量进行初始化，在程序运行结束，变量所处的全局内存会被全部回收。

```cpp
#include <iostream>
using namespace std;

int getValue()
{
    int x = 10;
    return x + 20;
}

void func()
{
    static int a = getValue();  // C++中可以这样写
    cout << a << endl;
}

int main()
{
    func();
    return 0;
}
```

```c
#include <stdio.h>

void func()
{
    int x = 10;

    static int a = x;  // C语言中错误，x不是常量表达式

    printf("%d\n", a);
}

int main()
{
    func();
    return 0;
}
```

3. 而在C++中，初始化时在执行相关代码时才会进行初始化，主要是由于C++引入对象后，要进行初始化必须执行相应构造函数和析构函数，在构造函数或析构函数中经常会需要进行某些程序中需要进行的特定操作，并非简单地分配内存。所以C++标准定为全局或静态对象是有首次用到时才会进行构造，并通过atexit()来管理。在程序结束，按照构造顺序反方向进行逐个析构。所以在C++中是可以使用变量对静态局部变量进行初始化的。

```cpp
{
    cout << "main 开始" << endl;

    func();
    func();

    cout << "main 结束" << endl;

}
//
main 开始
进入 func()
Test 构造函数执行
离开 func()
进入 func()
离开 func()
main 结束
Test 析构函数执行
```

## 48、const关键字的作用有哪些?
1. 阻止一个变量被改变，可以使用const关键字。在定义该const变量时，通常需要对它进行初始化，因为以后就没有机会再去改变它了；
2. 对指针来说，可以指定指针本身为const，也可以指定指针所指的数据为const，或二者同时指定为const；
3. 在一个函数声明中，const可以修饰形参，表明它是一个输入参数，在函数内部不能改变其值；
4. 对于类的成员函数，若指定其为const类型，则表明其是一个常函数，不能修改类的成员变量，类的常对象只能访问类的常成员函数；
5. 对于类的成员函数，有时候必须指定其返回值为const类型，以使得其返回值不为“左值”。
6. const成员函数可以访问非const对象的非const数据成员、const数据成员，也可以访问const对象内的所有数据成员；
7. 非 const 成员函数可以被非 const 对象调用，也可以访问该对象的普通成员和 const 成员；但非 const 成员函数不能被 const 对象调用。  
8.  一个没有明确声明为const的成员函数被看作是将要修改对象中数据成员的函数，而且编译器不允许它为一个const对象所调用。因此const对象只能调用const成员函数。
9. const类型变量可以通过类型转换符const_cast将const类型转换为非const类型；
10. const类型变量必须定义的时候进行初始化，因此也导致如果类的成员变量有const类型的变量，那么该变量必须在类的初始化列表中进行初始化；
11. 对于函数值传递的情况，因为参数传递是通过复制实参创建一个临时变量传递进函数的，函数内只能改变临时变量，但无法改变实参。则这个时候无论加不加const对实参不会产生任何影响。但是在引用或指针传递函数调用中，因为传进去的是一个引用或指针，这样函数内部可以改变引用或指针所指向的变量，这时const 才是实实在在地保护了实参所指向的变量。因为在编译阶段编译器对调用函数的选择是根据实参进行的，所以，只有引用传递和指针传递可以用是否加const来重载。一个拥有顶层const的形参无法和另一个没有顶层const的形参区分开来。

## 49、什么是类的继承？
+ 类与类之间的关系

has-A包含关系，用以描述一个类由多个部件类构成，实现has-A关系用类的成员属性表示，即一个类的成员属性是另一个已经定义好的类；

use-A，一个类使用另一个类，通过类之间的成员函数相互联系，定义友元或者通过传递参数的方式来实现；

is-A，继承关系，关系具有传递性；

+ 继承的相关概念

所谓的继承就是一个类继承了另一个类的属性和方法，这个新的类包含了上一个类的属性和方法，被称为子类或者派生类，被继承的类称为父类或者基类；

+ 继承的特点

子类拥有父类的所有属性和方法，子类可以拥有父类没有的属性和方法，子类对象可以当做父类对象使用；

+ 继承中的访问控制
+ public、protected、private
+ 继承中的构造和析构函数
+ 继承中的兼容性原则

例如：

汽车 has-A 发动机  
汽车 has-A 轮胎

```cpp
#include <iostream>
using namespace std;

// 部件类：发动机
class Engine
{
public:
    void start()
    {
        cout << "发动机启动" << endl;
    }
};

// 部件类：轮胎
class Wheel
{
public:
    void rotate()
    {
        cout << "轮胎转动" << endl;
    }
};

// 整体类：汽车
class Car
{
private:
    Engine engine;  // Car has-A Engine
    Wheel wheel;    // Car has-A Wheel

public:
```

## 50、从汇编层去解释一下引用
```cpp
 9:      int x = 1;
00401048  mov     dword ptr [ebp-4],1
10:     int &b = x;
0040104F   lea     eax,[ebp-4]
00401052  mov     dword ptr [ebp-8],eax
```

x的地址为ebp-4，b的地址为ebp-8，因为栈内的变量内存是从高往低进行分配的，所以b的地址比x的低。

lea eax,[ebp-4] 这条语句将x的地址ebp-4放入eax寄存器

mov dword ptr [ebp-8],eax 这条语句将eax的值放入b的地址

ebp-8中上面两条汇编的作用即：将x的地址存入变量b中，这不和将某个变量的地址存入指针变量是一样的吗？所以从汇编层次来看，的确引用是通过指针来实现的。

## 51、深拷贝与浅拷可以描述一下吗？
浅复制 ：只是拷贝了基本类型的数据，而引用类型数据，复制后也是会发生引用，我们把这种拷贝叫做“（浅复制）浅拷贝”。

换句话说，浅复制仅仅是指向被复制的内存地址，如果原地址中对象被改变了，那么浅复制出来的对象也会相应改变。

深复制 ：在计算机中开辟了一块新的内存地址用于存放复制的对象。

在某些状况下，类内成员变量需要动态开辟堆内存，如果实行位拷贝，也就是把对象里的值完全复制给另一个对象，如A=B。

这时，如果B中有一个成员变量指针已经申请了内存，那A中的那个成员变量也指向同一块内存，这就出现了问题：当B把内存释放了（如：析构），这时A内的指针就是悬挂指针了，出现运行错误。

1. 浅拷贝示例：两个对象指向同一块堆内存

```cpp
#include <iostream>
#include <cstring>
using namespace std;

class Person
{
public:
    char* name;

    Person(const char* n)
    {
        name = new char[strlen(n) + 1];
        strcpy(name, n);
    }

    ~Person()
    {
        delete[] name;
    }
};

int main()
{
    Person p1("Jack");

    Person p2 = p1;   // 默认拷贝构造函数：浅拷贝

    cout << p1.name << endl;
    cout << p2.name << endl;

    return 0;
}
```

这段代码的问题在这里：

```cpp
Person p2 = p1;
```

如果没有自己写拷贝构造函数，C++ 默认是**浅拷贝**，也就是直接把 `p1.name` 的地址复制给 `p2.name`。

相当于：

```cpp
p2.name = p1.name;
```

所以 `p1.name` 和 `p2.name` 指向同一块内存。

---

2. 浅拷贝的问题

可以理解成这样：

```plain
p1.name  --->  堆内存："Jack"
p2.name  ---^
```

两个对象共用同一块堆内存。

程序结束时：

```cpp
~Person()
{
    delete[] name;
}
```

`p1` 会释放一次，`p2` 也会释放一次。

同一块内存被释放两次，就可能出现：

```plain
double free
```

也就是**重复释放内存错误**。

---

3. 深拷贝示例：重新开辟一块内存

正确写法是自己写拷贝构造函数：

```cpp
#include <iostream>
#include <cstring>
using namespace std;

class Person
{
public:
    char* name;

    Person(const char* n)
    {
        name = new char[strlen(n) + 1];
        strcpy(name, n);
    }

    // 自定义拷贝构造函数：深拷贝
    Person(const Person& p)
    {
        name = new char[strlen(p.name) + 1];
        strcpy(name, p.name);
    }

    ~Person()
    {
        delete[] name;
    }
};

int main()
{
    Person p1("Jack");

    Person p2 = p1;   // 调用自定义拷贝构造函数，深拷贝

    cout << p1.name << endl;
    cout << p2.name << endl;

    return 0;
}
```

这里：

```cpp
Person(const Person& p)
{
    name = new char[strlen(p.name) + 1];
    strcpy(name, p.name);
}
```

意思是：给 `p2.name` 重新申请一块新的堆内存，然后把 `p1.name` 中的内容复制过去。

---

4. 深拷贝的内存关系

深拷贝后是这样：

```plain
p1.name  --->  堆内存1："Jack"

p2.name  --->  堆内存2："Jack"
```

虽然内容一样，但是地址不一样。

所以析构时：

```plain
p1 释放自己的内存
p2 释放自己的内存
```

不会出现重复释放问题。

---

5. 再补一个赋值运算符的深拷贝

上面解决的是：

```cpp
Person p2 = p1;
```

这是**拷贝构造**。

但如果是：

```cpp
Person p1("Jack");
Person p2("Tom");

p2 = p1;
```

这叫**赋值操作**，还需要重载 `operator=`。

完整写法如下：

```cpp
#include <iostream>
#include <cstring>
using namespace std;

class Person
{
public:
    char* name;

    Person(const char* n)
    {
        name = new char[strlen(n) + 1];
        strcpy(name, n);
    }

    // 拷贝构造函数：用于 Person p2 = p1;
    Person(const Person& p)
    {
        name = new char[strlen(p.name) + 1];
        strcpy(name, p.name);
    }

    // 赋值运算符重载：用于 p2 = p1;
    Person& operator=(const Person& p)
    {
        if (this == &p)
        {
            return *this;
        }

        delete[] name;

        name = new char[strlen(p.name) + 1];
        strcpy(name, p.name);

        return *this;
    }

    ~Person()
    {
        delete[] name;
    }
};

int main()
{
    Person p1("Jack");
    Person p2("Tom");

    p2 = p1;   // 调用赋值运算符重载

    cout << p1.name << endl;
    cout << p2.name << endl;

    return 0;
}
```

6. 简单总结

浅拷贝：

```cpp
p2.name = p1.name;
```

特点是：

```plain
两个指针指向同一块内存
```

容易导致：

```plain
重复释放、悬挂指针、数据互相影响
```

深拷贝：

```cpp
p2.name = new char[strlen(p1.name) + 1];
strcpy(p2.name, p1.name);
```

特点是：

```plain
重新开辟内存，只复制内容，不共用地址
```

一句话记：

**浅拷贝拷贝地址，深拷贝拷贝内容并重新申请内存。**

## 52、new和malloc的区别
1、 new/delete是C++关键字，需要编译器支持。malloc/free是库函数，需要头文件支持；

2、 使用new操作符申请内存分配时无须指定内存块的大小，编译器会根据类型信息自行计算。而malloc则需要显式地指出所需内存的尺寸。

3、 new操作符内存分配成功时，返回的是对象类型的指针，类型严格与对象匹配，无须进行类型转换，故new是符合类型安全性的操作符。而malloc内存分配成功则是返回void * ，需要通过强制类型转换将void*指针转换成我们需要的类型。

4、 new内存分配失败时，会抛出bac_alloc异常。malloc分配内存失败时返回NULL。

5、 new会先调用operator new函数，申请足够的内存（通常底层使用malloc实现）。然后调用类型的构造函数，初始化成员变量，最后返回自定义类型指针。delete先调用析构函数，然后调用operator delete函数释放内存（通常底层使用free实现）。**malloc/free是库函数，只能动态的申请和释放内存，无法强制要求其做自定义类型对象构造和析构工作（6对其解释）。**

6、`new` 会调用构造函数，`delete` 会调用析构函数。`malloc/free` 只申请和释放内存，不会调用构造和析构  

## 53、delete p、delete [] p、allocator都有什么作用？
1、 动态数组管理new一个数组时，[]中必须是一个整数，但是不一定是常量整数，普通数组必须是一个常量整数；

2、 new动态数组返回的并不是数组类型，而是一个元素类型的指针；

3、 delete[]时，数组中的元素按逆序的顺序进行销毁；

4、 new在内存分配上面有一些局限性，new的机制是将内存分配和对象构造组合在一起，同样的，delete也是将对象析构和内存释放组合在一起的。allocator将这两部分分开进行，allocator申请一部分内存，不进行初始化对象，只有当需要的时候才进行初始化操作。

```cpp
#include <iostream>
#include <memory>
using namespace std;

class Student
{
public:
    int age;

    Student(int a)
    {
        age = a;
        cout << "构造 Student, age = " << age << endl;
    }

    ~Student()
    {
        cout << "析构 Student, age = " << age << endl;
    }
};

int main()
{
    allocator<Student> alloc;

    // 1. 只申请能放3个Student对象的原始内存，不调用构造函数
    Student* p = alloc.allocate(3);

    // 2. 在这块内存上构造对象
    alloc.construct(p, 18);
    alloc.construct(p + 1, 20);
    alloc.construct(p + 2, 22);

    cout << p[0].age << endl;
    cout << p[1].age << endl;
    cout << p[2].age << endl;

    // 3. 手动析构对象
    alloc.destroy(p + 2);
    alloc.destroy(p + 1);
    alloc.destroy(p);

    // 4. 释放原始内存
    alloc.deallocate(p, 3);

    return 0;
}

//输出
构造 Student, age = 18
构造 Student, age = 20
构造 Student, age = 22
18
20
22
析构 Student, age = 22
析构 Student, age = 20
析构 Student, age = 18
```

## 54、new和delete的实现原理， delete是如何知道释放内存的大小的？
1、 new简单类型直接调用operator new分配内存；

而对于复杂结构，先调用operator new分配内存，然后在分配的内存上调用构造函数；

对于简单类型，new[]计算好大小后调用operator new；

对于复杂数据结构，new[]先调用operator new[]分配内存，然后在p的前四个字节写入数组大小n，然后调用n次构造函数，针对复杂类型，new[]会额外存储数组大小；

①   new表达式调用一个名为operator new(operator new[])函数，分配一块足够大的、原始的、未命名的内存空间；

②   编译器运行相应的构造函数以构造这些对象，并为其传入初始值；

③   对象被分配了空间并构造完成，返回一个指向该对象的指针。

2、 delete简单数据类型默认只是调用free函数；复杂数据类型先调用析构函数再调用operator delete；针对简单类型，delete和delete[]等同。假设指针p指向new[]分配的内存。因为要4字节存储数组大小，实际分配的内存地址为[p-4]，系统记录的也是这个地址。delete[]实际释放的就是p-4指向的内存。而delete会直接释放p指向的内存，这个内存根本没有被系统记录，所以会崩溃。

3、 需要在 new [] 一个对象数组时，需要保存数组的维度，C++ 的做法是在分配数组空间时多分配了 4 个字节的大小，专门保存数组的大小，在 delete [] 时就可以取出这个保存的数，就知道了需要调用析构函数多少次了。

```plain
new 表达式会先调用 operator new 分配一块足够大的原始内存，
然后在这块内存上调用对象的构造函数，最后返回对象指针。

delete 表达式会先调用对象的析构函数，然后调用 operator delete
释放内存。如果是 delete[]，则会先根据保存的数组元素个数，
依次调用每个元素的析构函数，然后调用 operator delete[] 释放内存。

delete 之所以知道释放多大的内存，通常是因为底层堆分配器在分配内存时
会记录内存块大小等管理信息，释放时可以通过指针找到这些信息。
在 C++14 之后，编译器也可能调用带 size 参数的 sized delete，

```

```plain
new = operator new 分配内存 + 构造函数
delete = 析构函数 + operator delete 释放内存

delete 释放多大内存，通常由底层内存分配器记录；

```

## 55、malloc申请的存储空间能用delete释放吗?
不能，malloc /free主要为了兼容C，new和delete 完全可以取代malloc /free的。

malloc /free的操作对象都是必须明确大小的，而且不能用在动态类上。

new 和delete会自动进行类型检查和大小，malloc/free不能执行构造函数与析构函数，所以动态对象它是不行的。

当然从理论上说使用malloc申请的内存是可以通过delete释放的。不过一般不这样写的。而且也不能保证每个C++的运行时都能正常。

## 56、malloc与free的实现原理？
1、 在标准C库中，提供了malloc/free函数分配释放内存，这两个函数底层是由brk、mmap、，munmap这些系统调用实现的;

2、 brk是将「堆顶」指针向高地址移动，获得新的内存空间,mmap是在进程的虚拟地址空间中（堆和栈中间，称为文件映射区域的地方）找一块空闲的虚拟内存。这两种方式分配的都是虚拟内存，没有分配物理内存。在第一次访问已分配的虚拟地址空间的时候，发生缺页中断，操作系统负责分配物理内存，然后建立虚拟内存和物理内存之间的映射关系；

1. `brk` 的作用

`brk` 是通过调整进程的 **program break**，也就是常说的“堆顶指针”，来扩展堆空间。

可以简单理解为：

```plain
低地址
| 代码段 |
| 数据段 |
| BSS段  |
|  堆    |  <--- brk 向高地址移动，堆变大
|        |
| mmap映射区 |
|        |
|  栈    |  <--- 栈通常向低地址增长
高地址
```

当程序需要更多小块内存时，`malloc` 可能会通过 `brk` 把堆顶往高地址移动，从而获得一段新的虚拟地址空间。

例如：

```plain
void* p = malloc(100);
```

如果堆空间不够，底层可能会：

```plain
brk(新的堆顶地址);
```

这样堆就变大了。

2. `mmap` 的作用

`mmap` 不是移动堆顶，而是在进程虚拟地址空间中找一块空闲区域，建立一段新的映射。

它可以用于：

```plain
1. 文件映射
2. 匿名内存映射
3. 动态库加载
4. 大块内存分配
```

对于 `malloc` 来说，大块内存通常可能通过 `mmap` 分配。

例如：

```plain
void* p = malloc(10 * 1024 * 1024);
```

底层可能不会从堆里切，而是直接调用：

```plain
mmap(...)
```

申请一块独立的虚拟内存区域。

```plain
malloc 底层通常通过 brk 和 mmap 向操作系统申请内存。

brk 通过移动堆顶指针来扩大堆空间，适合管理较小、频繁申请的内存；
mmap 则是在进程虚拟地址空间中寻找一块空闲区域建立映射，常用于大块内存分配或文件映射。

brk 和 mmap 申请到的本质上都是虚拟内存，并不一定立即分配物理内存。
当程序第一次访问这段虚拟地址时，会触发缺页异常，由操作系统分配物理页，
并建立虚拟地址到物理地址的映射关系。

brk 是扩展堆，mmap 是单独映射；二者先拿到虚拟地址，物理内存通常按需分配。
```

3、 malloc小于128k的内存，使用brk分配内存，将「堆顶」指针往高地址推；malloc大于128k的内存，使用mmap分配内存，在堆和栈之间找一块空闲内存分配；brk分配的内存需要等到高地址内存释放以后才能释放，而mmap分配的内存可以单独释放。当最高地址空间的空闲内存超过128K（可由M_TRIM_THRESHOLD选项调节）时，执行内存紧缩操作（trim）。在上一个步骤free的时候，发现最高地址空闲内存超过128K，于是内存紧缩。

1. 什么是“最高地址空间的空闲内存”？

这里说的“最高地址空间”，主要指 **堆顶 top chunk**。

当 `malloc` 通过 `brk/sbrk` 扩展堆以后，堆空间大概是这样：

```plain
低地址
| 已分配块 |
| 空闲块   |
| 已分配块 |
| top chunk 空闲块 |  <--- 靠近堆顶的空闲内存
高地址
```

其中最靠近堆顶的那块空闲区域，通常叫：

```plain
top chunk
```

也就是堆末尾的空闲内存。

---

2. 为什么只有堆顶空闲内存容易归还？

因为 `brk` 管理堆时，本质上只能移动堆顶。

如果中间有一块空闲内存：

```plain
低地址
| 已分配 |
| 空闲   |
| 已分配 |
| top chunk |
高地址
```

中间那块空闲内存不能直接通过降低 `brk` 归还给操作系统。

因为它后面还有已分配对象挡着。

只有这种情况才方便归还：

```plain
低地址
| 已分配 |
| 已分配 |
| 大块空闲 top chunk |  <--- 在堆顶
高地址
```

这时可以把堆顶往回收缩：

```plain
brk 向低地址移动
```

相当于把堆末尾一部分虚拟地址空间还给操作系统。GNU C Library 手册也把 `M_TRIM_THRESHOLD` 描述为：当最顶部可释放 chunk 达到一定大小时，会用负参数调用 `sbrk` 把内存还给系统。

---

3. trim 是什么？

`trim` 可以理解为：

```plain
把堆顶多余的空闲内存归还给操作系统
```

也就是把：

```plain
[ 程序堆空间 ]
```

变小一点。

过程大概是：

```plain
1. free 释放某块内存
2. 如果这块内存能和 top chunk 合并
3. 合并后 top chunk 足够大
4. malloc 触发 trim
5. 通过 brk/sbrk 收缩堆顶
6. 把一部分内存还给操作系统
```

---

4. 128K 是什么意思？

你说的：

当最高地址空间的空闲内存超过 128K 时，执行内存紧缩操作

这个说法适合作为入门理解。

更严谨地说：

```plain
M_TRIM_THRESHOLD 表示触发堆收缩的阈值。
```

早期/常见资料里，它的默认值通常写作：

```plain
128 * 1024
```

也就是 128KB。

不过现代 glibc 中，`mmap threshold` 和 `trim threshold` 可能会动态调整；如果显式设置了 `M_TRIM_THRESHOLD`、`M_TOP_PAD`、`M_MMAP_THRESHOLD` 或 `M_MMAP_MAX`，动态调整会被关闭。Linux man-pages 对这一点有说明。

所以面试里可以说：

glibc 中可以通过 `mallopt(M_TRIM_THRESHOLD, value)` 调整触发 trim 的阈值，常见默认理解是 128KB，但实际行为还可能受到 glibc 版本和动态阈值机制影响。

5. 举个简单例子

假设程序申请了三块内存：

```plain
A = malloc(100K);
B = malloc(100K);
C = malloc(200K);
```

堆大概是：

```plain
低地址
| A |
| B |
| C |
| top chunk |
高地址
```

如果先释放 B：

```plain
free(B);
```

变成：

```plain
低地址
| A |
| 空闲B |
| C |
| top chunk |
高地址
```

虽然 B 空闲了，但它在中间，不能直接把堆顶往回缩。

所以它通常留在 malloc 的空闲链表里，供以后复用。

---

如果释放 C：

```plain
free(C);
```

此时 C 靠近堆顶，可以和 top chunk 合并：

```plain
低地址
| A |
| 空闲B |
| 更大的 top chunk |
高地址
```

如果这个 top chunk 超过阈值，就可能触发 trim：

```plain
brk 向低地址移动
```

把堆尾一部分内存还给系统。

---

6. 这句话推荐改成这样

你原句可以改得更严谨一点：

```plain
当 free 释放的内存与堆顶 top chunk 相邻时，glibc malloc 会尝试将其与 top chunk 合并。
如果合并后的堆顶空闲空间超过 M_TRIM_THRESHOLD 指定的阈值，
就可能触发 trim 操作，通过 brk/sbrk 收缩堆顶，把一部分空闲内存归还给操作系统。
但如果空闲块位于堆中间，后面仍有已分配块阻挡，则通常不能通过 brk 直接归还给系统，
只能留在 malloc 的空闲链表中等待后续复用。
```

---

7. 一句话总结

```plain
free 不一定把内存立刻还给操作系统；
只有当释放后形成了足够大的堆顶连续空闲空间时，
malloc 才可能通过 trim 收缩 brk，把这部分内存归还给系统。
```

所以你这句话的核心可以记成：

```plain
中间空闲：留给 malloc 以后复用
堆顶空闲：超过阈值后可能 trim 归还系统
```

4、 malloc 是 C 标准库提供的动态内存分配函数，它返回的是进程虚拟地址空间中一块可供程序使用的内存。一般情况下，小块内存通常来自堆区，而较大的内存块可能通过 mmap 在映射区单独分配。malloc 并不是每次都直接向操作系统申请内存，而是先在用户态内存分配器维护的空闲内存块中查找合适的空间。如果找到满足要求的空闲块，就将其切分并返回给程序；如果没有合适的空闲块，malloc 才会通过 brk 或 mmap 向操作系统申请更多虚拟内存。free 释放内存时，通常也是先将内存归还给 malloc 管理的空闲链表，供后续分配复用，而不一定立即归还给操作系统。

## 57、malloc、realloc、calloc的区别
+ malloc函数

```cpp
void* malloc(unsigned int num_size);
int p = malloc(20sizeof(int));申请20个int类型的空间；
```

+ calloc函数

```cpp
void* calloc(size_t n,size_t size);
int *p = calloc(20, sizeof(int));
```

省去了人为空间计算；malloc申请的空间的值是随机初始化的，calloc申请的空间的值是初始化为0的；

+ realloc函数

```cpp
 void realloc(void *p, size_t new_size);
```

给动态分配的空间分配额外的空间，用于扩充容量。

## 58、类成员初始化方式？构造函数的执行顺序 ？为什么用成员初始化列表会快一些？
+ 赋值初始化，通过在函数体内进行赋值初始化；列表初始化，在冒号后使用初始化列表进行初始化。

这两种方式的主要区别在于：

对于在函数体中初始化,是在所有的数据成员被分配内存空间后才进行的。

列表初始化是给数据成员分配内存空间时就进行初始化,就是说分配一个数据成员只要冒号后有此数据成员的赋值表达式(此表达式必须是括号赋值表达式),那么分配了内存空间后在进入函数体之前给数据成员赋值，就是说初始化这个数据成员此时函数体还未执行。

 1. 函数体内赋值初始化  

```cpp
#include <iostream>
using namespace std;

class Student
{
private:
    int age;
    string name;

public:
    Student()
    {
        age = 18;          // 在函数体内赋值
        name = "Jack";     // 在函数体内赋值
        cout << "构造函数体执行" << endl;
    }

    void show()
    {
        cout << name << " " << age << endl;
    }
};

int main()
{
    Student s;
    s.show();

    return 0;
}

1. 先给 age、name 分配空间
2. age 默认初始化，name 先调用 string 的默认构造函数
3. 进入构造函数体
4. 再执行 age = 18; name = "Jack";
```

 2. 初始化列表初始化  

```cpp
#include <iostream>
using namespace std;

class Student
{
private:
    int age;
    string name;

public:
    Student() : age(18), name("Jack")
    {
        cout << "构造函数体执行" << endl;
    }

    void show()
    {
        cout << name << " " << age << endl;
    }
};

int main()
{
    Student s;
    s.show();

    return 0;
}

1. 给 age 分配空间时，直接初始化为 18
2. 给 name 分配空间时，直接初始化为 "Jack"
3. 然后才进入构造函数体
```

+ 一个派生类构造函数的执行顺序如下：

①   虚拟基类的构造函数（多个虚拟基类则按照继承的顺序执行构造函数）。

②   基类的构造函数（多个普通基类也按照继承的顺序执行构造函数）。

③   类类型的成员对象的构造函数（按照成员对象在类中的定义顺序）

④   派生类自己的构造函数。

```cpp
#include <iostream>
using namespace std;

// 虚基类
class VBase
{
public:
    VBase()
    {
        cout << "1. 虚基类 VBase 构造" << endl;
    }
};

// 普通基类 1
class Base1
{
public:
    Base1()
    {
        cout << "2. 普通基类 Base1 构造" << endl;
    }
};

// 普通基类 2
class Base2
{
public:
    Base2()
    {
        cout << "3. 普通基类 Base2 构造" << endl;
    }
};

// 成员对象 1
class Member1
{
public:
    Member1()
    {
        cout << "4. 成员对象 Member1 构造" << endl;
    }
};

// 成员对象 2
class Member2
{
public:
    Member2()
    {
        cout << "5. 成员对象 Member2 构造" << endl;
    }
};

// 派生类
class Derived : virtual public VBase, public Base1, public Base2
{
private:
    Member1 m1;
    Member2 m2;

public:
    Derived()
    {
        cout << "6. 派生类 Derived 自己的构造函数执行" << endl;
    }
};

int main()
{
    Derived d;
    return 0;
}

1. 虚基类 VBase 构造
2. 普通基类 Base1 构造
3. 普通基类 Base2 构造
4. 成员对象 Member1 构造
5. 成员对象 Member2 构造
6. 派生类 Derived 自己的构造函数执行
```

+ 方法一是在构造函数体内对成员变量进行赋值，而方法二是通过构造函数初始化列表对成员变量进行初始化。二者的区别在于：使用构造函数体赋值时，类类型成员会先调用默认构造函数完成初始化，进入构造函数体后再执行赋值操作；而使用初始化列表时，成员变量在创建时就直接完成初始化，避免了先默认构造再赋值的过程。因此，对于类类型成员，初始化列表通常更加高效，尤其是成员对象构造开销较大时更明显。

## 59、有哪些情况必须用到成员列表初始化？作用是什么？
+ 必须使用成员初始化的四种情况

①    当初始化一个引用成员时；

```cpp
#include <iostream>
using namespace std;

class Test
{
private:
    int& ref;   // 引用成员

public:
    Test(int& x) : ref(x)
    {
    }

    void show()
    {
        cout << ref << endl;
    }
};

int main()
{
    int a = 10;
    Test t(a);
    t.show();

    return 0;
}
//不能这样写：
Test(int& x)
{
    ref = x;   // 错误，引用必须在定义时初始化
}
```

②    当初始化一个常量成员时；

```cpp
#include <iostream>
using namespace std;

class Test
{
private:
    const int num;   // 常量成员

public:
    Test(int x) : num(x)
    {
    }

    void show()
    {
        cout << num << endl;
    }
};

int main()
{
    Test t(100);
    t.show();

    return 0;
}

//不能这样写：
Test(int x)
{
    num = x;   // 错误，const 成员不能二次赋值
}
```

③    当调用一个基类的构造函数，而它拥有一组参数时；

```cpp
#include <iostream>
using namespace std;

class Base
{
public:
    Base(int x)
    {
        cout << "Base 构造，x = " << x << endl;
    }
};

class Derived : public Base
{
public:
    Derived(int x) : Base(x)
    {
        cout << "Derived 构造" << endl;
    }
};

int main()
{
    Derived d(10);

    return 0;
}
//因为 Base 没有无参构造函数，所以派生类必须明确告诉编译器如何构造基类部分：
Derived(int x) : Base(x)
{
}
```

④    当调用一个成员类的构造函数，而它拥有一组参数时；

```cpp
#include <iostream>
using namespace std;

class A
{
public:
    A(int x)
    {
        cout << "A 构造，x = " << x << endl;
    }
};

class B
{
private:
    A a;   // 成员对象

public:
    B(int x) : a(x)
    {
        cout << "B 构造" << endl;
    }
};

int main()
{
    B b(20);

    return 0;
}
```

必须使用成员初始化列表的情况主要有四种：

1. 初始化引用成员，因为引用必须在定义时绑定对象；

2. 初始化 const 成员，因为 const 成员只能初始化，不能在函数体内赋值；

3. 初始化没有默认构造函数的基类对象，必须在初始化列表中显式调用基类构造函数；

4. 初始化没有默认构造函数的成员对象，必须在初始化列表中显式调用成员对象的构造函数。

+ 成员初始化列表做了什么

①     成员初始化列表并不是按照书写顺序执行的。编译器会在构造函数体真正执行之前，根据固定的初始化顺序完成基类和成员变量的初始化操作。  

②     对于类中的成员变量，初始化顺序由它们在类中的声明顺序决定，而不是由初始化列表中的书写顺序决定。因此，即使初始化列表中把某个成员写在前面，只要它在类中声明得靠后，也会后初始化。

```cpp
#include <iostream>
using namespace std;

class Test
{
private:
    int a;
    int b;

public:
    Test() : b(20), a(10)
    {
        cout << "构造函数体执行" << endl;
        cout << "a = " << a << endl;
        cout << "b = " << b << endl;
    }
};

int main()
{
    Test t;
    return 0;
}
先初始化 a
再初始化 b
最后执行构造函数体
```

## 60、C++中新增了string，它与C语言中的 char *有什么区别吗？它是如何实现的？
C++ 中的 string 本质上是 std::basic_string<char> 的一个类型别名，它不是继承自 basic_string，而是 basic_string 模板针对 char 类型的实例化。string 对 C 风格字符串进行了封装，内部通常会维护字符数组、字符串长度和容量等信息。

与 char* 相比，char* 只是一个字符指针，需要程序员手动管理内存和字符串结束符 '\0'，容易出现越界、内存泄漏等问题；而 string 是一个类对象，可以自动管理内存，支持赋值、拼接、比较、查找等操作，使用更加安全和方便。

当 string 需要存储更多字符而容量不足时，会自动进行扩容。扩容时通常会重新申请一块更大的内存，将原字符串内容拷贝或移动到新空间中，再释放旧空间。不过扩容倍数由具体标准库实现决定，不一定严格是原来的 2 倍。

1. `char*` 示例

```cpp
#include <iostream>
#include <cstring>
using namespace std;

int main()
{
    char str1[20] = "hello";
    char str2[] = " world";

    // C语言字符串拼接，需要保证 str1 空间足够
    strcat(str1, str2);

    cout << str1 << endl;

    return 0;
}
```

输出：

```cpp
hello world
```

这里要注意：

```cpp
char str1[20] = "hello";
```

必须提前保证空间够大，否则：

```cpp
strcat(str1, str2);
```

可能导致数组越界。

---

2. `string` 示例

```cpp
#include <iostream>
#include <string>
using namespace std;

int main()
{
    string str1 = "hello";
    string str2 = " world";

    // string 可以直接拼接
    str1 += str2;

    cout << str1 << endl;

    return 0;
}
```

输出：

```cpp
hello world
```

`string` 不需要自己手动计算空间大小，它内部会自动管理内存。

---

3. `char*` 和 `string` 的主要区别

```cpp
char* p = "hello";
```

这里的 `p` 本质上只是一个指针，指向一段字符数组。

而：

```cpp
string s = "hello";
```

`string` 是一个类对象，内部封装了字符数组、字符串长度、容量等信息。

可以简单理解为：

```cpp
class string
{
private:
    char* data;      // 指向字符数组
    size_t size;     // 当前字符串长度
    size_t capacity; // 当前容量
};
```

当然，真实的 `std::string` 实现比这个复杂。

---

4. string 自动扩容示例

```cpp
#include <iostream>
#include <string>
using namespace std;

int main()
{
    string s = "abc";

    cout << "初始字符串: " << s << endl;
    cout << "长度 size: " << s.size() << endl;
    cout << "容量 capacity: " << s.capacity() << endl;

    s += "defghijklmnopqrstuvwxyz";

    cout << "扩展后字符串: " << s << endl;
    cout << "长度 size: " << s.size() << endl;
    cout << "容量 capacity: " << s.capacity() << endl;

    return 0;
}
```

可能输出：

```cpp
初始字符串: abc
长度 size: 3
容量 capacity: 15
扩展后字符串: abcdefghijklmnopqrstuvwxyz
长度 size: 26
容量 capacity: 30
```

这里能看到：

```cpp
size()
```

表示字符串实际长度。

```cpp
capacity()
```

表示当前已经申请的容量。

当字符串长度超过当前容量时，`string` 会自动申请更大的空间，然后把原来的内容拷贝过去。
