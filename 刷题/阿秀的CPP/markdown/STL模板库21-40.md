## 21、STL中的allocator、deallocator
+ 第一级配置器直接使用malloc()、free()和relloc()，第二级配置器视情况采用不同的策略：当配置区块超过128bytes时，视之为足够大，便调用第一级配置器；当配置器区块小于128bytes时，为了降低额外负担，使用复杂的内存池整理方式，而不再用一级配置器；
+ 第二级配置器主动将任何小额区块的内存需求量上调至8的倍数，并维护16个free-list，各自管理大小为8~128bytes的小额区块；
+ 空间配置函数allocate()，首先判断区块大小，大于128就直接调用第一级配置器，小于128时就检查对应的free-list。如果free-list之内有可用区块，就直接拿来用，如果没有可用区块，就将区块大小调整至8的倍数，然后调用refill()，为free-list重新分配空间；
+ 空间释放函数deallocate()，该函数首先判断区块大小，大于128bytes时，直接调用一级配置器，小于128bytes就找到对应的free-list然后释放内存。

一级配置器：

```plain
大于 128 bytes
直接 malloc / free
```

二级配置器：

```plain
小于等于 128 bytes
使用内存池 + 16 条 free-list
按 8 字节对齐
提高小块内存分配效率
```

`allocate()`：

```plain
申请内存：
大块走 malloc
小块先查 free-list
没有就 refill()
```

`deallocate()`：

```plain
释放内存：
大块走 free
小块挂回 free-list
```

**refill() 是干什么的？**

`refill()` 的作用是：  
**当某个 free-list 没有可用区块时，批量补充一批内存。**

比如现在需要 24 bytes 的区块，但是 24 bytes 对应的 free-list 空了。

那么 `refill(24)` 可能一次性申请 20 个 24 bytes 的区块：

```plain
24 * 20 = 480 bytes
```

然后：

第 1 个区块返回给当前用户使用；  
剩下 19 个区块挂到 24 bytes 对应的 free-list 上。

这样下次再申请 24 bytes，就不用重新调用 `malloc()` 了。

## 22、STL中hash table扩容发生什么？
+ hash table表格内的元素称为桶（bucket),而由桶所链接的元素称为节点（node),其中存入桶元素的容器为stl本身很重要的一种序列式容器——vector容器。之所以选择vector为存放桶元素的基础容器，主要是因为vector容器本身具有动态扩容能力，无需人工干预。
+  向前操作：首先尝试从目前所指的节点出发，前进一个位置（节点），由于节点被安置于list内，所以利用节点的next指针即可轻易完成前进操作，如果目前正巧是list的尾端，就跳至下一个bucket身上，那正是指向下一个list的头部节点。

1. hash table 的基本结构

STL 里的 `hash table` 可以理解成：

```cpp
vector + 链表
```

也就是：

```cpp
bucket数组 + node链表
```

结构大概是这样：

```plain
buckets
  |
  |-- bucket[0] -> node -> node -> node
  |
  |-- bucket[1] -> nullptr
  |
  |-- bucket[2] -> node -> node
  |
  |-- bucket[3] -> node
```

```plain
vector<node*> buckets;
```

`vector` 里面存的不是元素本身，而是 **链表头指针**。

每一个 `bucket` 指向一条链表。  
真正的数据元素存放在链表节点 `node` 中。

2. bucket 和 node 的区别

你原文这里容易混：

hash table 表格内的元素称为桶 bucket，而由桶所链接的元素称为节点 node

更准确地说：

```plain
bucket：哈希表数组中的一个位置
node：真正存储数据的链表节点
```

例如：

```plain
bucket[2] -> node(10) -> node(18) -> node(26)
```

这里：

```plain
bucket[2] 是桶
node(10)、node(18)、node(26) 是节点
```

这些节点之所以挂在同一个 bucket 后面，是因为它们经过哈希函数计算后，落到了同一个位置。

3. 为什么 bucket 用 vector 存？

因为 bucket 本质上是一个数组。

需要支持：

```plain
下标访问
动态扩容
连续空间
```

所以用 `vector` 很合适。

例如：

```plain
vector<node*> buckets;
```

访问第 `i` 个桶：

```plain
buckets[i]
```

扩容时可以重新创建更大的 bucket 数组，然后重新分配节点位置。

不过要注意：  
**vector 的扩容能力不代表 hash table 可以自动完成合理 rehash。**

hash table 扩容时不是简单地让 vector 变大，而是要把所有旧节点重新计算哈希位置，再放到新桶中。

4. hash table 什么时候扩容？

当元素越来越多，bucket 不够用时，就需要扩容。

一般和 **负载因子 load factor** 有关：

```plain
load factor = 元素个数 / bucket数量
```

例如：

```plain
元素个数 = 100
bucket数量 = 50
load factor = 2
```

负载因子越高，说明平均每个桶后面的链表越长，查找效率会下降。

所以当负载因子超过某个阈值时，会触发扩容，也叫：

```plain
rehash
```

5. hash table 扩容发生什么？

扩容不是简单地扩大 `vector`，而是要重新哈希。

```plain
1. 创建一个更大的 bucket 数组
2. 遍历旧 bucket 中的所有 node
3. 对每个 node 的 key 重新计算 hash 值
4. 根据新的 bucket 数量，计算新的下标
5. 把 node 挂到新的 bucket 链表中
6. 替换旧的 bucket 数组
```

假设原来有 5 个 bucket：

```plain
bucket_count = 5
```

某个 key 的位置是：

```plain
index = hash(key) % 5;
```

扩容后变成 11 个 bucket：

```plain
bucket_count = 11
```

那么它的新位置就变成：

```plain
index = hash(key) % 11;
```

因为取模的数字变了，所以元素位置大概率会改变。

6. 举个例子

假设有这些数字：

```plain
3, 8, 13, 18
```

原来 bucket 数量是 5。

计算位置：

```plain
3  % 5 = 3
8  % 5 = 3
13 % 5 = 3
18 % 5 = 3
```

所以它们都在 `bucket[3]`：

```plain
bucket[3] -> 3 -> 8 -> 13 -> 18
```

现在扩容到 11 个 bucket。

重新计算：

```plain
3  % 11 = 3
8  % 11 = 8
13 % 11 = 2
18 % 11 = 7
```

扩容后变成：

```plain
bucket[2] -> 13
bucket[3] -> 3
bucket[7] -> 18
bucket[8] -> 8
```

所以扩容后，节点会被重新分散，链表变短，查找效率提高。

7. 扩容会导致什么影响？

hash table 扩容后：

```plain
元素本身还在
但是 bucket 位置会变
迭代器通常会失效
```

因为 rehash 会重新组织节点所在的桶。

对于 `unordered_map`、`unordered_set` 这类基于 hash table 的容器来说，扩容可能导致迭代器失效。

```cpp
unordered_map<int, string> mp;

mp[1] = "A";
auto it = mp.find(1);

mp[2] = "B";
mp[3] = "C";
// 如果插入过程中触发 rehash，it 可能失效
```

所以不要在插入大量元素并可能触发扩容后，继续使用旧迭代器。

8. “向前操作”是什么意思？

你这段：

向前操作：首先尝试从目前所指的节点出发，前进一个位置，由于节点被安置于 list 内，所以利用节点的 next 指针即可轻易完成前进操作，如果目前正巧是 list 的尾端，就跳至下一个 bucket 身上，那正是指向下一个 list 的头部节点。

这讲的是 **hash table 迭代器的 **`**operator++**`。

也就是：

```cpp
++it;
```

hash table 的迭代器前进逻辑是：

```plain
1. 先看当前 node 有没有 next
2. 如果有 next，就移动到 next 节点
3. 如果没有 next，说明当前 bucket 的链表走完了
4. 那就去后面的 bucket 中找下一个非空 bucket
5. 找到后，指向那个 bucket 的第一个 node
```

9. 迭代器前进示例

假设 hash table 是这样：

```plain
bucket[0] -> nullptr

bucket[1] -> A -> B -> C

bucket[2] -> nullptr

bucket[3] -> D -> E

bucket[4] -> F
```

遍历顺序大概是：

```plain
A -> B -> C -> D -> E -> F
```

当迭代器在 `A`：

```plain
A 有 next，所以 ++it 到 B
```

当迭代器在 `B`：

```plain
B 有 next，所以 ++it 到 C
```

当迭代器在 `C`：

```plain
C 没有 next，说明 bucket[1] 结束
于是继续找 bucket[2]，空
再找 bucket[3]，非空
所以跳到 D
```

当迭代器在 `E`：

```plain
E 没有 next
继续找 bucket[4]
跳到 F
```

10. 面试回答版

可以这样说：

STL 中 hash table 底层通常采用 **bucket 数组加链表** 的结构。bucket 数组一般用 `vector` 维护，每个 bucket 保存一条链表的头指针，真正的数据存放在链表节点 node 中。当元素数量增加导致负载因子过高时，hash table 会发生扩容，也就是 rehash。扩容时会创建一个更大的 bucket 数组，然后遍历原来的所有节点，根据新的 bucket 数量重新计算哈希位置，并把节点挂到新的 bucket 上。由于元素所在桶的位置可能发生变化，所以 rehash 可能导致迭代器失效。

hash table 的迭代器前进时，首先沿着当前 bucket 后面的链表移动。如果当前节点还有 next 指针，就直接移动到下一个节点；如果当前链表已经到尾部，就继续向后寻找下一个非空 bucket，并指向该 bucket 链表的头节点。这样就可以完成整个 hash table 的遍历。

## 23、常见容器性质总结？
1.vector    底层数据结构为数组 ，支持快速随机访问

```cpp
支持快速随机访问
尾部插入删除较快
中间插入删除较慢
扩容时可能整体搬移元素
```

```cpp
vector<int> v = {1, 2, 3};

cout << v[1];     // 快速随机访问
v.push_back(4);   // 尾部插入较快
```

2.list       底层数据结构为双向链表，支持快速增删

```cpp
不支持随机访问
任意位置插入删除较快
每个节点额外保存前驱和后继指针
```

```cpp
list<int> lst = {1, 2, 3};

auto it = lst.begin();
++it;
lst.insert(it, 100);
```

3.deque    底层数据结构为一个中央控制器和多个缓冲区，详细见STL源码剖析P146，支持首尾（中间不能）快速增删，也支持随机访问

deque是一个双端队列(double-ended queue)，也是在堆中保存内容的.它的保存形式如下:

[堆1] --> [堆2] -->[堆3] --> ...

每个堆保存好几个元素,然后堆和堆之间有指针指向,看起来像是list和vector的结合品.

`deque` 是 **双端队列**，底层不是简单数组，也不是普通链表。

它通常由：

```plain
中央控制器 map + 多个缓冲区 buffer
```

可以简单理解成：

```plain
map
 |
 |-- buffer1: [1 2 3 4]
 |-- buffer2: [5 6 7 8]
 |-- buffer3: [9 10 11 12]

 这里的 map 不是 std::map，而是一个控制缓冲区地址的指针数组。
```

```cpp
支持随机访问
支持头部和尾部快速插入删除
中间插入删除效率较低
内存不是完全连续的
```

```cpp
deque<int> dq;

dq.push_back(1);
dq.push_front(0);

cout << dq[1];
```

4.stack    底层一般用list或deque实现，封闭头部即可，不用vector的原因应该是容量大小有限制，扩容耗时

```plain
后进先出 LIFO
只允许在栈顶操作
```

```cpp
stack<int> st;

st.push(1);
st.push(2);

cout << st.top();  // 2
st.pop();
```

`stack` 其实可以用 `vector` 作为底层容器：

```cpp
stack<int, vector<int>> st;
```

只要底层容器支持：

```cpp
back()
push_back()
pop_back()
```

就可以作为 `stack` 的底层容器。

默认用 `deque`，主要是因为 `deque` 两端扩展方便，扩容时不需要像 `vector` 那样整体搬移大量元素。

5.queue   底层一般用list或deque实现，封闭头部即可，不用vector的原因应该是容量大小有限制，扩容耗时（stack和queue其实是适配器,而不叫容器，因为是对容器的再封装）

```cpp
先进先出 FIFO
队尾插入
队头删除
```

```cpp
queue<int> q;

q.push(1);
q.push(2);

cout << q.front();  // 1
q.pop();
```

它要求底层容器支持：

```cpp
front()
back()
push_back()
pop_front()
```

所以 `vector` 一般不能作为 `queue` 的默认底层容器，因为 `vector` 没有高效的 `pop_front()`。

这里和 `stack` 不一样：

```cpp
stack<int, vector<int>> st;  // 可以
queue<int, vector<int>> q;   // 通常不行
```

6.priority_queue   的底层数据结构一般为vector为底层容器，堆heap为处理规则来管理底层容器实现

```cpp
每次取出的都是优先级最高的元素
默认最大元素优先
底层通常是 vector
使用堆算法维护顺序
```

```cpp
priority_queue<int> pq;

pq.push(3);
pq.push(1);
pq.push(5);

cout << pq.top();  // 5
```

底层默认使用：

```plain
vector + heap
vector 负责存储数据
heap 负责维护优先级顺序
```

7.set          底层数据结构为红黑树，有序，不重复

```plain
有序
元素不可重复
自动排序
查找、插入、删除复杂度 O(log n)
```

```cpp
set<int> s;

s.insert(3);
s.insert(1);
s.insert(3);

for (int x : s)

    cout << x << " ";

```

8.multiset      底层数据结构为红黑树，有序，可重复

```plain
有序
元素可以重复
```

```cpp

ms.insert(3);
ms.insert(1);
ms.insert(3);
```

里面可以有两个 `3`。

9.map         底层数据结构为红黑树，有序，不重复

```cpp
按 key 有序
key 不可重复
存储 key-value 键值对
查找、插入、删除复杂度 O(log n)
```

```cpp
map<int, string> mp;

```

`map` 中每个元素本质上是：


```plain
不能直接用 [] 访问
```

```cpp
mmp.insert({1, "B"});
```

可以保存重复元素。

## 24、vector的增加删除都是怎么做的？为什么是1.5或者是2倍？
1. 新增元素：vector通过一个连续的数组存放元素，如果集合已满，在新增数据的时候，就要分配一块更大的内存，将原来的数据复制过来，释放之前的内存，在插入新增的元素；
2.  对vector的任何操作，一旦引起空间重新配置，指向原vector的所有迭代器就都失效了 ；
3.  初始时刻vector的capacity为0，塞入第一个元素后capacity增加为1；
4.  不同的编译器实现的扩容方式不一样，VS2015中以1.5倍扩容，GCC以2倍扩容。
5. 对比可以发现采用成倍方式扩容，可以保证常数的时间复杂度，而增加指定大小的容量只能达到O(n)的时间复杂度，因此，使用成倍的方式扩容。
6. 考虑可能产生的堆空间浪费，成倍增长倍数不能太大，使用较为广泛的扩容方式有两种，以2二倍的方式扩容，或者以1.5倍的方式扩容。
7. 以2倍的方式扩容，导致下一次申请的内存必然大于之前分配内存的总和，导致之前分配的内存不能再被使用，所以最好倍增长因子设置为(1,2)之间：
8. 向量容器vector的成员函数pop_back()可以删除最后一个元素.
9. 而函数erase()可以删除由一个iterator指出的元素，也可以删除一个指定范围的元素。
10. 还可以采用通用算法remove()来删除vector容器中的元素.
11. 不同的是：采用remove一般情况下不会改变容器的大小，而pop_back()与erase()等成员函数会改变容器的大小。

1. vector 新增元素怎么做？

`vector` 底层是一段**连续数组空间**。

如果当前容量还够，例如：

```cpp
size < capacity
```

那么 `push_back()` 直接把新元素放到末尾即可，时间复杂度是 **O(1)**。

例如：

```cpp
vector<int> v;
v.reserve(4);

v.push_back(1);
v.push_back(2);
v.push_back(3);
```

此时只是在已有空间后面继续放元素。

如果容量不够，例如：

```cpp
size == capacity
```

再插入新元素时，`vector` 就必须扩容。

扩容大致过程是：

```plain
1. 申请一块更大的连续内存
2. 把原来的元素拷贝或移动到新内存
3. 释放旧内存
4. 把新元素插入进去
```

```cpp
vector<int> v;

v.push_back(1); // capacity 可能变成 1
v.push_back(2); // 空间不够，扩容
v.push_back(3); // 空间不够，继续扩容
```

因为扩容后内存地址变了，所以：

```plain
一旦 vector 发生重新分配，原来的迭代器、指针、引用都会失效。
```

```cpp

cout << *it << endl; // 危险
```

2. vector 删除元素怎么做？

`vector` 删除元素分几种情况。

① 删除末尾元素：pop_back()

```cpp
v.pop_back();
```

它只删除最后一个元素，通常不会移动其他元素，效率很高，时间复杂度是 **O(1)**。

```cpp
vector<int> v = {1, 2, 3, 4};

v.pop_back(); // 变成 {1, 2, 3}
```

② 删除中间元素：erase()

```cpp
v.erase(v.begin() + 1);
```

```cpp
vector<int> v = {1, 2, 3, 4};

v.erase(v.begin() + 1);
```

删除元素 `2` 后，后面的元素要往前移动：

```plain
原来：1 2 3 4
删除：  2
移动：1 3 4
```

所以删除中间元素的时间复杂度一般是 **O(n)**。

删除一段范围也可以：

```cpp
v.erase(v.begin() + 1, v.begin() + 3);
```

③ remove 并不真正删除元素

很多人容易搞混：

```cpp
remove(v.begin(), v.end(), 3);
```

`remove()` 是算法，不是 vector 的成员函数。它只会把不需要删除的元素往前挪，并返回新的逻辑结尾，但**不会改变 vector 的 size**。

所以真正删除通常要写成：

```cpp
v.erase(remove(v.begin(), v.end(), 3), v.end());
```

完整例子：

```cpp
vector<int> v = {1, 3, 2, 3, 4};

v.erase(remove(v.begin(), v.end(), 3), v.end());

// 结果：{1, 2, 4}
```

```cpp
原始 vector
vector<int> v = {1, 3, 2, 3, 4};
remove(v.begin(), v.end(), 3)
把所有不等于 3 的元素往前移动，把等于 3 的元素“挤到后面”。
也就是说，它不会真正删除元素，也不会改变 vector 的 size()。
执行完：
remove(v.begin(), v.end(), 3)
1  2  4  ?  ?后面两个位置是什么值不重要，可能还是旧值。
remove 会返回一个迭代器，指向新的“逻辑结尾”。
1  2  4  ?  ?
         ↑
       remove 返回的位置
```

这个叫做 **erase-remove 惯用法**。

3. 为什么 vector 要按 1.5 倍或 2 倍扩容？

假设每次容量不够时，只增加 1 个空间。

例如插入 10000 个元素，就可能要扩容很多次：

```plain
1 -> 2 -> 3 -> 4 -> 5 -> ... -> 10000
```

每次扩容都要重新申请内存，并搬移旧元素，这样总代价很高，整体插入复杂度会接近 **O(n²)**。

所以 vector 通常采用**成倍扩容**：

```plain
1 -> 2 -> 4 -> 8 -> 16 -> 32 ...
```

或者：

```plain
1 -> 2 -> 3 -> 4 -> 6 -> 9 -> 13 ...
```

这样扩容次数大大减少，虽然某一次 `push_back()` 可能因为扩容是 **O(n)**，但是平均下来，每次插入的均摊复杂度仍然是 **O(1)**。

4. 为什么不是无限大倍数扩容？

扩容倍数太小，会导致扩容太频繁。

扩容倍数太大，又会浪费内存。

例如原来容量是 1000，如果按 2 倍扩容：

```plain
1000 -> 2000
```

可能会多出很多暂时用不到的空间。

如果按 1.5 倍扩容：

```plain
1000 -> 1500
```

内存浪费相对少一些，但扩容次数会比 2 倍略多。

所以不同 STL 实现会选择不同策略：

```plain
GCC 的 libstdc++ 常见是 2 倍扩容；
MSVC 常见是 1.5 倍扩容。
```

它们的目的都是在：

减少扩容次数和减少内存浪费之间做平衡。

## 26、STL中迭代器失效的情况有哪些？
以vector为例：

**插入元素：**

1、尾后插入：size < capacity时，首迭代器不失效尾迭代失效（未重新分配空间），size == capacity时，所有迭代器均失效（需要重新分配空间）。

2、中间插入：中间插入：size < capacity时，首迭代器不失效但插入元素之后所有迭代器失效，size == capacity时，所有迭代器均失效。

**删除元素：**

尾后删除：只有尾迭代失效。

中间删除：删除位置之后所有迭代失效。

deque 和 vector 的情况类似,

而list双向链表每一个节点内存不连续, 删除节点仅当前迭代器失效,erase返回下一个有效迭代器;

map/set等关联容器底层是红黑树删除节点不会影响其他节点的迭代器, 使用递增方法获取下一个迭代器 mmp.erase(iter++);

unordered_(hash) 迭代器意义不大, rehash之后, 迭代器应该也是全部失效.

示例

**vector 尾部插入**

```cpp
vector<int> v;
v.reserve(4);
v.push_back(1);
v.push_back(2);

auto it = v.begin();
auto end_it = v.end();

v.push_back(3);
```

因为提前 `reserve(4)`，所以没有扩容。

```cpp
it      // 仍然有效
end_it  // 失效
```

原因是：`end()` 表示尾后位置，插入新元素后，尾后位置变了。

**vector 尾部插入导致扩容**

```cpp
vector<int> v = {1, 2, 3};

auto it = v.begin();

v.push_back(4); // 如果触发扩容
```

如果 `size == capacity`，插入时会重新申请更大的内存。

```plain
it // 失效
```

因为原来的整块内存都被释放了，所以**所有迭代器、指针、引用都失效**。

**vector 中间插入，未扩容**

```cpp
vector<int> v;
v.reserve(5);
v.push_back(1);
v.push_back(2);
v.push_back(4);

auto it1 = v.begin();      // 指向 1
auto it2 = v.begin() + 1;  // 指向 2
auto it3 = v.begin() + 2;  // 指向 4

v.insert(v.begin() + 2, 3);
```

插入后：

```cpp
1 2 3 4
```

此时：

```cpp
it1 // 有效
it2 // 有效
it3 // 失效
```

原因是：插入位置及其后面的元素发生了移动。

```cpp
插入点之前的迭代器有效；
插入点及之后的迭代器失效。
```

**vector 中间插入，发生扩容**

```cpp
vector<int> v = {1, 2, 4};

auto it = v.begin();

v.insert(v.begin() + 2, 3); // 如果触发扩容
```

如果空间不够，需要重新分配内存。

此时：

```plain
所有迭代器全部失效
```

**vector 删除元素**

```cpp
vector<int> v = {1, 2, 3, 4, 5};

auto it1 = v.begin();      // 指向 1
auto it2 = v.begin() + 2;  // 指向 3
auto it3 = v.begin() + 4;  // 指向 5

v.erase(v.begin() + 2);
```

删除 `3` 后：

```plain
1 2 4 5
```

此时：

```plain
it1 // 有效
it2 // 失效
it3 // 失效
```

原因是：删除位置及其后面的元素都要往前移动。

所以：

```plain
删除点之前的迭代器有效；
删除点及之后的迭代器失效。
```

## 27、STL中vector的实现
vector是一种序列式容器，其数据安排以及操作方式与array非常类似，两者的唯一差别就是对于空间运用的灵活性。

众所周知，array占用的是静态空间，一旦配置了就不可以改变大小，如果遇到空间不足的情况还要自行创建更大的空间，并手动将数据拷贝到新的空间中，再把原来的空间释放。

vector则使用灵活的动态空间配置，维护一块**连续的线性空间**，在空间不足时，可以自动扩展空间容纳新元素，做到按需供给。

其在扩充空间的过程中仍然需要经历：**重新配置空间，移动数据，释放原空间**等操作。这里需要说明一下动态扩容的规则：以原大小的两倍配置另外一块较大的空间（或者旧长度+新增元素的个数），源码：

```cpp
 const size_type len  = old_size + max(old_size, n);
```

Vector扩容倍数与平台有关，在Win +  VS 下是 1.5倍，在 Linux + GCC 下是 2 倍

测试代码：

```cpp
#include  #include  using namespace std;
int main()
{
    //在Linux + GCC下
    vector res(2,0);    
    cout << res.capacity() <<endl; //2     
    res.push_back(1);     
    cout << res.capacity() <<endl;//4     
    res.push_back(2);     
    res.push_back(3);     
    cout << res.capacity() <<endl;//8     
    return 0;

    //在 win 10 + VS2019下
    vector<int> res(2,0);
    cout << res.capacity() <<endl; //2
    res.push_back(1);
    cout << res.capacity() <<endl;//3
    res.push_back(2);
    res.push_back(3);
    cout << res.capacity() <<endl;//6
     
}
```

运行上述代码，一开始配置了一块长度为2的空间，接下来插入一个数据，长度变为原来的两倍，为4，此时已占用的长度为3，再继续两个数据，此时长度变为8，可以清晰的看到空间的变化过程

需要注意的是，频繁对vector调用push_back()对性能是有影响的，这是因为每插入一个元素，如果空间够用的话还能直接插入，若空间不够用，则需要重新配置空间，移动数据，释放原空间等操作，对程序性能会造成一定的影响

## 28、STL中slist的实现
list是双向链表，而slist（single linked list）是单向链表，它们的主要区别在于：前者的迭代器是双向的Bidirectional iterator，后者的迭代器属于单向的Forward iterator。虽然slist的很多功能不如list灵活，但是其所耗用的空间更小，操作更快。

根据STL的习惯，插入操作会将新元素插入到指定位置之前，而非之后，然而slist是不能回头的，只能往后走，因此在slist的其他位置插入或者移除元素是十分不明智的，但是在slist开头却是可取的，slist特别提供了insert_after()和erase_after供灵活应用。考虑到效率问题，slist只提供push_front()操作，元素插入到slist后，存储的次序和输入的次序是相反的。

这句话的核心意思是：**slist/forward_list 是单向链表，只能从前往后走，不能从后往前走，所以它不适合在任意位置做“前插”和“删除当前元素”。**

`slist` 可以理解成现在 C++ 标准库里的：

```cpp
forward_list
```

它的底层大概是这样：

```plain
head -> 1 -> 2 -> 3 -> 4 -> nullptr
```

每个节点只知道自己的**下一个节点**，不知道自己的**上一个节点**。

所以它只能这样走：

```plain
1 -> 2 -> 3 -> 4
```

不能这样走：

```plain
4 -> 3 -> 2 -> 1
```

1. 为什么“不能回头，只能往后走”？

因为单向链表节点里只有一个 `next` 指针。

比如节点 `2`：

```plain
1 -> 2 -> 3
```

节点 `2` 只知道：

```plain
2 的下一个是 3
```

但它不知道：

```plain
2 的上一个是 1
```

所以如果你手里只有指向 `2` 的迭代器，你很难快速找到它前面的节点 `1`。

2. 为什么普通 insert 不方便？

STL 习惯中，`insert(pos, value)` 的意思是：

```plain
把 value 插入到 pos 指向位置的前面
```

```cpp
vector<int> v = {1, 2, 4};

v.insert(v.begin() + 2, 3);
```

结果是：

```plain
1 2 3 4
```

也就是说，`3` 插入到了 `4` 前面。

但是对于 `slist / forward_list`，如果你想把 `3` 插入到 `4` 前面：

```plain
1 -> 2 -> 4
```

你必须找到 `4` 前面的节点 `2`，然后修改 `2` 的 `next` 指针：

```plain
1 -> 2 -> 3 -> 4
```

问题是：单向链表从 `4` 不能往回找到 `2`。

所以如果只给你一个指向 `4` 的迭代器，想在 `4` 前面插入元素就很麻烦。

3. 为什么提供 insert_after？

所以 `slist / forward_list` 不提供普通的 `insert(pos, value)`，而是提供：

```cpp
insert_after(pos, value)
```

意思是：

```plain
把新元素插入到 pos 后面
```

```cpp
#include <iostream>
#include <forward_list>
using namespace std;

int main() {
    forward_list<int> fl = {1, 2, 4};

    auto it = fl.begin(); // 指向 1
    ++it;                // 指向 2

    fl.insert_after(it, 3); // 在 2 后面插入 3

    for (int x : fl) {
        cout << x << " ";
    }

    return 0;
}
```

输出：

```plain
1 2 3 4
```

这里为什么方便？

因为你手里有 `2` 的迭代器，`2` 知道自己的下一个是 `4`，所以直接把 `3` 接到 `2` 后面即可。

4. 为什么提供 erase_after？

同理，`erase_after(pos)` 的意思是：

```plain
删除 pos 后面的那个元素
```

例如：

```cpp
forward_list<int> fl = {1, 2, 3, 4};

auto it = fl.begin(); // 指向 1
++it;                // 指向 2

fl.erase_after(it);  // 删除 2 后面的元素，也就是 3
```

结果：

```plain
1 2 4
```

为什么不能方便地删除当前节点？

因为删除一个节点时，需要修改它前一个节点的 `next` 指针。

比如删除 `3`：

```plain
1 -> 2 -> 3 -> 4
```

需要让 `2` 指向 `4`：

```plain
1 -> 2 -> 4
```

所以你必须知道 `3` 的前一个节点是 `2`。

单向链表如果只给你 `3`，没法直接回头找到 `2`。

所以它提供的是：

```plain
erase_after(it)
```

让你删除 `it` 后面的节点。

5. 为什么在开头插入是可取的？

因为单向链表在头部插入非常快。

比如原来：

```plain
head -> 1 -> 2 -> 3
```

执行：

```plain
push_front(0);
```

只需要让新节点 `0` 指向原来的头节点 `1`：

```plain
head -> 0 -> 1 -> 2 -> 3
```

不需要找前驱节点，时间复杂度是 **O(1)**。

所以 `slist / forward_list` 特别适合：

```plain
push_front()
```

6. 为什么插入后顺序和输入顺序相反？

因为它只有 `push_front()`，每次都插到最前面。

例如你依次插入：

```cpp
push_front(1);
push_front(2);
push_front(3);
```

过程是：

```cpp
插入 1：1
插入 2：2 -> 1
插入 3：3 -> 2 -> 1
```

所以最终顺序是：

```plain
3 2 1
```

和输入顺序：

```plain
1 2 3
```

是相反的。

## 29、STL中list的实现
相比于vector的连续线型空间，list显得复杂许多，但是它的好处在于插入或删除都只作用于一个元素空间，因此list对空间的运用是十分精准的，对任何位置元素的插入和删除都是常数时间。list不能保证节点在存储空间中连续存储，也拥有迭代器，迭代器的“++”、“--”操作对于的是指针的操作，list提供的迭代器类型是双向迭代器：Bidirectional iterators。

list节点的结构见如下源码：

```cpp
template <class T>
struct __list_node {
    typedef void* void_pointer;
    void_pointer prev;  // 指向前一个节点
    void_pointer next;  // 指向后一个节点
    T data;             // 当前节点保存的数据
};
```

从源码可看出list显然是一个双向链表。list与vector的另一个区别是，在插入和接合操作之后，都不会造成原迭代器失效，而vector可能因为空间重新配置导致迭代器失效。

```cpp
       ┌──────────────────────┐
       ↓                      │
dummy <-> node1 <-> node2 <-> node3
  ↑                            ↓
  └────────────────────────────┘
这个 dummy 节点不存放真实数据。
它的作用是让 begin() 和 end() 的处理更统一。
[begin, end)包含 begin 指向的元素
不包含 end 指向的空白节点
```

此外list也是一个环形链表，因此只要一个指针便能完整表现整个链表。list中node节点指针始终指向尾端的一个空白节点，因此是一种“前闭后开”的区间结构

list的空间管理默认采用alloc作为空间配置器，为了方便的以节点大小为配置单位，还定义一个list_node_allocator 函数可一次性配置多个节点空间

由于list的双向特性，其支持在头部（front)和尾部（back)两个方向进行push和pop操作，当然还支持erase，splice(`splice` 可以把一个链表中的节点直接接到另一个链表中。  )，sort，merge，reverse，sort等操作，这里不再详细阐述。

## 30、STL中的deque的实现
vector是单向开口（尾部）的连续线性空间，deque则是一种双向开口的连续线性空间，虽然vector也可以在头尾进行元素操作，但是其头部操作的效率十分低下（主要是涉及到整体的移动）

<!-- 这是一张图片，ocr 内容为： -->
![](https://cdn.nlark.com/yuque/0/2026/png/57223890/1779237460409-3fc02338-af8d-4d61-8f91-c6b48f671f5c.png)

deque和vector的最大差异一个是deque运行在常数时间内对头端进行元素操作，二是deque没有容量的概念，它是动态地以分段连续空间组合而成，可以随时增加一段新的空间并链接起来

deque虽然也提供随机访问的迭代器，但是其迭代器并不是普通的指针，其复杂程度比vector高很多，因此除非必要，否则一般使用vector而非deque。如果需要对deque排序，可以先将deque中的元素复制到vector中，利用sort对vector排序，再将结果复制回deque

deque由一段一段的定量连续空间组成，一旦需要增加新的空间，只要配置一段定量连续空间拼接在头部或尾部即可，因此deque的最大任务是如何维护这个整体的连续性

deque的数据结构如下：

```cpp
class deque

    iterator end();
    ...
}
```

## 31、STL中stack和queue的实现
**stack**

stack（栈）是一种先进后出（First In Last Out）的数据结构，只有一个入口和出口，那就是栈顶，除了获取栈顶元素外，没有其他方法可以获取到内部的其他元素，其结构图如下：

<!-- 这是一张图片，ocr 内容为： -->
![](/assets/img/202205220021348.436cb6cf.png)<!-- 这是一张图片，ocr 内容为： -->
![](https://cdn.nlark.com/yuque/0/2026/png/57223890/1779238300263-48c2af5f-1f9b-490e-8c08-9eb37d78cb87.png)

stack这种单向开口的数据结构很容易由**双向开口的deque和list**形成，只需要根据stack的性质对应移除某些接口即可实现，stack的源码如下：

```cpp
template <class T, class Sequence = deque<T>>
class stack
{
protected:
    Sequence c;  // 底层容器

public:
    bool empty() const { return c.empty(); }
    size_t size() const { return c.size(); }

    T& top() { return c.back(); }
    const T& top() const { return c.back(); }

    void push(const T& x) { c.push_back(x); }
    void pop() { c.pop_back(); }
};
```

从stack的数据结构可以看出，其所有操作都是围绕Sequence完成，而Sequence默认是deque数据结构。stack这种“修改某种接口，形成另一种风貌”的行为，成为adapter(配接器)。常将其归类为container adapter而非container

stack除了默认使用deque作为其底层容器之外，也可以使用双向开口的list，只需要在初始化stack时，将list作为第二个参数即可。由于stack只能操作顶端的元素，因此其内部元素无法被访问，也不提供迭代器。

**queue**

queue（队列）是一种先进先出（First In First Out）的数据结构，只有一个入口和一个出口，分别位于最底端和最顶端，出口元素外，没有其他方法可以获取到内部的其他元素，其结构图如下：

<!-- 这是一张图片，ocr 内容为： -->
![](/assets/img/202205220021436.6bd7acf3.png)<!-- 这是一张图片，ocr 内容为： -->
![](https://cdn.nlark.com/yuque/0/2026/png/57223890/1779239093435-6f1e65bf-54ca-405a-8897-c43db1ad437e.png)

类似的，queue这种“先进先出”的数据结构很容易由双向开口的deque和list形成，只需要根据queue的性质对应移除某些接口即可实现，queue的源码如下：

```cpp
template <class T, class Sequence = deque<T>>
class queue
{
protected:
    Sequence c;   // 底层容器，默认使用 deque<T>

public:
    typedef typename Sequence::value_type value_type;
    typedef typename Sequence::size_type size_type;
    typedef typename Sequence::reference reference;
    typedef typename Sequence::const_reference const_reference;

    bool empty() const
    {
        return c.empty();
    }

    size_type size() const
    {
        return c.size();
    }

    reference front()
    {
        return c.front();
    }

    const_reference front() const
    {
        return c.front();
    }

    reference back()
    {
        return c.back();
    }

    const_reference back() const
    {
        return c.back();
    }

    void push(const value_type& x)
    {
        c.push_back(x);
    }

    void pop()
    {
        c.pop_front();
    }
};
```

从queue的数据结构可以看出，其所有操作都也都是是围绕Sequence完成，Sequence默认也是deque数据结构。queue也是一类container adapter。

同样，queue也可以使用list作为底层容器，不具有遍历功能，没有迭代器。

| 适配器 | 入元素 | 出元素 | 访问元素 | 特点 |
| --- | --- | --- | --- | --- |
| `stack` | `push_back()` | `pop_back()` | `back()` | 后进先出 |
| `queue` | `push_back()` | `pop_front()` | `front()` | 先进先出 |


## 32、STL中的heap的实现
heap（堆）并不是STL的容器组件，是priority queue（优先队列）的底层实现机制，因为binary max heap（大根堆）总是最大值位于堆的根部，优先级最高。

binary heap本质是一种complete binary tree（完全二叉树），整棵binary tree除了最底层的叶节点之外，都是填满的，但是叶节点从左到右不会出现空隙，如下图所示就是一颗完全二叉树

<!-- 这是一张图片，ocr 内容为： -->
![](/assets/img/202205220021792.efdc9985.png)<!-- 这是一张图片，ocr 内容为： -->
![](https://cdn.nlark.com/yuque/0/2026/png/57223890/1779239382967-d47aa8d4-bef9-4bfb-81ba-34bcf3133236.png)

完全二叉树内没有任何节点漏洞，是非常紧凑的，这样的一个好处是可以使用array来存储所有的节点，因为当其中某个节点位于$ i $处，其左节点必定位于$ 2i $处，右节点位于$ 2i+1 $处，父节点位于$ i/2 $（向下取整）处。这种以array表示tree的方式称为隐式表述法。

因此我们可以使用一个array和一组heap算法来实现max heap（每个节点的值大于等于其子节点的值）和min heap（每个节点的值小于等于其子节点的值）。由于array不能动态的改变空间大小，用vector代替array是一个不错的选择。

那heap算法有哪些？常见有的插入、弹出、排序和构造算法，下面一一进行描述。

**push_heap插入算法**

由于完全二叉树的性质，新插入的元素一定是位于树的最底层作为叶子节点，并填补由左至右的第一个空格。

事实上，在刚执行插入操作时，新元素位于底层vector的end()处，之后是一个称为percolate up（上溯）的过程，举个例子如下图：

<!-- 这是一张图片，ocr 内容为： -->
![](/assets/img/202205220022842.2864f2a2.png)<!-- 这是一张图片，ocr 内容为： -->
![](https://cdn.nlark.com/yuque/0/2026/png/57223890/1779239428964-2df463c1-3719-4686-bb56-6604ff785c76.png)

新元素50在插入堆中后，先放在vector的end()存着，之后执行上溯过程，调整其根结点的位置，以便满足max heap的性质，如果了解大根堆的话，这个原理跟大根堆的调整过程是一样的。

**pop_heap算法**

heap的pop操作实际弹出的是根节点吗，但在heap内部执行pop_heap时，只是将其移动到vector的最后位置，然后再为这个被挤走的元素找到一个合适的安放位置，使整颗树满足完全二叉树的条件。

这个被挤掉的元素首先会与根结点的两个子节点比较，并与较大的子节点更换位置，如此一直往下，直到这个被挤掉的元素大于左右两个子节点，或者下放到叶节点为止，这个过程称为percolate down（下溯）。

举个例子：

<!-- 这是一张图片，ocr 内容为： -->
![](/assets/img/202205220022993.7cf3cf64.png)<!-- 这是一张图片，ocr 内容为： -->
![](https://cdn.nlark.com/yuque/0/2026/png/57223890/1779239442187-655f1826-5253-4fc6-be01-9c88ccb45001.png)

根节点68被pop之后，移到了vector的最底部，将24挤出，24被迫从根节点开始与其子节点进行比较，直到找到合适的位置安身，需要注意的是pop之后元素并没有被移走，如果要将其移走，可以使用pop_back()。

**sort算法**

一言以蔽之，因为pop_heap可以将当前heap中的最大值置于底层容器vector的末尾，heap范围减1，那么不断的执行pop_heap直到树为空，即可得到一个递增序列。

**make_heap算法**

将一段数据转化为heap，一个一个数据插入，调用上面说的两种percolate算法即可。

代码实测：

```cpp
#include <iostream>
#include <vector>
#include <algorithm>

using namespace std;

int main()
{
    vector<int> v = {0, 1, 2, 3, 4, 5, 6};

    // 1. 将 vector 调整为大根堆
    make_heap(v.begin(), v.end());

    for (auto i : v)
    {
        cout << i << " ";
    }
    // 输出可能为：6 4 5 3 1 0 2
    cout << endl;

    // 2. 插入新元素 7
    v.push_back(7);

    // 将新插入的元素调整到堆中合适位置
    push_heap(v.begin(), v.end());

    for (auto i : v)
    {
        cout << i << " ";
    }
    // 输出可能为：7 6 5 4 1 0 2 3
    cout << endl;

    // 3. 将堆顶元素移动到末尾
    pop_heap(v.begin(), v.end());

    // 此时最大值 7 被放到了 v.back()
    cout << v.back() << endl; // 7

    // 真正删除最大值
    v.pop_back();

    for (auto i : v)
    {
        cout << i << " ";
    }
    // 输出可能为：6 4 5 3 1 0 2
    cout << endl;

    // 4. 对堆排序，排序后为升序
    sort_heap(v.begin(), v.end());

    for (auto i : v)
    {
        cout << i << " ";
    }
    // 输出：0 1 2 3 4 5 6

    return 0;
}
```

## 33、STL中的priority_queue的实现
priority_queue，优先队列，是一个拥有权值观念的queue，它跟queue一样是顶部入口，底部出口，在插入元素时，元素并非按照插入次序排列，它会自动根据权值（通常是元素的实值）排列，权值最高，排在最前面，如下图所示。

<!-- 这是一张图片，ocr 内容为： -->
![](/assets/img/202205220022333.3aafbbba.png)<!-- 这是一张图片，ocr 内容为： -->
![](https://cdn.nlark.com/yuque/0/2026/png/57223890/1779239759673-00a278d0-2601-4768-ad00-96cae447c0a6.png)

默认情况下，priority_queue使用一个max-heap完成，底层容器使用的是一般为vector为底层容器，堆heap为处理规则来管理底层容器实现 。priority_queue的这种实现机制导致其不被归为容器，而是一种容器配接器。关键的源码如下：

```cpp
#include <vector>
#include <algorithm>
#include <functional>

using namespace std;

template <
    class T,
    class Sequence = vector<T>,
    class Compare = less<typename Sequence::value_type>
>
class priority_queue
{
protected:
    Sequence c;     // 底层容器，默认是 vector<T>
    Compare comp;   // 比较规则，默认 less，形成大根堆

public:
    typedef typename Sequence::value_type value_type;
    typedef typename Sequence::size_type size_type;
    typedef typename Sequence::reference reference;
    typedef typename Sequence::const_reference const_reference;

    bool empty() const
    {
        return c.empty();
    }

    size_type size() const
    {
        return c.size();
    }

    const_reference top() const
    {
        return c.front();
    }

    void push(const value_type& x)
    {
        c.push_back(x);                       // 先把元素放到底层容器末尾
        push_heap(c.begin(), c.end(), comp);  // 再调整成堆
    }

    void pop()
    {
        pop_heap(c.begin(), c.end(), comp);   // 先把堆顶元素移到末尾
        c.pop_back();                         // 再删除末尾元素
    }
};
```

priority_queue的所有元素，进出都有一定的规则，只有queue顶端的元素（权值最高者），才有机会被外界取用，它没有遍历功能，也不提供迭代器

举个例子：

```cpp
#include <iostream>
#include <queue>

using namespace std;

int main()
{
    int ia[9] = {0, 4, 1, 2, 3, 6, 5, 8, 7};

    // 用数组区间初始化 priority_queue
    priority_queue<int> pq(ia, ia + 9);

    cout << pq.size() << endl;  // 9

    // 注意：这里只访问 top，不 pop，所以每次输出都是 8
    for (size_t i = 0; i < pq.size(); i++)
    {
        cout << pq.top() << " ";
    }
    cout << endl;  // 8 8 8 8 8 8 8 8 8

    // 正确遍历 priority_queue 的方式：
    // 每次输出堆顶元素，然后 pop 删除堆顶
    while (!pq.empty())
    {
        cout << pq.top() << " ";
        pq.pop();
    }
    cout << endl;  // 8 7 6 5 4 3 2 1 0

    return 0;
}
```

## 34、STL中set的实现？
STL中的容器可分为序列式容器（sequence）和关联式容器（associative），set属于关联式容器。

set的特性是，所有元素都会根据元素的值自动被排序（默认升序），set元素的键值就是实值，实值就是键值，set不允许有两个相同的键值

set不允许迭代器修改元素的值，其迭代器是一种constance iterators

标准的STL set以RB-tree（红黑树）作为底层机制，几乎所有的set操作行为都是转调用RB-tree的操作行为，这里补充一下红黑树的特性：

+ 每个节点不是红色就是黑色
+ 根结点为黑色
+ 如果节点为红色，其子节点必为黑
+ 任一节点至（NULL）树尾端的任何路径，所含的黑节点数量必相同

关于红黑树的具体操作过程，比较复杂读者可以翻阅《算法导论》详细了解。

举个例子：

```cpp
#include <iostream>
#include <set>

using namespace std;

int main()
{
    // set 默认按照从小到大排序
    set<int> s;

    // 插入元素
    s.insert(5);
    s.insert(2);
    s.insert(8);
    s.insert(1);
    s.insert(3);

    // 插入重复元素
    s.insert(3);
    s.insert(5);

    cout << "set 中的元素为：";
    for (auto it = s.begin(); it != s.end(); ++it)
    {
        cout << *it << " ";
    }
    cout << endl;

    // 查找元素
    auto it = s.find(3);
    if (it != s.end())
    {
        cout << "找到了元素：" << *it << endl;
    }
    else
    {
        cout << "没有找到元素 3" << endl;
    }

    // 删除元素
    s.erase(2);

    cout << "删除 2 之后：";
    for (auto x : s)
    {
        cout << x << " ";
    }
    cout << endl;

    // 统计某个元素是否存在
    cout << "元素 5 的个数：" << s.count(5) << endl;
    cout << "元素 9 的个数：" << s.count(9) << endl;

    return 0;
}

//
set 中的元素为：1 2 3 5 8
找到了元素：3
删除 2 之后：1 3 5 8
元素 5 的个数：1
元素 9 的个数：0
```

1. set 会自动排序，默认从小到大。

2. set 不允许元素重复。

3. set 的底层通常是红黑树。

4. set 的查找、插入、删除效率一般是 O(log n)。

5. set 中元素不能通过迭代器直接修改。

关联式容器尽量使用其自身提供的find()函数查找指定的元素，效率更高，因为STL提供的find()函数是一种顺序搜索算法。

## 35、STL中map的实现
map的特性是所有元素会根据键值进行自动排序。map中所有的元素都是pair，拥有键值(key)和实值(value)两个部分，并且不允许元素有相同的key

一旦map的key确定了，那么是无法修改的，但是可以修改这个key对应的value，因此map的迭代器既不是constant iterator，也不是mutable iterator

标准STL map的底层机制是RB-tree（红黑树），另一种以hash table为底层机制实现的称为hash_map。map的架构如下图所示

map的在构造时缺省采用递增排序key，也使用alloc配置器配置空间大小，需要注意的是在插入元素时，调用的是红黑树中的insert_unique()方法，而非insert_euqal()（multimap使用）

举个例子：

```cpp
#include  #include  #include  using namespace std;
int main()
{
    map<string, int> maps;
    //插入若干元素
    maps["jack"] = 1;
    maps["jane"] = 2;
    maps["july"] = 3;
    //以pair形式插入
    pair<string, int> p("david", 4);//字母排序
    maps.insert(p);
    //迭代输出元素
    map<string, int>::iterator iter = maps.begin();
    for (; iter != maps.end(); ++iter)
    {
        cout << iter->first << " ";
        cout << iter->second << "--"; //david 4--jack 1--jane 2--july 3--
    }
    cout << endl;
    //使用subscipt操作取实值
    int num = maps["july"];
    cout << num << endl; // 3
    //查找某key
    iter = maps.find("jane");
    if(iter != maps.end())
        cout << iter->second << endl; // 2
    //修改实值
    iter->second = 100;
    int num2 = maps["jane"]; // 100
    cout << num2 << endl;
return 0;
}
```

需要注意的是subscript（下标）操作既可以作为左值运用（修改内容）也可以作为右值运用（获取实值）。例如：

```cpp
 maps["abc"] = 1; //左值运用
int num = maps["abd"]; //右值运用
```

无论如何，subscript操作符都会先根据键值找出实值，源码如下：

```cpp
 ...T& operator[](const key_type& k){	
    return (*((insert(value_type(k, T()))).first)).second;
}...
```

第一步：构造一个临时元素

```cpp
value_type(k, T())
```

对于：

```cpp
map<string, int>
```

来说，`value_type` 本质上类似于：

```cpp
pair<const string, int>
```

所以：

```cpp
value_type("abc", int())
```

就是：

```cpp
pair<const string, int>("abc", 0)
```

---

第二步：插入元素

```cpp
insert(value_type(k, T()))
```

返回值是：

```cpp
pair<iterator, bool>
```

其中：

```cpp
.first
```

是迭代器，指向对应的元素。

```cpp
.second
```

表示是否插入成功。

如果 key 不存在，插入成功：

```cpp
second == true
```

如果 key 已经存在，插入失败：

```cpp
second == false
```

但是注意：即使插入失败，`.first` 仍然会指向已经存在的那个元素。

---

第三步：取出迭代器

```cpp
(insert(value_type(k, T()))).first
```

得到的是：

```cpp
iterator
```

它指向 map 中的某个元素。

---

第四步：解引用迭代器

```cpp
*((insert(value_type(k, T()))).first)
```

得到的是一个 pair：

```cpp
pair<const string, int>
```

例如：

```cpp
("abc", 1)
```

---

第五步：取出 value

```cpp
(*((insert(value_type(k, T()))).first)).second
```

取出的就是 value：

```cpp
1
```

因为返回类型是：

```cpp
T&
```

所以返回的是 value 的引用。

代码运行过程是：首先根据键值和实值做出一个元素，这个元素的实值未知，因此产生一个与实值型别相同的临时对象替代：

```cpp
 value_type(k, T());
```

再将这个对象插入到map中，并返回一个pair：

```cpp
 pair<iterator,bool> insert(value_type(k, T()));
```

pair第一个元素是迭代器，指向当前插入的新元素，如果插入成功返回true，此时对应左值运用，根据键值插入实值。插入失败（重复插入）返回false，此时返回的是已经存在的元素，则可以取到它的实值

```cpp
 (insert(value_type(k, T()))).first; //迭代器
((insert(value_type(k, T()))).first); //解引用
(((insert(value_type(k, T()))).first)).second; //取出实值
```

由于这个实值是以引用方式传递，因此作为左值或者右值都可以

**左值使用**

```cpp
maps["abc"] = 1;
```

执行过程大概是：

```cpp
maps["abc"]
```

发现 `"abc"` 不存在，于是插入：

```cpp
pair<string, int>("abc", int())
```

也就是：

```cpp
"abc" -> 0
```

然后 `operator[]` 返回这个 `0` 的引用。

于是：

```cpp
maps["abc"] = 1;
```

等价于：

```cpp
maps 中 "abc" 对应的 value = 1;
```

最终：

```cpp
abc 1
```

---

**右值使用**

```cpp
int num = maps["abd"];
```

如果 `"abd"` 不存在，`map` 也会插入：

```cpp
"abd" -> 0
```

然后返回 `0` 的引用，再赋值给 `num`：

```cpp
int num = 0;
```

所以这句代码执行后，`maps` 里面会多一个元素：

```cpp
abd 0
```

这点非常重要：**用 **`**[]**`** 读取一个不存在的 key，也会插入新元素。**

##  36、set和map的区别，multimap和multiset的区别
set只提供一种数据类型的接口，但是会将这一个元素分配到key和value上，而且它的compare_function用的是 identity()函数。这个函数是输入什么输出什么，这样就实现了set机制，set的key和value其实是一样的了。其实他保存的是两份元素，而不是只保存一份元素

map则提供两种数据类型的接口，分别放在key和value的位置上，他的比较function采用的是红黑树的comparefunction（），保存的确实是两份元素。

他们两个的insert都是采用红黑树的insert_unique() 独一无二的插入 。

multimap和map的唯一区别就是：multimap调用的是红黑树的insert_equal(),可以重复插入而map调用的则是独一无二的插入insert_unique()，multiset和set也一样，底层实现都是一样的，只是在插入的时候调用的方法不一样。

**set**

`set` 只存一个值，例如：

```cpp
set<int> s;
s.insert(10);
s.insert(20);
```

它里面的元素就是：

```cpp
10
20
```

但是在底层红黑树里，这个元素既被当作 **key**，也被当作 **value**。

也就是说：

```cpp
key = value = 10
```

所以 set 的特点是：

```cpp
set<T>
```

只关心一个类型 `T`。

例如：

```cpp
set<int>
set<string>
```

它的元素本身就是排序依据。

---

**map**

`map` 存的是键值对：

```cpp
map<string, int> m;
m["jack"] = 1;
m["jane"] = 2;
```

它里面的元素是：

```cpp
("jack", 1)
("jane", 2)
```

其中：

```cpp
key = string
value = int
```

更准确地说，`map` 中每个元素的类型是：

```cpp
pair<const Key, T>
```

例如：

```cpp
map<string, int>
```

里面存的是：

```cpp
pair<const string, int>
```

| 容器 | 存储内容 | key 是否可重复 | 底层插入方式 |
| --- | --- | --- | --- |
| `set` | 单个元素，元素本身就是 key | 不可重复 | `insert_unique()` |
| `map` | `pair<const Key, T>` | 不可重复 | `insert_unique()` |
| `multiset` | 单个元素，元素本身就是 key | 可以重复 | `insert_equal()` |
| `multimap` | `pair<const Key, T>` | 可以重复 | `insert_equal()` |


**红黑树概念**

面试时候现场写红黑树代码的概率几乎为0，但是红黑树一些基本概念还是需要掌握的。

1、它是二叉排序树（继承二叉排序树特显）：

若左子树不空，则左子树上所有结点的值均小于或等于它的根结点的值。

若右子树不空，则右子树上所有结点的值均大于或等于它的根结点的值。

左、右子树也分别为二叉排序树。

2、它满足如下几点要求：

+ 树中所有节点非红即黑。
+ 根节点必为黑节点。
+ 红节点的子节点必为黑（黑节点子节点可为黑）。
+ 从根到NULL的任何路径上黑结点数相同。

3、查找时间一定可以控制在O(logn)。

## 37、STL中unordered_map和map的区别和应用场景
map支持键值的自动排序，底层机制是红黑树，红黑树的查询和维护时间复杂度均为O(logn)，但是空间占用比较大，因为每个节点要保持父节点、孩子节点及颜色的信息

unordered_map是C++ 11新添加的容器，底层机制是哈希表，通过hash函数计算元素位置，其查询时间复杂度为O(1)，维护时间与bucket桶所维护的list长度有关，但是建立hash表耗时较大

从两者的底层机制和特点可以看出：map适用于有序数据的应用场景，unordered_map适用于高效查询的应用场景

1. map 的特点

`map` 是有序关联容器，存储的是键值对：

```cpp
map<Key, Value>
```

例如：

```cpp
map<string, int> m;

m["jack"] = 1;
m["jane"] = 2;
m["david"] = 3;
```

遍历时会按照 key 自动排序：

```cpp
david 3
jack 1
    jane 2
```

因为 `map` 底层通常是红黑树，红黑树是一种平衡二叉搜索树，所以它的主要操作复杂度是：

```cpp
查找：O(log n)
插入：O(log n)
删除：O(log n)
```

适合需要**有序遍历**、**范围查找**、**按 key 排序输出**的场景。

---

2. unordered_map 的特点

`unordered_map` 是 C++11 引入的无序关联容器，底层通常是哈希表。

例如：

```cpp
unordered_map<string, int> um;

um["jack"] = 1;
um["jane"] = 2;
um["david"] = 3;
```

它遍历时不保证顺序，输出可能是：

```cpp
jane 2
david 3
jack 1
```

也可能是其他顺序。

它通过哈希函数计算 key 应该放在哪个桶里：

```cpp
hash(key) -> bucket index
```

平均情况下：

```plain
查找：O(1)
插入：O(1)
删除：O(1)
```

但是如果哈希冲突严重，很多元素落到同一个桶里，最坏情况下可能退化为：

```plain
O(n)
```

| 对比点 | `map` | `unordered_map` |
| --- | --- | --- |
| 底层结构 | 红黑树 | 哈希表 |
| 是否有序 | 有序，按 key 排序 | 无序，不保证遍历顺序 |
| 查找复杂度 | `O(log n)` | 平均 `O(1)`，最坏 `O(n)` |
| 插入删除复杂度 | `O(log n)` | 平均 `O(1)`，最坏 `O(n)` |
| 内存开销 | 节点需要保存父子指针和颜色 | 需要桶数组，冲突处理也有额外开销 |
| 适合场景 | 需要排序、范围查询 | 只关心快速查找 |


## 38、hashtable中解决冲突有哪些方法？
```cpp
hash("abc") % 10 = 3
hash("abd") % 10 = 3
```

两个 key 都想放到下标 `3`，这就发生了冲突。

**记住前三个：**

1. 线性探测法

线性探测属于**开放定址法**。

假设哈希函数算出来的位置是 `i`：

```cpp
i = hash(key) % table_size
```

如果 `i` 位置已经有元素了，就继续往后找：

```cpp
i + 1
i + 2
i + 3
...
```

如果找到表尾，就从表头继续找。

例如哈希表大小为 10，要插入的位置是 3：

```cpp
3 被占用
找 4
4 被占用
找 5
5 为空
插入 5
```

优点是实现简单，缓存命中率较好。缺点是容易产生**主聚集**，也就是一大片连续位置都被占用，查找效率下降。

2. 开链法

开链法也叫**链地址法**。

哈希表的每个桶后面挂一个链表，或者其他结构。

例如：

```cpp
bucket[3] -> abc -> abd -> jack
```

如果多个 key 经过 hash 后都落到下标 3，就都放到这个桶对应的链表中。

查找时先计算桶位置：

```cpp
index = hash(key) % table_size
```

然后在这个桶对应的链表中继续查找。

这是很多哈希表常用的冲突处理方式。`unordered_map` 底层通常就是类似“桶 + 链表/节点”的结构。

3. 再散列法

再散列也叫**双重哈希**。

发生冲突后，不是简单地向后找，而是换一个 hash 函数继续计算位置。

例如：

```cpp
H1(key) = 初始位置
H2(key) = 冲突后的步长
```

探测序列可以是：

```cpp
H1(key)
H1(key) + H2(key)
H1(key) + 2 * H2(key)
H1(key) + 3 * H2(key)
```

这样可以减少线性探测中的聚集问题。

4. 二次探测法

二次探测也是开放定址法的一种。

如果初始位置冲突，不是按：

```cpp
+1, +2, +3
```

这样线性查找，而是按照平方步长查找：

```cpp
+1^2
    +2^2
    +3^2
    +4^2
```

也就是：

```cpp
i + 1
i + 4
i + 9
i + 16
...
```

有些写法也会向两边探测：

```cpp
i + 1^2, i - 1^2
i + 2^2, i - 2^2
i + 3^2, i - 3^2
```

它比线性探测更不容易产生连续聚集，但实现和删除处理会复杂一些。

5. 公共溢出区

公共溢出区的思想是：

哈希表正常区域放主要元素，如果发生冲突，就把冲突元素统一放到一个专门的溢出区域。

例如：

```cpp
正常哈希表：
0
1
2
3 -> abc
4
5

公共溢出区：
abd
jack
rose
```

查找时，先查正常哈希表。如果对应位置不是目标元素，再去公共溢出区查找。

这种方法思想简单，但如果溢出区元素太多，查找效率会下降。

| 方法 | 核心思想 | 特点 |
| --- | --- | --- |
| 线性探测 | 冲突后向后一个一个找空位 | 简单，但容易聚集 |
| 开链法 | 每个桶后面挂链表 | 常用，处理冲突直观 |
| 再散列 | 冲突后换另一个 hash 函数 | 分布更均匀 |
| 二次探测 | 冲突后按平方步长找空位 | 减少线性聚集 |
| 公共溢出区 | 冲突元素统一放到溢出区 | 简单，但溢出区大了效率低 |
