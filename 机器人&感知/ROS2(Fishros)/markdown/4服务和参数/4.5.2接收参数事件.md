## 4.5.2接收参数事件
在 src/demo_cpp_service/src/**turtle_control.cpp**文件中添加代码

```cpp
#include "rcl_interfaces/msg/set_parameters_result.hpp"
using SetParametersResult = rcl_interfaces::msg::SetParametersResult;

class TurtleController : public rclcpp::Node {
public:
    TurtleController() : Node("turtle_controller") {
        ...
        // 添加参数设置回调
        parameters_callback_handle_ = this->add_on_set_parameters_callback(
            [&](const std::vector<rclcpp::Parameter> &params)
                -> SetParametersResult {

                // 遍历参数
                for (auto param : params) 
                {
                    RCLCPP_INFO(
                        this->get_logger(),
                        "更新参数 %s 值为: %f",
                        param.get_name().c_str(),
                        param.as_double()
                    );

                    if (param.get_name() == "k") 
                    {
                        k_ = param.as_double();
                    } else if (param.get_name() == "max_speed") 
                    {
                        max_speed_ = param.as_double();
                    }
                }

                auto result = SetParametersResult();
                result.successful = true;
                return result;
            }
        );
    }

private:
    OnSetParametersCallbackHandle::SharedPtr parameters_callback_handle_;
    ...
};
```

执行顺序就是：

1. **收到新参数**（例如 k=2.0）
2. **打印日志**  
日志里输出的值是 `param.as_double()`，也就是新设置的值  
（日志不会输出旧值）
3. **将新值写入变量 k_**

所以流程是：

**打印新参数值 → 更新节点内部变量**

 🔍 关键点：打印的不是旧值，而是新值  

### **触发机制到底在哪里体现？**
在这一句：

```plain
this->add_on_set_parameters_callback(...)
```

你把一个 lambda 或函数指针“挂”在了参数系统上。

内部实现（简化说明）：

+ ROS 2 节点有一个参数服务 `/node/set_parameters`
+ 当任何地方请求更新参数：
    - rclcpp 会收到请求并遍历 callbacks
    - 调用你注册的 callback
    - callback 返回成功/失败
    - 参数最终被系统写入

所以“触发点”不是在你代码里，而是在 **rclcpp 框架内部**。

🔥 **你最关心的关键点：是否必须写在 main？**

❌ **不需要，也通常不会写在 main！**

✔ **应该写在节点内部，例如：**

+ 定时器回调
+ 订阅回调
+ 服务回调
+ 动作反馈回调
+ 甚至构造函数之后

示例：

```plain
timer_ = this->create_wall_timer(1s, [this]() {
    this->set_parameter(rclcpp::Parameter("k", 2.0));
});
```

🔍 那么既然有 ros2 param set，为什么还需要 set_parameter()？

因为 **有时候节点需要自己修改参数**：

例如：

+ PID 控制器自动调整参数
+ 机器人任务执行过程中动态改变某个阈值
+ 节点根据某些事件自行调整 max_speed

这种情况下 **外部命令无法满足需求**，只能在代码中调用：

```plain
set_parameter(...)
```

`<font style="color:#DF2A3F;">set_parameter()`**<font style="color:#DF2A3F;">只能在节点对象已经创建之后调用**<font style="color:#DF2A3F;">。

例如在构造函数之后、定时器回调、服务回调等地方调用都可以：

```cpp
auto node = std::make_shared<TurtleController>();
node->set_parameter(rclcpp::Parameter("k", 2.0));
```
