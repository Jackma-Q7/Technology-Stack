# 第四章 服务和参数
## 4.1.1服务通信介绍

&emsp;&emsp;在 ROS2 中，服务通信 Service 是一种常用的节点间通信方式。它采用的是 请求—响应模式，也就是一个节点发送请求，另一个节点处理请求后返回结果。

&emsp;&emsp;服务通信和话题通信不同。话题通信是持续发布和订阅，适合连续数据传输，例如速度、图像、雷达、位姿等；而服务通信更像是“问一次，答一次”，适合执行某个明确的操作，例如清除轨迹、生成新乌龟、设置参数、查询状态等。

1. 服务通信的基本概念

服务通信中通常有两个角色：

客户端 Client：发送请求的一方
服务端 Server：接收请求并返回响应的一方

例如在 turtlesim 中，可以使用服务清除小乌龟的运动轨迹：
```
ros2 service call /clear std_srvs/srv/Empty
```
这里：
```
/clear 是服务名称
std_srvs/srv/Empty 是服务接口类型
```
执行后，客户端向 /clear 服务发送请求，turtlesim 节点接收请求并清除背景轨迹，然后返回响应。
