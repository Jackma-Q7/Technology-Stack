## 通过shared_ptr实现“写时复制”
写时复制(copy-on-write)的概念

只有在真正需要资源时才去分配资源

写时复制应用在多线程同步的场景

&emsp;&emsp;在系统中，有多个读线程和写线程共享一个数据结构。如果系统中的读操作的概率远远大于写操作，**<font style="color:#DF2A3F;">因为读写互斥的需要也会造成读线程间也需要加锁互斥，这无疑降低了系统处理的速度</font>**。其实只有当写线程进行操作时，才需要读写线程间的加锁互斥而读线程间是无需加锁的。运用写时复制的概念，在写线程判断如果有读线程在操作则**<font style="color:#DF2A3F;">拷贝一份数据进行更新</font>**

两个前提:

1.shared_ptr的读方法是多线安全的

2.shared_ptr所指向的对象的提供的读方法必须是多线程安全的

```cpp
#include <iostream>
#include <memory>
#include <thread>
#include <vector>
#include <shared_mutex>
#include <chrono>

class Data
{
public:
    Data() = default;
    Data(const std::vector<int>& v) : mVec(v) {}

    void print() const
    {
        for (int v : mVec)
        {
            std::cout << v << " ";
        }
        std::cout << std::endl;
    }

    void push_back(int value)
    {
        mVec.push_back(value);
    }

private:
    std::vector<int> mVec;
};

// 全局共享数据
std::shared_ptr<Data> gData = std::make_shared<Data>(std::vector<int>{1, 2, 3});
std::shared_mutex gMutex;

// 读线程：只拿到当前快照，然后无锁读对象内容
void reader(int id)
{
    for (int i = 0; i < 5; ++i)
    {
        std::shared_ptr<Data> localPtr;

        {
            std::shared_lock<std::shared_mutex> lock(gMutex);
            localPtr = gData;   // 只复制 shared_ptr
        }

        std::cout << "Reader " << id << " sees: ";
        localPtr->print();

        std::this_thread::sleep_for(std::chrono::milliseconds(100));
    }
}

// 写线程：复制旧数据，修改副本，再整体替换
void writer(int id)
{
    for (int i = 0; i < 3; ++i)
    {
        std::shared_ptr<Data> oldPtr;

        {
            std::shared_lock<std::shared_mutex> lock(gMutex);
            oldPtr = gData;   // 先读出旧快照
        }

        // ===== 写时复制的关键 =====
        // 基于旧数据拷贝一个新对象
        std::shared_ptr<Data> newPtr = std::make_shared<Data>(*oldPtr);

        // 修改副本，不影响正在读的线程
        newPtr->push_back(100 + i);

        {
            std::unique_lock<std::shared_mutex> lock(gMutex);
            gData = newPtr;   // 一次性替换
        }

        std::cout << "Writer " << id << " updated data." << std::endl;

        std::this_thread::sleep_for(std::chrono::milliseconds(150));
    }
}

int main()
{
    std::thread t1(reader, 1);
    std::thread t2(reader, 2);
    std::thread t3(writer, 1);

    t1.join();
    t2.join();
    t3.join();

    return 0;
}
```

`std::make_shared<Data>(std::vector<int>{1, 2, 3}); `

`std::make_shared<Data>(); `

## 问题1：括号中不应该是一个Data类型的对象吗？为什么std::vector<int>{1, 2, 3}也可以？

+ `make_shared<Data>( 一个vector )`→ 等价于 `new Data( vector )` ✅ 匹配构造函数
+ `make_shared<Data>()`→ 等价于 `new Data()` ✅ 调用无参构造

## 问题2：Data &就是data类型的本身对吗？

`Data&` 不是 Data 本身，而是“Data 对象的引用（别名）”  

```plain
Data a;
Data& ref = a;
```

👉 现在：

```plain
ref 就是 a 的另一个名字
```

改 ref 就是改 a

```cpp
#include <memory>
#include <iostream>
#include <thread>
#include <mutex>
#include <vector>

typedef std::vector<int> IntList;
typedef std::shared_ptr<IntList> IntListPtr;

IntListPtr g_Ints;
std::mutex g_Mutex;

void read()
{
    IntListPtr intsPtr;

    {
        std::lock_guard<std::mutex> lock(g_Mutex);
        // 对于全局共享指针 g_Ints 来说，这里是读操作
        // 把当前共享数据拷贝一份 shared_ptr 出来，保证后续使用时对象还活着
        intsPtr = g_Ints;
    } // 锁在这里释放

    // 对共享对象 IntList 进行读操作
    // 注意：这里应该使用 intsPtr，而不是直接使用 g_Ints
    for (size_t i = 0; i < intsPtr->size(); ++i)
    {
        std::cout << (*intsPtr)[i] << std::endl;
    }
}

void write(int value)
{
    std::lock_guard<std::mutex> lock(g_Mutex);

    // 如果当前不是唯一持有者，说明还有读线程在使用旧数据
    // 此时执行“写时复制”：先复制一份新数据，再在新数据上修改
    if (!g_Ints.unique())
    {
        g_Ints.reset(new IntList(*g_Ints));
    }

    // 对共享对象 IntList 进行写操作
    g_Ints->push_back(value);
}

void ReadThreadFunc()
{
    read();
}

void WriteThreadFunc()
{
    write(18);
}

int main()
{
    g_Ints = std::make_shared<IntList>();

    // 先放几个初始数据，方便读线程看到内容
    g_Ints->push_back(1);
    g_Ints->push_back(2);
    g_Ints->push_back(3);

    std::thread Read1(ReadThreadFunc);
    std::thread Read2(ReadThreadFunc);
    std::thread Read3(ReadThreadFunc);
    std::thread Read4(ReadThreadFunc);
    std::thread Read5(ReadThreadFunc);

    std::thread Write1(WriteThreadFunc);

    Read1.join();
    Read2.join();
    Read3.join();
    Read4.join();
    Read5.join();
    Write1.join();

    std::cout << "main thread final data: ";
    for (size_t i = 0; i < g_Ints->size(); ++i)
    {
        std::cout << (*g_Ints)[i] << " ";
    }
    std::cout << std::endl;

    return 0;
}
```

| 对比项             | 你这份代码                         | 我前面的示例                     |
|--------------------|------------------------------------|----------------------------------|
| 共享对象           | `shared_ptr<vector<int>>`          | `shared_ptr<Data>`               |
| 读线程             | 先拷贝指针，但后续代码误用了 `g_Ints` | 全程使用本地快照 `localPtr`       |
| 写线程             | `unique()` 判断后按需复制           | 每次写都复制                     |
| 锁                 | `mutex`                            | `shared_mutex`                   |
| 是否更像标准 COW   | 是                                 | 稍偏“版本快照替换”               |
| 适合学习原理       | 很适合                             | 也适合                           |
| 适合扩展到项目     | 一般                               | 更好                             |

## 问题3：这里不用新定义一个对象出来接收拷贝构造的吗？直接用g_Ints不会出问题吗？

g_Ints.reset(newIntList(*g_Ints));

① 用旧对象 *g_Ints 拷贝构造一个新 vector  
② 让 g_Ints 指向这个新对象  
③ 原来的旧对象引用计数 -1（但不会立刻销毁，如果还有读线程在用）

写法1（你现在的）

g_Ints.reset(new IntList(*g_Ints));

写法2（更直观）

IntListPtr newPtr = std::make_shared<IntList>(*g_Ints);

g_Ints = newPtr;

不会破坏旧数据
