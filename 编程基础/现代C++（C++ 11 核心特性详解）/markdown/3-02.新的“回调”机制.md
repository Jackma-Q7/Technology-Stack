## function与bind结合
&emsp;&emsp;function可以存储任意类型的可调用对象，bind可以将一个可调用对象转换成新的可调用对象，那么我们可以通过bind将一个可调用对象转换成指定的funtcion类型。

## 新的回调实现机制
&emsp;&emsp;试想我们实现一个网络的库，通过IO复用函数(select，epoll)来监听网络的事件(可读，可写，连接断开等)，当这些网络事件发生时，需要有一个机制来通知上层业务，通常我们会通过回调来实现。网络事件对于的处理函数称为回调处理函数，有如下三种方式来实现

1.面向对象：多态的方式实现事件的回调

2.事件回调：通过C语言的方式---->通过函数指针实现，function + bind来实现

```cpp
#include <iostream>
//网络库中提供的处理事件的接口类
class NetEvent
{
public:
    virtual void OnMessage(const std::string& strMsg) = 0;
    virtual void OnDisconnect(int i) = 0;
    virtual void Connect(int i) = 0;
};

//上层应用继承NetEvent实现各个接口
class MyEvent :public NetEvent
{
public:
    virtual void OnMessage(const std::string& strMsg)
    {
        ...
    }

    virtual void OnDisconnect(int i)
    {
        ...
    }

    virtual void Connect(int i)
    {
        ...
    }

};

int main()
{
    //网络库对象
    Netlib lib;
    //产生MyEvent对象
    MyEvent* pEvent = new MyEvent;

    lib.registerHandler(pEvent);
    lib.run();
}
```

运行流程就是：

1. `MyEvent event;` 创建业务对象 
2. `registerHandler(&event);` 注册给网络库 
3. `run();` 网络库开始工作 
4.  网络事件发生 
5.  网络库通过基类指针调用虚函数 
6.  实际执行的是 `MyEvent` 里的代码

这段代码的本质就是：

&emsp;&emsp;网络库负责监听事件，上层业务把“处理事件的方法”注册进去；当事件发生时，网络库通过基类指针调用虚函数，借助多态执行子类中的具体处理逻辑，这就是用面向对象方式实现回调。

## 面向对象的思想
&emsp;&emsp;我们通常的实现方式是在库中定义几个抽象类，其中声明一些(纯)虚函数，比如OnMessage()，OnDisconnect()等。来对应具体事件对应的事件处理函数。使用者需要继承这些基类，并覆写这些虚函数，以获得事件回调通知，并且使用者必须把派生类对象(即handler对象，通常是动态分配的)的指针或引用注册到库中，网络库通过多态的特性来调用相应的接口(handle对象，即为事件处理)。但是有几个弊端：

**对象所有权**

&emsp;&emsp;就是对handler的生命周期的管理，首先到底谁有权释放handler对象，就需要仔细斟酌(也许可以通过智能指针来解决释放对象的问题，但是依然需要甄别所有权，对不拥用对象使用weak_ptr，拥有对象使用shared_ptr)

**设计思想上的**

&emsp;&emsp;库中的事件接口定义，其所要表述的思想是，当有对应的事件发生时，需要进行处理。关于这个处理事件的“东西”(在这里把回调处理函数称为“东西”)到底是什么并不关心，它可以是一个事件处理对象，可以是一个普通的函数，可以是一个对象的成员方法，或是一个函数对象。库只关心事件发生时，能有对应的“东西”去处理即可。而由于C++ 语言机制的限定，这个“东西”必须有个特定类型，在面向对象的思想中，它被定义为一个事件处理对象。在函数编程思想中，它被定义为一个函数指针。当这个“东西”有了特定的类型，也就是排它的了，即如果是一个事件处理对象，那么就不能绑定到一个函数。所以这种语言上的限制就限定了代码编写的灵活性。反观C#，python中就没有这样的限制，C#通过委托可以不用在意具体事件处理的类型，而python的函数都归为对象

**代码的可读性和可维护性**

&emsp;&emsp;继承是强耦合关系,如果通过上述的handler对象实现的方式，显然是增加了代码的耦合度，类的层次，加大了代码的复杂度，就降低了代码的可读性和可维护性

## 通过函数指针实现事件回调
&emsp;&emsp;函数指针实现事件回调，相对于多态的方式会更加简明，不用引入复杂的继承类型。通过定义对应事件处理函数的指针，事件发生时，通过指针来调用事件处理函数。这是c语言的做法。但是这种方式事件处理回调的类型依然被限制

## function + bind的实现事件回调
&emsp;&emsp;function + bind的方式，类似于函数指针实现回调的方式，但是它更加灵活，一个是避免了对回调处理函数的类型限制，二是避免了引入继承类型增加类型的复杂度

```cpp
#include <iostream>
#include <functional>

typedef std::function<void(const std::string&)> OnMessage;
typedef std::function<void(int)> onConnect;
typedef std::function<void(int)> onDisConnect;

class Netlib
{
public:
    void Init(const OnMessage& Msg, const onConnect& Connect, const onDisConnect &Disconnect)
    {
        m_fOnMesage = Msg;
        m_fOnConnect = Connect;
        m_fOnDisConnect = Disconnect;
    }

    void Process()
    {
        if (m_fOnMesage)
        {
            m_fOnMesage("this is message");
        }

        if (m_fOnConnect)
        {
            m_fOnConnect(18);
        }

        if (m_fOnDisConnect)
        {
            m_fOnDisConnect(-1);
        }
    }
private:
    OnMessage m_fOnMesage;
    onConnect m_fOnConnect;
    onDisConnect m_fOnDisConnect;
};

void OMsg(const std::string& msg)
{
    std::cout << msg.c_str() << std::endl;
}

void OnConnect(int v)
{
    std::cout << v << std::endl;
}

void OnDisConnect(int v)
{
    std::cout << v << std::endl;
}

struct sConnect
{
    void operator()(int i)
    {
        std::cout << i << std::endl;
    }
};

void MyMessag(const std::string& name, const std::string& Msg)
{
    std::cout << name.c_str() << "," << Msg.c_str() << std::endl;
}

class CConnect
{
public:
    void DisConnect(int i)
    {
        std::cout << i << std::endl;
    }
};

int main()
{
    Netlib lib;
    CConnect disConnect;
    lib.Init(std::bind(MyMessag,"MyMessage",std::placeholders::_1), sConnect(), std::bind(&CConnect::DisConnect,&disConnect,std::placeholders::_1));
    lib.Process();
}
```

一、function 就在这里（最关键）

```cpp

typedef std::function<void(int)> onConnect;
typedef std::function<void(int)> onDisConnect;
```

👉 这三行就是 **std::function 的定义位置**


二、function 真正“存东西”的地方

```cpp

onConnect m_fOnConnect;
onDisConnect m_fOnDisConnect;
```

👉 这里是 **std::function 的实例**

这3个成员变量 = “回调函数槽位”

五、最关键一行：你传了什么进来？

```cpp

    sConnect(),
```

① 第一个参数（消息回调）

```cpp

```

```cpp

```

👉 bind 之后变成：

```cpp

```

等价于：

```cpp

```

② 第二个参数（连接回调）

```cpp

```

这个是仿函数：

```cpp

{

```

👉 本质就是一个“可以像函数一样调用的对象”

③ 第三个参数（断开回调）

```cpp

```

👉 绑定成员函数：



`std::function` 把“各种不同形式的函数”统一包装成一种类型，然后在需要的时候统一调用。  

**一句话解释回调  ：**

&emsp;&emsp;回调就是：你把一个函数交给别人，当某个事件发生时，由别人反过来调用你这个函数。

```cpp
#include <iostream>
#include <functional>

// 定义一个回调类型（可以装函数）
typedef std::function<void(int)> Callback;

// 模拟一个“事件触发器”（比如网络库）
class EventSource
{
public:
void setCallback(Callback cb)
{
    m_cb = cb; // 保存回调函数
}

void trigger()
{
    std::cout << "事件发生了！" << std::endl;

    if (m_cb)
    {
        m_cb(100); // 回调！
    }
}

private:
Callback m_cb;
};

// 业务层函数（被回调）
void MyHandler(int value)
{
    std::cout << "收到回调，value = " << value << std::endl;
}

int main()
{
    EventSource source;

    // 把函数“交给”事件源
    source.setCallback(MyHandler);

    // 模拟事件发生
    source.trigger();

    return 0;
}
```

&emsp;&emsp;回调是把函数交给别人调用；std::function 负责统一“函数类型（ 函数的“参数类型 + 返回值类型”  ）”，std::bind 负责适配“函数参数”。
