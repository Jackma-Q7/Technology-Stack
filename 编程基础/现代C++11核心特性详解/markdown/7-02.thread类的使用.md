## **线程的创建**
C++11中创建一个线程，变得很简单

```cpp
#include <thread>
#include <iostream>
int main()
{
    std::thead t([]{std::cout<<"func()"<<std::endl;});
    //等待线程执行完毕
    t.join();
    //线程分离
    //t.detach();
}
```

## 线程的生命周期
&emsp;&emsp;当通过Thread对象产生一个线程时，则Thread对象的生命周期等于线程的生命周

&emsp;&emsp;可以将Thread定义为类的成员变量

&emsp;&emsp;可以通过容器来存储线程对象

**线程对象只可移动，不能复制**

```cpp
#include <thread>
#include <iostream>
#include <vector>
void func()
{
    std::cout << "before move " << std::this_thread::get_id() << std::endl;
    std::this_thread::sleep_for(std::chrono::seconds(3));
    std::cout << "after move " << std::this_thread::get_id() << std::endl;
}

int main()
{
    std::vector<std::thread> vecThreads;
    std::thread t1(func);
    /*std::this_thread::sleep_for(std::chrono::seconds(1));
    std::thread t2(std::move(t1));
    t2.join();*/
    vecThreads.push_back(std::move(t1));
}
```

一、线程生命周期（核心一条线）

线程从创建到结束，大致经历这几个阶段：

**创建 → 运行 → 阻塞/等待 → 结束（join/detach）**

一句话理解：  
👉 **线程对象存在 ≠ 线程一定在跑，但线程结束前必须被正确回收**

二、结合你的代码讲

你的代码核心是：

```cpp
std::thread t1(func);
vecThreads.push_back(std::move(t1));
```

我们一步步看生命周期 👇

1️⃣ 创建线程（开始运行）

```cpp
std::thread t1(func);
```

发生了两件事：

+  创建了线程对象 `t1`
+ **操作系统线程已经启动，开始执行 func()**

👉 注意：线程不是“调用 start 才运行”，而是**构造就开始运行**

2️⃣ 线程运行中

```cpp
void func()
{
    std::cout << "before move " << std::this_thread::get_id() << std::endl;
    std::this_thread::sleep_for(std::chrono::seconds(3));
    std::cout << "after move " << std::this_thread::get_id() << std::endl;
}
```

线程会：

+  打印ID 
+  睡眠3秒（阻塞状态） 
+  再继续执行 

👉 这里就是：  
**运行 → 阻塞 → 再运行**

3️⃣ 移动线程对象（关键点🔥）

```cpp
vecThreads.push_back(std::move(t1));
```

因为：

👉 `std::thread`**不能拷贝，只能移动**

移动后：

+ `t1` 变成 **空线程（不再关联任何线程）**
+  vector里的那个 thread 才是真正“拥有线程”的对象 

👉 本质：

```cpp
线程所有权 从 t1 → vector里的对象
```

4️⃣ 生命周期问题（你代码的坑⚠️）

你的代码**没有 join 或 detach**

程序结束时：

```cpp
vecThreads 析构
```

而此时：

👉 线程还在运行（sleep 3秒）

结果：

❌ **程序直接崩溃（terminate）**

因为标准规定：

如果 thread 对象析构时仍然 joinable → 程序终止

三、正确写法（必须掌握）

✔️ 写法1：join（最常用）

```cpp
for (auto& t : vecThreads)//在vecThreads取auto& t
{
    t.join();
}
```

👉 含义：主线程等待子线程结束

✔️ 写法2：detach（少用）

```cpp
t.detach();
```

👉 含义：线程自己跑，不再受控制（容易出问题）

四、总结

👉 **线程生命周期 = 创建即运行，结束前必须 join 或 detach，否则程序崩溃**

五、你这段代码的本质总结

👉 做了三件事：

1.  创建线程（开始执行 func） 
2.  把线程所有权 move 到 vector 
3.  ❌ 没有 join → 程序风险 

六、再给你一个直觉理解

把 `std::thread` 想象成：

👉 **“线程的控制权句柄”**

+  可以移动（转移控制权） 
+  不能复制（避免多个控制者） 
+  必须“善终”（join/detach）

**Thread定义为类的成员变量**

```cpp
#include <iostream>
#include <thread>

class MyWorker
{
public:
    MyWorker()
    {
        t = std::thread(&MyWorker::run, this); // 启动线程
    }

    ~MyWorker()
    {
        if (t.joinable())
        {
            t.join(); // 必须回收线程
        }
    }

    void run()
    {
        std::cout << "Thread running, id = "
                  << std::this_thread::get_id() << std::endl;
    }

private:
    std::thread t; // 成员变量
};

int main()
{
    MyWorker w;
    return 0;
}
```
