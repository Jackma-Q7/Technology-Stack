**队列的实现**

&emsp;&emsp;在用途这个方向的划分，对于队列的实现，没有太大区别。只是队列中放的数据类型不一样。一种是业务的数据，一种是可调用的对象。

&emsp;&emsp;那么有界队列和无界队列，在队列的实现方式上是有很大的不同。

有界队列

1.容量有限，对生产者来说，是需要等待队列中有空位，如果没有则应该等待。对消费者来说，是需要队列中有数据，如果没有也应该等待

2.那么生产者放入数据后，应该通知消费者。消费者取走数据后应该通知生产者有空位

无界队列

1.容量无限制，所以对生产者来说，是无需关心是否有空位

2.但对消费者来说，如果队列中没有空位则需要等待

消费者，生产者间都需要同步

```cpp
#include <thread>
#include <deque>
#include <mutex>
#include <condition_variable>
#include <iostream>
#include <future>
#include <chrono>
#include <functional>

template<typename T>
class CBoundedQueue
{
public:
    CBoundedQueue(int maxSize)
        : m_iMaxSize(maxSize), m_iCnt(0)
    {}

    ~CBoundedQueue() {}

    // 生产者：放入数据
    void Put(const T& x)
    {
        std::unique_lock<std::mutex> lock(m_mutex);

        // 队列满时等待，直到队列不满
        m_notFull.wait(lock, [this]() {
            return CanPut();
        });

        m_deqDatas.push_back(x);
        ++m_iCnt;

        lock.unlock();

        // 通知消费者：队列中有数据了
        m_notEmpty.notify_one();
    }

    // 消费者：取出数据
    T Get()
    {
        std::unique_lock<std::mutex> lock(m_mutex);

        // 队列为空时等待，直到队列不空
        m_notEmpty.wait(lock, [this]() {
            return CanGet();
        });

        T front = m_deqDatas.front();
        m_deqDatas.pop_front();
        --m_iCnt;

        lock.unlock();

        // 通知生产者：队列有空位了
        m_notFull.notify_one();

        return front;
    }
//完全没使用
    bool Empty() const
    {
        std::lock_guard<std::mutex> lock(m_mutex);
        return m_deqDatas.empty();
    }

    bool Full() const
    {
        std::lock_guard<std::mutex> lock(m_mutex);
        return m_iCnt == m_iMaxSize;
    }

private:
    // 判断是否可以放数据
    bool CanPut() const
    {
        return m_iCnt < m_iMaxSize;
    }

    // 判断是否可以取数据
    bool CanGet() const
    {
        return m_iCnt > 0;
    }

private:
    int m_iCnt;                         // 当前队列元素数量
    int m_iMaxSize;                     // 队列最大容量
    std::deque<T> m_deqDatas;           // 底层容器

    mutable std::mutex m_mutex;         // 互斥锁
    std::condition_variable m_notFull;  // 队列不满条件变量
    std::condition_variable m_notEmpty; // 队列不空条件变量
};

// 消费者线程函数
void c(CBoundedQueue<int>* d)
{
    auto threadid = std::this_thread::get_id();

    std::this_thread::sleep_for(std::chrono::seconds(3));

    while (true)
    {
        int v = d->Get();

        std::cout << "thread id " << threadid
                  << ", get value " << v << std::endl;
    }
}

int main()
{
    CBoundedQueue<int> d(10);

    // 创建两个消费者线程
    std::future<void> ret =
        std::async(std::launch::async, c, &d);

    std::future<void> ret1 =
        std::async(std::launch::async, c, &d);

    // 生产者线程：放入12个数据
    for (int i = 0; i < 12; ++i)
    {
        d.Put(i);
        std::cout << "put data " << i << std::endl;
    }

    ret.wait();
    ret1.wait();

    return 0;
}
```

```plain
（暂停3秒）

```

一、先看整体：这段代码在干嘛？

👉 一句话：

用一个固定大小的队列，在多个线程之间安全地传递数据

角色划分

| 角色 | 对应代码 |
| --- | --- |
| 队列 | `CBoundedQueue` |
| 生产者 | `main()`里的 `Put()` |
| 消费者 | 函数 `c()` |
| 同步机制 | `mutex + condition_variable` |


二、最核心的模型（你必须理解）

👉 这是经典模型：

```plain
生产者 → Put() → 队列 → Get() → 消费者
```

三、一步一步拆核心逻辑

1️⃣ Put（生产者逻辑）

```cpp
void Put(const T& x)
```

🔑 核心流程：

① 加锁

```cpp
std::unique_lock<std::mutex> lock(m_mutex);
```

👉 保证线程安全

② 队列满 → 等待

```cpp
m_notFull.wait(lock, [this]() {
    return CanPut();
});
```

👉 等价于：

```cpp
while (队列满) {
    等待
}
```

③ 放数据

```cpp
m_deqDatas.push_back(x);
++m_iCnt;
```

④ 解锁

```cpp
lock.unlock();
```

👉 ⚠️ 这里手动解锁是为了提高性能（很专业的写法）

⑤ 通知消费者

```cpp
m_notEmpty.notify_one();
```

👉 告诉消费者：

“有数据了，可以取了”

✅ 总结一句话

👉 Put =  
**如果满了就等 → 不满就放 → 通知消费者**

四、Get（消费者逻辑）

```cpp
T Get()
```

① 加锁

```cpp
std::unique_lock<std::mutex> lock(m_mutex);
```

② 队列空 → 等待

```cpp
m_notEmpty.wait(lock, [this]() {
    return CanGet();
});
```

👉 等价于：

```cpp
while (队列空) {
    等待
}
```

③ 取数据

```cpp
T front = m_deqDatas.front();
m_deqDatas.pop_front();
--m_iCnt;
```

④ 解锁

```cpp
lock.unlock();
```

⑤ 通知生产者

```cpp
m_notFull.notify_one();
```

👉 告诉生产者：

“有位置了，可以放了”

✅ 总结一句话

👉 Get =  
**如果空就等 → 不空就取 → 通知生产者**

五、条件变量的本质（非常关键🔥）

这一句是灵魂：

```cpp
m_notFull.wait(lock, predicate);
```

👉 本质是：

```cpp
while (!predicate()) {
    等待
}
```

🧠 为什么必须这样？

👉 防止：

+  虚假唤醒（spurious wakeup） 
+  被错误唤醒

✅ 它实现了：

1️⃣ 有界队列（容量限制）

```cpp
最大只能存10个
```

2️⃣ 自动阻塞

```cpp
满了 → 生产者等
空了 → 消费者等
```

3️⃣ 线程安全

```cpp

```

4️⃣ 线程同步

```plain

```

九、你要真正理解的3个点（面试必问🔥）

🎯 1. 为什么要两个 condition_variable？

```cpp
m_notFull
m_notEmpty
```

👉 因为：

| 条件 | 谁等 | 谁通知 |
| --- | --- | --- |
| 队列满 | 生产者等 | 消费者通知 |
| 队列空 | 消费者等 | 生产者通知 |


🎯 2. 为什么 unlock 再 notify？

```cpp
lock.unlock();
notify_one();
```

👉 避免：

```cpp
唤醒线程 → 但锁还没释放 → 白唤醒 ❌
```

🎯 3. 为什么用 deque？

👉 因为：

```plain
push_back + pop_front 高效
```

十、一句话总结

👉这个代码实现了一个基于 mutex 和 condition_variable 的有界阻塞队列，通过两个条件变量分别控制“队列满”和“队列空”的同步，实现了线程安全的生产者-消费者模型。

## 问题1： 如果满了怎么通知进行阻塞  ？
一、关键代码（就是这一句）

```cpp
m_notFull.wait(lock, [this]() {
    return CanPut();
});
```

👉 这就是**阻塞的源头**

二、它到底做了什么？

这句代码 ≈ 等价于：

```cpp
while (!CanPut())   // 队列满
{
    m_notFull.wait(lock);
}
```

三、阻塞的完整过程（一步一步）

🧠 场景：队列已经满了

```cpp
m_iCnt == m_iMaxSize
```

🔴 第一步：线程进入 wait

```cpp
m_notFull.wait(lock, ...);
```

👉 发生三件事（非常重要）：

1️⃣ 判断条件

```plain
CanPut() → false
```

2️⃣ 自动释放锁 🔓

```cpp
lock.unlock()
```

👉 为什么要释放？  
👉 不然消费者拿不到锁，就永远无法消费 → 死锁 ❌

3️⃣ 当前线程“睡眠”（阻塞）

```plain
线程挂起（不占CPU）
```

👉 此时：

+  线程不会继续执行 
+  操作系统把它挂起 
+  等待别人唤醒 

四、谁来唤醒它？

👉 消费者线程！

看这里：

```cpp
m_notFull.notify_one();
```

👉 当消费者执行完：

```cpp
Get()
```

之后：

```cpp
队列有空位了
```

👉 就会：

```cpp
唤醒一个正在等待的生产者线程
```

五、被唤醒之后发生什么？

👉 线程不会直接往下跑，而是：

🔁 重新执行：

```plain
while (!CanPut())
```

👉 再检查一次！

为什么要再检查？（重点🔥）

👉 防止：

+  多线程竞争 
+  虚假唤醒（spurious wakeup） 

六、完整流程图（你一定要理解）

```plain
生产者 Put
    ↓
队列满？
    ↓ 是
进入 wait
    ↓
释放锁 + 线程睡眠
    ↓
消费者 Get
    ↓
notify_one()
    ↓
生产者被唤醒
    ↓
重新检查条件
    ↓
继续执行 Put
```

七、总结成一句话（非常重要🔥）

👉  **阻塞的本质是：线程在 condition_variable.wait 中释放锁并进入休眠，直到被其他线程通过 notify 唤醒。**

👉 想象：

```plain
生产者：门口排队
队列：房间（最多10人）
```

队列满了：

```plain
生产者：进不去 → 在门口等（阻塞）
```

消费者出来一个：

```plain
房间空出一个位置
```

👉 然后：

```plain

```

生产者醒来：

```plain
重新尝试进入
```

九、你现在要记住的3个关键点

🎯 1. wait 会自动释放锁

👉 否则死锁

🎯 2. wait 会让线程睡眠

👉 不占CPU（不是死循环）

🎯 3. 被唤醒后一定要重新检查条件

👉 因为可能被“误唤醒”
