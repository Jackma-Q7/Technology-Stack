## 错过信号及假醒
&emsp;&emsp;错过信号：`notify` 发生时，线程还没进入 `wait`。

&emsp;&emsp;假醒：没人 `notify`，线程也可能从 `wait()` 返回。  

&emsp;&emsp;通常条件变量被唤醒，需要配合一个判断条件。当这个条件不满足时，线程应该会再次阻塞。如果条件满足则不会被阻塞

```cpp
while(!condition)
{
    g_cnd.wait(g_mtx);
}
```

&emsp;&emsp;还可以解决假醒的情况，假醒就是虚假唤醒，当线程被条件变量唤醒时，但此时共享资源并不满足线程继续执行的条件

&emsp;&emsp;多个线程都对一个队列取数据，当队列中没有数据时，线程都被阻塞，当有数据时，线程都被唤醒取数据。但是可能存在某个线程醒来，但是队列为空的情况。出现这种情况，是某个线程先把数据取走了。也就是无论哪一个线程抢到了资源, 另一个线程的唤醒就可以被认为是没有必要的, 也就是被虚假唤醒了

```cpp

#include <thread>
#include <condition_variable>
#include <mutex>
#include <iostream>

std::mutex g_mxt;
//条件变量
std::condition_variable g_cnd;
//共享资源
int g_cnt = 0;
//判断条件
bool g_flag = false;

void thread1Func()
{
    std::unique_lock<std::mutex> lock(g_mxt);
    g_cnd.wait(lock);

    if (g_flag)
    {
        std::cout << "thread 1 g_cnt " << g_cnt << std::endl;
        g_flag = false;
    }
    else
    {
        std::cout << "thread 1 g_flag is false" << std::endl;
    }
}

void thread2Func()
{
    std::unique_lock<std::mutex> lock(g_mxt);
    g_cnd.wait(lock);
    if (g_flag)
    {
        std::cout << "thread 2 g_cnt " << g_cnt << std::endl;
        g_flag = false;
    }
    else
    {
        std::cout << "thread 2 g_flag is false" << std::endl;
    }
}

int main()
{
    std::thread thread1(thread1Func);
    std::thread thread2(thread2Func);

    std::this_thread::sleep_for(std::chrono::seconds(1));
    while (1)
    {
        //std::lock_guard<std::mutex> lock(g_mxt);
        ++g_cnt;
        if (18 == g_cnt)
        {
            g_flag = true;
            g_cnd.notify_all();
            break;
        }
    }

    thread1.join();
    thread2.join();
}
```

1. 大概输出结果

可能是：

```cpp
thread 1 g_cnt 18
thread 2 g_flag is false
```

也可能是：

```cpp
thread 2 g_cnt 18
thread 1 g_flag is false
```

因为 `notify_all()` 会把两个线程都叫醒，但它们醒来后要抢同一把锁。

谁先抢到锁，谁先执行：

```cpp
if (g_flag)
{
    std::cout << "thread 1 g_cnt " << g_cnt << std::endl;
    g_flag = false;
}
```

第一个线程看到 `g_flag == true`，打印 `g_cnt`，然后把 `g_flag` 改成 `false`。

第二个线程再拿到锁时，发现：

```cpp
g_flag == false
```

所以输出：

```cpp
g_flag is false
```

2. 最大问题：主线程修改共享变量没有加锁

主线程这里：

```cpp
++g_cnt;
if (18 == g_cnt)
{
    g_flag = true;
    g_cnd.notify_all();
    break;
}
```

修改了共享变量：

```cpp
g_cnt
g_flag
```

但是没有加锁。

而 thread1/thread2 里面会读：

```cpp
g_cnt
g_flag
```

所以这是**数据竞争**。

正确做法：主线程修改 `g_cnt` 和 `g_flag` 时也要加锁。

3. 第二个问题：wait 没有判断条件

你现在写的是：

```cpp
g_cnd.wait(lock);
```

这不严谨。

应该写：

```cpp
g_cnd.wait(lock, [] {
    return g_flag;
});
```

因为可能有**虚假唤醒**。

4. 但是这里还有一个细节

如果两个线程都写：

```cpp
g_cnd.wait(lock, [] {
    return g_flag;
});
```

然后第一个线程醒来后把：

```cpp
g_flag = false;
```

第二个线程醒来后会重新判断 `g_flag`，发现是 false，然后继续睡。

可是主线程不会再通知了。

结果：**第二个线程可能永远卡住**。

所以如果你想让两个线程都正常结束，不能让其中一个线程把 `g_flag` 改回 false。

5. 推荐改法

```cpp
#include <thread>
#include <condition_variable>
#include <mutex>
#include <iostream>

std::mutex g_mxt;
std::condition_variable g_cnd;

int g_cnt = 0;
bool g_flag = false;

void threadFunc(int id)
{
    std::unique_lock<std::mutex> lock(g_mxt);

    g_cnd.wait(lock, [] {
        return g_flag;
    });

    std::cout << "thread " << id << " g_cnt " << g_cnt << std::endl;
}

int main()
{
    std::thread thread1(threadFunc, 1);
    std::thread thread2(threadFunc, 2);

    {
        std::lock_guard<std::mutex> lock(g_mxt);

        while (g_cnt != 18)
            {
                ++g_cnt;
            }

        g_flag = true;
    }

    g_cnd.notify_all();

    thread1.join();
    thread2.join();

    return 0;
}
```

输出可能是：

```cpp
thread 1 g_cnt 18
thread 2 g_cnt 18
```

顺序不固定。

一句话总结：

&emsp;&emsp;**notify_all 会唤醒所有等待线程，但共享数据必须加锁，wait 必须带条件，多个线程都要继续执行时不要让其中一个线程把条件改回 false。**

## 问题1：
&emsp;&emsp;改进的代码，会出现线程1拿到锁住，离开作用域了解锁，才给线程2.有没有两个同时用的方法  ？

对，你理解得对：**同一把 **`mutex`** 同一时间只能被一个线程拿到**。

所以改进代码里：

```cpp
std::unique_lock<std::mutex> lock(g_mxt);
```

线程 1 拿到锁后，线程 2 必须等线程 1 离开临界区释放锁，才能继续。

如果你想“两个线程都同时干活”，做法是：

**锁只保护共享数据，拿到数据后立刻解锁，真正耗时的工作放到锁外面。**

```cpp
void threadFunc(int id)
{
    int local_cnt = 0;

    {
        std::unique_lock<std::mutex> lock(g_mxt);

        g_cnd.wait(lock, [] {
            return g_flag;
        });

        // 只在锁内读取共享数据
        local_cnt = g_cnt;
    } // 这里立刻解锁

    // 锁外执行，两个线程可以同时运行
    std::cout << "thread " << id << " g_cnt " << local_cnt << std::endl;
}
```

关键点：

```cpp
local_cnt = g_cnt;
```

把共享数据复制到局部变量后，就不需要一直占着锁了。

但是要注意：

`std::cout` 本身多个线程同时输出，可能会交叉打印。可以再专门用一个输出锁：

```cpp
std::mutex g_cout_mtx;

void threadFunc(int id)
{
    int local_cnt = 0;

    {
        std::unique_lock<std::mutex> lock(g_mxt);
        g_cnd.wait(lock, [] {
            return g_flag;
        });
        local_cnt = g_cnt;
    }

    {
        std::lock_guard<std::mutex> lock(g_cout_mtx);
        std::cout << "thread " << id << " g_cnt " << local_cnt << std::endl;
    }
}
```

一句话总结：

&emsp;&emsp;**共享数据不能两个线程同时改/读写；但可以把共享数据拷贝出来，然后两个线程在锁外同时处理。**

## 用法总结
条件变量的使用

有意修改共享资源的线程必须

1. 获得锁(lock_guard)

2. 在保证有锁时对共享资源进行修改

3. 释放锁，通知其它线程(std::condition_variable 上执行 notify_one 或 notify_all) 

任何有意在 std::condition_variable 上等待的线程必须

1. 获得锁(unique_lock) ，在与用于保护共享资源者相同的互斥上

2. 执行等待(condition_variable的wait方法)，等待操作自动释放互斥，并悬挂线程的执行。

3. 被通知时，时限消失或虚假唤醒发生，线程被唤醒，且自动重获得互斥。之后线程应检查条件，若唤醒是虚假的，则继续等待(condition_variable的wait方法)

&emsp;&emsp;条件变量通常会配合一个检查条件使用，循环检查该条件，以防止"假醒"。通过wait方法配合lambda表达式可以很方便的实现(形参是一个调用对象，不限于lambda表达式)

**g_cnd.wait(lock, [] { return g_flag;});假如唤醒了，但是g_flag还是0，也会继续锁住，为什么呢？**

因为 wait(lock, 谓词) 自带一个自动循环！

唤醒了但 g_flag == 0 → 它会自己重新调用 wait，再次卡住、继续等，不会往下执行！

等价：

```cpp
while (!g_flag)  // 只要条件不满足，就一直循环等待
{
    g_cnd.wait(lock);  // 唤醒后不满足，会重新回来等
}
```
