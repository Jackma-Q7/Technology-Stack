## std::move函数
&emsp;&emsp;通过std::move可以将左值转换成右值引用，move函数并不会产生移动操作，只是产生一个右值引用，真正的移动操作是在移动构造函数和移动赋值函数中完成的

`string s = "abc";`

`std::string &&s1 = std::move(s);`➡️ s1 是引用（别名）

`std::cout << s1.c_str() << std::endl;`

&emsp;&emsp;要转移变量s的资源，需要调用移动构造函数或移动赋值函数

`std::string ss(std::move(s));`

`std::string ss1 = std::move(s);`➡️ s1 是新对象（发生移动构造）

&emsp;&emsp;std::move(s)产生右值引用，从而触发调用string的移动构造函数或移动赋值函数，此时变量s的资源就被转移了，如果对象没有定义移动语义，则会调用拷贝构造函数或赋值构造函数

```cpp
std::string ss(std::move(s));   // 移动构造
std::string ss1 = std::move(s); // 也是移动构造，不是移动赋值
```

因为 `ss`、`ss1` 都是在**创建新对象**。

移动赋值是这种：

```cpp
std::string ss2;
ss2 = std::move(s); // 移动赋值
```

```cpp
#include <utility>
#include <iostream>
#include <vector>

class CTest
{
public:
    CTest() { std::cout << "CTest()" << std::endl; }
    CTest(const CTest& t) { std::cout << "CTest(const CTest& t)" << std::endl; }
    CTest(CTest &&t) { std::cout << "CTest(CTest &&t)" << std::endl; }
};

int main()
{
    std::string s = "abc";

    // 将 s 转换为右值，从而调用 string 的移动构造函数
    std::string s1 = std::move(s);

    // 此时 s 已被移动，一般变为空字符串，但仍然是有效对象
    std::cout << s.c_str() << s1.c_str() << std::endl;

    // 已经被移动过的对象，不建议再继续使用其原有值
    // std::string s2 = std::move(s);
    // std::cout << s2.c_str() << std::endl;

    CTest t;

    // 将左值 t 转为右值，触发移动构造函数
    CTest t1 = std::move(t);

    std::vector<std::string> vec;

    // 将 s1 移动到 vector 中
    vec.push_back(std::move(s1));

    // 此时 s1 已被移动，一般为空，这里是拷贝一个“被移动后的对象”
    vec.push_back(s1);

    return 0;
}
```

## STL中的移动语义
&emsp;&emsp;移动语义已被全面引入了STL，比如string，容器类，智能指针

&emsp;&emsp;旧的标准中我们返回一个容器往往是返回一个容器的引用，在C++ 11 的STL的容器都支持了移动语义，就可以直接返回容器对象了

```cpp
//以前为了避免产生临时对象，避免复制的写法
void GetDatas(std::vector<Data>& Datas)
{
    ...
}
```

```cpp
//有了移动语义的写法
std::vector<Data> GetDatas()
{
    ...
    return Datas;
}
```

| 写法                | 行为        | 结果           |
|---------------|------------|------------|
| std::move(s1)            | 移动     | 把数据搬走         |.
| s1           | 拷贝     | 复制当前内容        |

 👉 **C++11 之后，STL 支持移动语义，可以“直接返回对象”，不再需要返回引用来避免拷贝开销**

🔥旧时代（C++11 之前）

```cpp
std::vector<int>& GetVec()
{
    static std::vector<int> v = {1,2,3};
    return v;
}
```

👉 为什么要返回引用？

因为：

❗ 返回对象会触发**拷贝构造（很慢）**

⚠️问题

+  不安全（返回局部对象会炸） 
+  必须用 static / 外部变量 
+  代码很别扭

🚀C++11之后（重点）

```cpp
std::vector<int> GetVec()
{
    std::vector<int> v = {1,2,3};
    return v;
}
```

👉 现在可以这样写了！

🧠为什么可以？

因为：

👉 **返回时会触发“移动构造”**

本质发生：

```cpp
return v;
```

👉 等价于：

```cpp
return std::move(v); // 编译器自动优化
```

🔥效果

+  ❌ 不再拷贝整个容器 
+  ✅ 直接“偷内部指针”（移动） 

👉 非常高效

## 问题1： 返回类型还是std::vector<int>，不过不是拷贝构造来的了是移动构造来的  
👉 **不一定是移动构造，有可能是：**

1.  ✅ **直接构造（RVO/NRVO）——最常见**
2.  ✅ 移动构造（如果没优化） 
3.  ❌ 很少才是拷贝构造（基本不会）

 👉 **现代C++中返回对象：优先“直接构造”，其次“移动”，最后才“拷贝”。**
