## 一个形象的比喻
&emsp;&emsp;如何把一个冰箱里的大象放到另一个冰箱中?

&emsp;&emsp;打开冰箱1的门，打开冰箱2的门，将冰箱1里的大象移动冰箱2中，关上冰箱门

&emsp;&emsp;将冰箱1里的大象复制一头，将复制的大象放到冰箱2中，再让冰箱1里的大象消失掉。这种方法是不是感觉似曾相识，这个就是C ++中拷贝复制的概念。 一种很自然的方法结果在C ++中表现的如此纠结

## 复制语义
&emsp;&emsp;C++11 之前只有复制(拷贝)语义，定义了**析构函数**，**复制构造函数**，**赋值函数**就称有了拷贝控制。对对象的非指针，非引用的行为都会使用复制语义。在拥有内存资源对象中，都会定义这三个函数以实现深拷贝，但是在某些场景中，对象拷贝后就立即被销毁了，在这些情况下，如果只是移动而非拷贝对象会大幅度提升性能

```cpp
#include <iostream>
#include <cstring> // 需要这个头文件支持 memset / memcpy

class CPointTest
{
public:
    // 默认构造函数
    CPointTest()
    {
        m_size = 1024;
        m_pInts = new int[1024];
        memset(m_pInts, 0, 1024); // 初始化为0
    }

    // 带参数构造函数（直接接管外部数据指针）
    CPointTest(int* pData, int size) : m_pInts(pData), m_size(size)
    {

    }

    // 析构函数
    ~CPointTest()
    {
        std::cout << "~CPointTest()" << std::endl;
        delete[] m_pInts;
        m_pInts = NULL;
    }

    // 拷贝构造函数
    // 因为类中有指针成员，必须实现深拷贝
    // 否则会导致多个对象共享同一块内存（浅拷贝问题）
    CPointTest(const CPointTest& t)
    {
        std::cout << "CPointTest(const CPointTest& t)" << std::endl;
        m_size = t.m_size;
        m_pInts = new int[m_size];
        memcpy(m_pInts, t.m_pInts, m_size); // 拷贝数据内容
    }

    // 赋值运算符重载（深拷贝）
    CPointTest& operator=(const CPointTest& t)
    {
        if (this != &t) // 防止自赋值
        {
            // 先释放原有资源
            if (NULL != m_pInts)
            {
                delete[] m_pInts;
                m_pInts = NULL;
            }

            // 再重新分配并拷贝
            m_size = t.m_size;
            m_pInts = new int[m_size];
            memcpy(m_pInts, t.m_pInts, m_size);
        }//左边对象原来指向的那块堆空间会被释放掉，然后它的指针会改为指向新申请的堆空间。

        return *this;
    }

private:
    int* m_pInts = nullptr; // 指向动态数组
    int m_size = 0;         // 数组大小
};

// 返回对象（触发拷贝构造 / NRVO优化）
CPointTest GetPointTest()
{
    CPointTest t;
    // 通过返回值，可能触发拷贝构造（或编译器优化）
    return t;
}

int main()
{
    // 用返回值初始化对象，可能触发拷贝构造
    CPointTest t = GetPointTest();

    std::system("pause");
}
```

🔧 一步一步走流程

① 创建对象

```cpp
CPointTest t;
```

做了什么？

```cpp
m_pInts = new int[1024];  // 在堆上开空间
```

👉 现在内存结构是：

```plain
t（栈）
 ├── m_size = 1024
 └── m_pInts ---> 堆上一块 int[1024]
```

② 析构函数（最重要）

```cpp
~CPointTest()
{
    delete[] m_pInts;
}
```

👉 作用：

**对象销毁时，把堆内存释放掉**

否则：

❌ 内存泄漏

③ 为什么要写拷贝构造？

看这个：

```cpp
CPointTest t2 = t;
```

如果你不写：

👉 默认行为 = **浅拷贝**

```plain
t.m_pInts  ----\
                ----> 同一块内存 ❌
t2.m_pInts ----/
```

结果：

👉 两个对象析构 → **delete两次 → 崩溃**

✅ 所以你写了“深拷贝”：

```cpp
m_pInts = new int[m_size];
memcpy(m_pInts, t.m_pInts, m_size);
```

👉 变成：

```cpp
t  ----> 内存A
t2 ----> 内存B（复制的）
```

✔️ 安全

④ 赋值运算符（更隐蔽）

```plain
t2 = t;
```

流程：

1.  先删旧内存 
2.  再拷贝新内存 

```cpp
delete[] m_pInts;
m_pInts = new int[m_size];
```

👉 否则：

❌ 内存泄漏（旧的没释放）

⑤ GetPointTest()

```cpp
CPointTest GetPointTest()
{
    CPointTest t;
    return t;
}
```

👉 这里会发生两种情况：

情况1（老编译器）：

触发拷贝构造

情况2（现代编译器）：

👉 **NRVO优化（直接构造到目标位置）**

👉 你甚至看不到拷贝发生

⑥ main 这一句

```cpp
CPointTest t = GetPointTest();
```

👉 本质：

+  要么拷贝构造 
+  要么直接构造（优化） 

⚠️ 你必须知道的坑（重点）

```cpp
memset(m_pInts, 0, 1024);
memcpy(m_pInts, t.m_pInts, m_size);
```

👉 错在：

**单位是字节，不是int个数**

✔️ 正确写法：

```cpp
memset(m_pInts, 0, 1024 * sizeof(int));
memcpy(m_pInts, t.m_pInts, m_size * sizeof(int));
```

🔥 最关键总结（记住这句）

👉 **只要类里有 **`new`**，你就必须自己写：**

1.  析构函数（释放） 
2.  拷贝构造（深拷贝） 
3.  赋值运算符（深拷贝） 

👉 这就是：

👉 Rule of Three（三法则）

**🚀 给你一个进阶理解（非常关键）**

你现在写的是：

👉 **“手动版 vector”**

现代写法其实是：

```cpp
std::vector<int> v;
```

👉 自动帮你处理：

+  内存分配 
+  拷贝 
+  释放

## 问题1： CPointTest&  
CPointTest& operator=(const CPointTest& t)   
这个重载运算符，又叫什么？   
返回值是CPointTest& 对象的别名，传入也是对象不发生拷贝对吗？  

✅ 1️⃣ 这个运算符叫什么？

```cpp
CPointTest& operator=(const CPointTest& t)
```

👉 它的名字是：

👉 **赋值运算符重载（assignment operator）**

一句话：

👉 **让对象可以用 **`=`** 进行赋值时，走你自己写的逻辑**

✅ 2️⃣ 返回值为什么是 `CPointTest&`？

```cpp
return *this;
```

👉 返回的是：

👉 当前对象的引用（别名）

为什么必须返回引用？

为了支持**连续赋值**：

```plain
a = b = c;
```

执行顺序：

1. `b = c` → 返回 `b`
2. `a = b`

👉 如果不返回引用，就断链了 ❌

✅ 3️⃣ 参数为什么是 `const CPointTest&`？

```plain
const CPointTest& t
```

你说的这句：

传入也是对象不发生拷贝对吗？

✔️ **完全正确，但我帮你说完整一点：**

👉 发生了什么？

#### 如果写成这样：
```plain
CPointTest operator=(CPointTest t)  // ❌
```

👉 会发生：

+  传参时调用 **拷贝构造函数**
+  多一次对象复制（浪费） 

✔️ 正确写法：

```plain
const CPointTest& t
```

👉 效果：

+ **不拷贝对象**
+  只是传一个引用（类似指针） 
+  更高效 

👉 为什么加 `const`？

防止你在函数里写：

```plain
t.m_size = 100; // ❌ 不允许
```

👉 本质：

**我只读你，不改你**

🔥 一句话总结（重点记住）

👉 这个函数本质就是：

```plain
对象1 = 对象2;
```

做了三件事：

1.  防止自赋值（`this != &t`） 
2.  释放旧内存 
3.  深拷贝新数据 

🧠 再给你一个“理解升维点”（很重要）

你可以这样理解：

| 写法 | 本质 |
| --- | --- |
| `CPointTest t2 = t1;` | 调用 **拷贝构造** |
| `t2 = t1;` | 调用 **赋值运算符** |


 👉 两者**完全不是一回事**

## 问题2：区分深浅拷贝

1. 浅拷贝（默认合成 / 简单赋值）
```cpp
CPointTest::CPointTest(const CPointTest& t)
{
    this->a = t.a;
    this->ptr = t.ptr; // 指针直接赋值，共享同一块堆内存
}
```
只拷贝成员变量本身，指针只拷贝地址，多个对象共用堆空间。
2. 深拷贝（手动开辟新内存）
```cpp
CPointTest::CPointTest(const CPointTest& t)
{
    this->a = t.a;
    // 重新 new 一块独立内存
    this->ptr = new int(*t.ptr); 
}
```
指针成员重新分配堆内存，每个对象资源独立。

## 左值与右值
在赋值操作符的左边即为左值，在赋值操作符的右边即为右值

也可以这样理解左值和右值：

左值是有名字，可以取地址的值

右值是字面量等取不了地址值，没有名字的值

int i = 18；//i即为左值，18 字面量即为右值，可以对i取地址，但是不能对18取地址

int &r = i; //&r为左值引用

**int &r3 = 18*i; //&r3不能引用一个右值**

在C++11中，右值是又包括两个概念：

&emsp;&emsp;纯右值，上面的例子中， 18，18*i就是纯右值

&emsp;&emsp;将亡值，比如函数返回时的临时对象；将要被移动的对象

## 左值引用和右值引用
&emsp;&emsp;在旧的C++标准中我们说的引用指的是左值引用(对左值的引用)，在C++ 11新标准中引入了右值引用，指的就是对右值的引用

左值引用只能引用左值，右值引用只能引用右值

int i = 42 //i是左值

int &r = i //&r为左值引用

int &&r = i //&&r是右值引用，不能将左值给右值引用

int &r = 42; //42是字面量，是右值，右值不能给左值引用

&emsp;&emsp;返回左值引用(引用)的函数，连同赋值，下标，解引用和前置递增/递减运算符，都是返回左值

&emsp;&emsp;返回非引用类型的函数，连同算术，关系，位及后置递增/递减运算符，都是返回右值(很显然这些操作运算符都会产生临时变量)，这样值的引用就是右值引用

&emsp;&emsp;const左值引用是可以指向右值

```cpp
#include <iostream>

int f()
{
    int i = 118;
    return i;
}

int main()
{
    int i = 18; // i 是变量，i 本身是左值，值是 18

    int &r = i; // 左值引用可以绑定左值

    // int &rr = 18;
    // 错误：普通左值引用不能绑定右值

    int &&r1 = 18; // 右值引用可以绑定右值

    // int &r2 = i * 18;
    // 错误：i * 18 的结果是临时值，是右值

    int &&r3 = i * 18; // 右值引用绑定表达式产生的临时右值

    // int &r4 = f();
    // 错误：f() 的返回值是临时右值

    int &&r5 = f(); // 右值引用绑定函数返回的临时右值

    int &&r6 = i++; // i++ 是右值，先返回旧值，再自增

    int &r7 = ++i; // ++i 是左值，先自增，再返回 i 本身

    // 常量左值引用比较特殊：
    // const int& 既可以绑定左值，也可以绑定右值
    const int &c = 18;

    return 0;
}
```

 一句话记：**左值一般是“有名字、能取地址”的对象；右值一般是“临时结果”；**`int&`**绑定左值，**`int&&`**绑定右值，**`const int&`**两边都能绑。**
