**日期**

&emsp;&emsp;这里介绍chrono的使用，主要是chrono对时间的处理

&emsp;&emsp;在C++ 11中的chrono基本没有对日期处理，在后续几个版本，对日期处理的功能，陆续加强，到了C++20 对日期的处理是非常强大了

到了 **C++20**，情况变了：

直接支持：

```cpp
#include <chrono>
using namespace std::chrono;

year_month_day today = 2026y/April/27d;
```

甚至可以：

```cpp
std::cout << today;
```

C++开发更偏底层，涉及日期处理的需求是比较少的。

**boost库中的chrono**

&emsp;&emsp;chrono是来自 boost中的，但是它只是boost chrono的一个子集，它的提供的功能更加强大，比如它提供了更多的 clock类型，比如：process_real_cpu_clock，process_user_cpu_clock，process_system_cpu_clock，process_cpu_clock， thread_clock。

比如：

+ `process_cpu_clock` → 进程CPU时间 
+ `thread_clock` → 线程时间 
+ `process_user_cpu_clock` → 用户态时间 
+ `process_system_cpu_clock` → 系统态时间

&emsp;&emsp;对time_point，duration提供了IO功能，可以直接通过标准输入格式time_point，也可以直接输出到标准输出。

Boost可以直接：

```cpp
std::cout << time_point;
std::cin >> time_point;
```

而C++11：  
👉 ❌ 不支持（要自己转）

**定时器**

&emsp;&emsp;chrono中并没有定时器，整个C++ stl中都没有定时器，定时器最佳实现是通过IO复用的API去对time_fd进行监听(linux下)

❌ 为什么没有 timer？

因为：

👉 **定时器依赖操作系统，不是纯C++能做的**

✅ 正确做法（Linux）

用：

👉 **IO复用 + timerfd**

涉及系统调用，比如：

+ `timerfd_create`
+ `epoll`
+ `select`

👉 典型模型：

```cpp
epoll 监听
↓
timerfd 触发
↓
执行回调
```

👉 一句话总结：

👉 **定时器 = OS能力，不是STL能力**
