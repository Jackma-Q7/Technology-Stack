## 6.3-signed与unsigned隐式转换

```c
#include <stdio.h>

// 嵌入式程序员面试题：下面的代码输出是什么，为什么？

int main(void)
{
    unsigned int a = 9;
    int b = -10;

    printf("    a+b = %d \n", a+b);

    (b+a > 0) ?
        puts("    a+b > 0") :
        puts("    a+b <= 0");

    return 0;
}

// 输出结果
//     a+b = -1
//     a+b > 0
```
原因：
a 是 unsigned int 类型，b 是 int 类型。
当 unsigned int 和 int 一起运算时，int 类型的 b 会被转换成 unsigned int。

所以：

`b = -10`

在 32 位 unsigned int 中会变成：

`4294967286`

也就是：

`(unsigned int)-10 = 4294967286`

然后：
```
a + b
= 9 + 4294967286
= 4294967295
```
4294967295 对应 32 位二进制是：
`0xFFFFFFFF`
如果用 %d 按有符号 int 打印，它会被解释为：
`-1`
所以第一句输出：
`a+b = -1`
但是判断：
`b + a > 0`
这里 b + a 的计算结果仍然是 unsigned int 类型。
也就是：
`4294967295 > 0`
这个判断为真。
所以第二句输出：
`a+b > 0`
重点：
printf("%d", a+b) 是把 unsigned int 的结果按 int 格式打印，所以看到的是 -1。
但是比较 b+a > 0 时，参与比较的是 unsigned int，所以它实际是一个很大的正数。
更推荐的写法：
`printf("a+b = %u\n", a+b);`
这样会输出：
`a+b = 4294967295`
如果想按有符号方式计算，应该强制转换：
`printf("a+b = %d\n", (int)a + b);`
或者不要混用 signed 和 unsigned。
